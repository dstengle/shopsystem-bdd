# Raising a Request

## Overview

A request is a conversation on one GitHub issue on the upstream's repository, and every step is a comment a `work` command posts. It opens with the asker's need in its own words (`work request`); the upstream offers the capabilities that may serve, with its glossary; then the asker either says one fits (`work fits`) or proposes lines (`work propose`). A request's lines are codified requirements: each parses to one meaning (its logical form) in the grammar 4 of the context it goes to, built from that context's layers (the base grammar, the packs its `spec/index.md` imports, its glossary and its capabilities' terms), and the upstream refuses to accept one that does not. This skill turns the person's English into lines in the upstream's terms. It writes no spec and decides nothing: a line is a proposal, and the upstream judges it.

Scripts: `<this skill's base directory>/../../scripts/`. The upstream's terms are the glossary its offer quotes (under the request's `## Offer`). Where the upstream's spec is at hand, run every `model` command with `--root <the upstream's repository>`; its lexicon decides, never ours. The language's reference is the plugin's `grammar/language.md` (the reading rules R1-R12 and each construct, with real lines and their logical forms) and `grammar/constructs.md` (the construct catalogue: each construct's code, form and example), at `<this skill's base directory>/../../grammar/`. Nothing reads or writes the upstream's repository.

## The forms

One sentence, the clauses in this order (`grammar/language.md`, R9; `grammar/constructs.md`, `when` to `where`):

| the person says | form | shape |
|---|---|---|
| when someone runs or something happens | event-driven | `When T, Actor shall V.` |
| while something holds | state-driven | `While C, when T, Actor shall V.` |
| it refuses, or fails safely | unwanted behaviour | `[While C,] If T, then Actor shall V.` |
| it is never done, or done only so | prohibition, restriction | `Actor shall not V.`, `Actor shall V only Ks that P.` |
| it is so by definition | necessity | `A K always/never ...` |
| it is allowed | permission | `Actor may V.` |
| a feature the product is built with | optional feature | `Where F, [while C,] when T, Actor shall V.` |

A line that obliges with no trigger, and neither "always" nor "never", is refused (R12): a `shall` that obliges needs a When or an If; `shall not` and `only` stand alone. The form follows what starts the behaviour, not the person's wording. What happens under one trigger and condition is one line, its verb phrases joined by `and`:

```
While the status of an item is `idea`, when the person runs `work shape` on the item, `work` shall set the status of the item to `shaped`.
If the person runs `work decision` without the `--tier` option, then `work` shall refuse the command and name `--tier`.
While the status of an item is not `idea`, if the person runs `work shape` on the item, then `work` shall refuse the command and name the status of the item.
```

`shall A, B and C` lists more; `shall not A or B` forbids both; `R1, and R2` joins responses whose subjects differ. A condition's clauses join by `and` or `or`. A preposition (`of`, `in`, `on`, `for`, `with`, `from`, `to`, `by`, `at`) means the one relation the context's `## Relations` rows give for the two kinds it joins, and a blank cardinality is any number (`one` makes it functional); a line with two readings that mean different things is refused, naming the words. Exits are in words (`shall exit successfully`, `shall exit with an error naming …`). Never restate what `spec/universal.md` or a pack's `## Definitions` hold: `model explain` shows what a line means through them.

## Writing a line in 4.0

The rules of the controlled language 4 (`grammar/language.md` reads each with real lines):

- **Plain words in sentence structure, no coined adjective.** A state is said with the structure that holds it, from the lexicon's own words: "a comment that does not conform to the comment form", "an item whose status is not `shaped`", "a commit that cites no item", "a request that holds no comment". A new adjective is a state missing its structure. An adjective that stays is defined by a sentence of the grammar (`- **open** (adjective of initiative): An initiative is open when the initiative is not `done` and the initiative is not `abandoned`.`), never by prose.
- **States in While, behaviour in When or If.** A state verb (`(verb, state)`, "has V-ed") goes in a While clause or a relative clause; an action verb (`(verb, action)`) in the trigger and the response; a verb of the wrong aspect there is refused. A state put into the trigger's noun phrase moves to While: "While an item is `shaped`, when the person runs `work ready` on the item", not "when the person runs `work ready` on a shaped item".
- **The agent explicit.** Every trigger and response says who acts: the person, a session, `work`, a clock. No passive ("when an item is readied").
- **A command's option is in the trigger**, in the code of the CLI pack's `run`: "runs `work backlog` with the `--json` option", "with the `--source` and `--thread` options", "with the `--to` option set to a bounded context", "without the `--tier` option". Never "Where `--x` is given": Where is a feature the product is built with.
- **A refusal is short:** "If ..., then `work` shall refuse the command and name X". That it exits with an error and changes nothing is entailed (the CLI pack's definition of refuse, the universal conditions); `model explain` shows it, and the generated scenario writes it as a `# entailed:` comment.
- **"the K" names something the line gave**: an earlier noun of the line, "the K of X" over a relation row or an attribute, or a kind whose entry has `This:` ("this repository", "the command"); else the line is refused, naming the noun (R2). "its" binds to its clause's subject (R8).
- **"does not V a K" in a condition is refused** (R4): say "Vs no K" or "a K that X does not V". "a K" in a condition or trigger is any K; in a response, a new one (R1). "one K" is exactly one; counts as "at least two Ks", "the number of Ks is at least n" (R7, `count`, `number-of`).
- **Example data goes in the group's given block**, never in the line. A line names kinds and declared constants (actors, commands, options, values, rule and construct codes, named instances); a code or quoted string that names none (a path, a message text, a sample value) is a parameter that the given block binds, and `model check` warns of it (`w_example`). A command (the code after "runs", or one that starts with a tool's name) and an option are constants, though `model parse --form` marks every code `(parameter)`, a command's too: what is example data is what `w_example` names.
- **A format is an artifact the line conforms to**: "a comment that conforms to the comment form", "a file that does not conform to `grammar/language.md`". The artifact is a term, `- **the comment form** (artifact): <one sentence>.`, its schema in `Schema:` when it has one.
- **A line about the language or the check names its code**: a construct by its code in `grammar/constructs.md` ("a requirement that uses `rc-object`"), a rule by its code in `grammar/rules.md` or `model rules` ("a term that violates `v_t11`"), with the spec pack's words (`imports: [cli, spec]`); never a coined word for a construct.
- **A value in the full form unless it is an adjective.** "the status of an item is `idea`", "an item whose status is `idea`" take any value; the short form "an item is `shaped`" only a value the attribute entry lists under `Values (adjective):`. A value under `Values (noun):` (a noun, a verb phrase, a release: `idea`, `needs-input`, `check`, `1.0.0`) in the short form is refused, naming the full form; reword to it. A new attribute entry declares its values: `- **tier** (attribute of design-decision): Values (noun): `check`, `requirement`, `judgement`.`
- **Compounds and attributive nouns.** "the batch status" is "the status of the batch" (an attribute), "a request comment" "a comment of a request" (a relation row); a compound that is a thing of its own ("pull request") is a declared noun. A declared attributive noun tells two things apart ("http status" against "batch status", "work item").
- **A verb may have several frames.** One entry's `Frame:` lines are one meaning; a second entry of the same verb is a second meaning, told apart by its kinds (`- **name** (verb, action)` for an agent naming a thing, `- **name** (verb, state)` for a text that holds a name). The kinds of a line's nouns pick the frame; a noun of the wrong kind is refused, naming the verb's frame.

## Process

1. **Find the words.** `python3 <scripts>/model lexicon` lists the context's terms by category: actors (the subject of `shall`, proper nouns and artifacts among them), kinds, attributes with their values, events (verbs, a pack's marked `[pack cli]`), resources, conditions. The packs `spec/index.md` imports (`imports: [cli, spec]`) bring the words of a command line (run, print, exit, change, refuse, name, conform; tool, command, option, reason, artifact) and of a spec (requirement, construct, rule, use, violate); the plugin's packs are `grammar/packs/<name>.md`, a context's own `spec/packs/<name>.md`. Use a value only in its own attribute's slot (`an initiative that is `started``). Commands, paths and options are backticked codes, message texts double-quoted strings; a command and an option are constants, and a path, a message text or a sample value the lexicon does not declare is example data (Writing a line, above). `python3 <scripts>/model constructs --check` says whether the catalogue is current; read the construct you need in `grammar/constructs.md`.
2. **Write the lines**, one per line in a file, in the person's order: `<scratch>/request-lines.md`.
3. **Check every line** with `python3 <scripts>/model parse --file <scratch>/request-lines.md`. Each line prints its tree, or its refusal: the token and its position, the longest prefix that parsed (`parsed up to:`), the nearest lexicon words and the words that `may follow`; or the rule that refuses what parsed (an unbound "the", "does not V a K" in a condition, a verb of the wrong aspect, a line with no trigger, two readings that mean different things), naming the words. Then run it again with `--form`: each line's logical form, its referents (constants, parameters, the run's own things) and its While, trigger and response boxes. Read it against what the person meant: a `the` bound to the wrong noun, a state in the wrong box, is a line that parses and means something else. `--form` marks every code `(parameter)`, a command's too; the example data that goes into a given block is what `model check`'s `w_example` names (a path, a message text, a sample value), never a command or an option.
4. **Reword from the refusal.** Reword at the refused token, starting from the prefix that parsed, with one of the nearest words when it means what the person meant. A line refused for two readings is split or made specific at the words it names. A state in the trigger's noun phrase goes into While; an option said with Where goes into the trigger; a long refusal ("exit with an error naming X and change nothing") becomes "refuse the command and name X"; example data goes into the given block (on an item here, `work line --given`; for an upstream, the line names the kinds and the upstream writes the given block). Run step 3 again until every line parses and its form says what the person meant.
5. **A missing word is a glossary entry, never a synonym.** When the person means a thing the lexicon has no word for, do not bend the line onto a nearby word that means something else. Tell the person which word is missing, and write the entry the context would need, in the glossary's form, one sentence, its part of speech one of `noun`, `proper noun`, `adjective of <kind>`, `attribute of <kind>` (its values under `Values (adjective):` and `Values (noun):`, by how they read after "is"), `verb, action`, `verb, state` or `artifact`: `- **archive** (verb, action): an agent puts a request out of use. Forms: archives, archived. Frame: agent archives request.` A verb takes one `Frame:` per argument pattern of one meaning; a second meaning is a second entry whose kinds differ. A word a pack the context imports defines too carries `Redefines: <pack>.`; a kind whose "this K" is the run's own carries `This: <gloss>.` A missing relation is a `## Relations` row with a preposition or role noun (`| request | in | initiative | |`); a missing format is an artifact entry. A state with no word is a structure of words the lexicon has (Writing a line), not a new adjective. In this repository that entry goes into an item as a term bullet (`work line <item> --into <cap> --term "<bullet>"`) or a relation row (`--relation "<row>"` in place of `--term`); for an upstream, ask the person to raise it with its owner, and give the entry in the request's `--source` note. The line that needs the word waits until the term exists, since the upstream cannot accept it until then. Write every term a set of lines needs before checking them: each change to the glossary or a capability's terms recompiles the grammar, which takes minutes, so terms go in at once and the lines are checked after, not a term between two checks.
6. **Show the person the lines** beside their English, each with what it means: its logical form (`model parse --form`) read back in plain words, and for a line already in a capability `python3 <scripts>/model explain <capability>#r<n>`, which prints what it also means (through a pack's definition or a universal condition) and each line that takes precedence over it, and change what they say. The lines are the person's.
7. **Ask first**, in this repository: `python3 <scripts>/work request "<title>" --from <this context's id> --thread <job-thread> --ask "<the need, in the person's words>"` (`--to <upstream>` when there are several). It opens the issue on the upstream's GitHub repository (its `github: <owner>/<name>` under `## Upstreams`) and writes `.shop/requests/q<n>.md`. `python3 <scripts>/work sync` records the upstream's offer when it comes.
8. **Wait on the upstream with a watch.** While a request waits on the other side (`work sync` prints `waiting on the other side`), start `python3 <scripts>/work watch --forward` with the Monitor tool (its timeout at the maximum), in place of Bash `run_in_background`: it takes GitHub's events on each repository the account administers (`gh webhook forward`, the cli/gh-webhook extension, installed if missing), polls GitHub's notifications for the others (an upstream's repository) and says which on stderr, and ends, printing one line for each, when the other side posts a comment a request does not hold or a new ask arrives. When it ends, run `python3 <scripts>/work sync`, then this skill's step for each request it named, then start the Monitor again; start it again too when it times out, and after each `work sync`. Stop once no request waits on the other side. A comment it has printed once is not printed again, and it writes nothing. Say to the person that the session is watching.
9. **Answer the offer.** When an offered requirement serves the need: `python3 <scripts>/work fits q<n> --serves <capability>#r<n>`, which delivers the request and closes the issue. Otherwise write the lines (steps 1-6) in the offer's terms and propose them: `python3 <scripts>/work propose q<n> --line "<line>"` (once a line), answer questions with `python3 <scripts>/work reply q<n> <k> "<answer>"`, and post the turn with `python3 <scripts>/work turn q<n>`. A line the upstream refuses or rewrites comes back with `work sync`; go back to step 4.

## Red Flags

| Seen | Fix |
|---|---|
| A line proposed without `model parse` run on it, the upstream's spec at hand | Step 3 first; the upstream refuses to accept what does not parse |
| The person asked to nudge the session when the upstream answers | Start `work watch --forward` with the Monitor tool (step 8) |
| Lines given at `work request` | The ask is words; lines follow the offer, with `work propose` |
| A synonym chosen because the right word is missing | A missing word is a glossary entry (step 5) |
| A value in another attribute's slot (`an initiative that is `drafted``) | `model lexicon`: each value belongs to one attribute of one kind |
| Our glossary used for an upstream's request | `--root <the upstream>`: its lexicon decides |
| Two lines with the same trigger and condition | One line, `shall A and B` |
| Two behaviours in one line joined by "and then" | `and` joins responses to one trigger; a later step is its own trigger and its own line |
| An exit code, a message's exact words, or a field name in a line | Exits in words; wording and fields are implementation |
| A new adjective for a state (`unreadable`, `misversioned`) | The structure that holds it: "a comment that does not conform to the comment form" |
| A noun value in the short form (`an item is `idea``) | The full form: `the status of an item is `idea``; `model lexicon` shows each value's kind |
| A state in the trigger's noun phrase (`on a shaped item`) | `While an item is `shaped`, when ... on the item` |
| `Where `--json` is given, ...` | The option in the trigger: `runs `work backlog` with the `--json` option` |
| `shall exit with an error naming X and change nothing` | `shall refuse the command and name X`; the rest is entailed |
| A sample value (`m1`, "banana") in a line | It goes in the group's given block; the line names kinds |
| A passive, or no one who acts (`when an item is readied`) | Name the agent: the person, a session, `work` |
| A construct or check named by a coined word | Its code: `uses `rc-object``, `violates `v_t11`` |
| `model parse --capability` or `--grammar` | Gone: `model parse` reads grammar 4 from `spec/index.md` |
| A line that parses, its form not read | `model parse --form`: a parse is not a meaning |
| A term added, `work ready` run, another term added | Every term first, then one check: each glossary change recompiles |
