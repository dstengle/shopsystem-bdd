# A session starts the watch when a request waits on the other side

## Notes

Nothing starts work watch today unless a session follows a request skill, so a watch is lost when a session ends; the person asked for a hook that starts it, the person's words in quote-7 (and the event-driven watch, quote-6). The SessionStart hook runs `work watch --hook`: while any request waits on the other side (a sent request awaiting-upstream, a received one awaiting-asker), it prints each such request and a line telling the session to start `work watch --forward` with the Monitor tool; with none, it prints nothing and exits 0. Like conversation_hook, the hook never fails a session start: any error exits 0 silently. hooks/hooks.json gains the hook beside `migrate status --hook` and `conversation_hook names`.

## Requirements

### requests

#### [g54] The SessionStart hook names a sent request awaiting the upstream
- [r54] While a request is sent and the request is `awaiting-upstream`, when the SessionStart hook runs `work watch --hook`, `work` shall print the request.
