## Requirements

### decision-tiers

language: codified-2

retired: [r1, r2, r3, r4, r5, r6, r7, r8, r9, r10, r11, r12]

- **`w_untiered`** (proper noun): the rule of the rule catalogue: a design-decision in force gives no tier. Kind of: rule.
- **`v_d6`** (proper noun): the rule of the rule catalogue: a check decision names no test. Kind of: rule.
- **`v_d7`** (proper noun): the rule of the rule catalogue: a requirement decision names no requirement. Kind of: rule.
- **`v_d8`** (proper noun): the rule of the rule catalogue: an accepted decision supersedes one still accepted. Kind of: rule.
- **enforce** (verb, state): a design-decision names a test or a requirement under its `enforced_by` as what holds it. Forms: enforces, enforced. Frame: test enforces design-decision. Frame: requirement enforces design-decision.
- **outcome** (attribute of test): what the test gave the last time `pytest` ran it. Values: `passed`, `failed`.
- **supersede** (verb, state): a design-decision names another under its `supersedes` as the one it takes the place of. Forms: supersedes, superseded. Frame: design-decision supersedes design-decision.
- **route** (noun): a way a design-decision is verified, named under its `verified_by`. Kind of: text.
- **the route list** (proper noun): the routes a design-decision may name: `scenario`, `check`, `judgement` and `monitor`. Kind of: text.
- **verify** (verb, state): a design-decision that is not `superseded` or `rejected` names a route of the route list under its `verified_by` and a universal condition under its `rests_on`. Forms: verifies, verified. Frame: design-decision verifies universal condition.
- **require** (verb, state): a command refuses to run without an argument it names. Forms: requires, required. Frame: command requires argument.

#### [g13] A decision in force with no tier is a warning
- [r13] While a design-decision is not `superseded` and the design-decision is not `rejected` and the design-decision is not `check` and the design-decision is not `requirement` and the design-decision is not `judgement`, when the person runs `model check`, `model` shall print `w_untiered`.

#### [g14] A `check` decision names its test
- [r14] While a design-decision is `check` and no test enforces the design-decision, if the person runs `model check`, then `model` shall exit with an error naming `v_d6`.

#### [g15] A `requirement` decision names its requirement
- [r15] While a design-decision is `requirement` and no requirement enforces the design-decision, if the person runs `model check`, then `model` shall exit with an error naming `v_d7`.

#### [g16] `model decisions --check` runs the tests of the `check` decisions
- [r16] While a design-decision is `check` and a test enforces the design-decision, when the person runs `model decisions --check`, `model` shall run `pytest` on the test.

#### [g17] `model decisions --check` names each failing decision
- [r17] While a design-decision is `check` and a test whose outcome is `failed` enforces the design-decision, if the person runs `model decisions --check`, then `model` shall exit with an error naming the design-decision.

#### [g18] An accepted decision supersedes no accepted decision
- [r18] While a design-decision whose status is `accepted` supersedes a design-decision whose status is `accepted`, if the person runs `model check`, then `model` shall exit with an error naming `v_d8`.

#### [g19] `work decision` writes and commits a decision and the decisions index
- [r19] When the person runs `work decision`, `work` shall write a design-decision and a decisions index and commit the design-decision and the decisions index.

#### [g20] `work decision` names a required option it is not given
- [r20] While `work decision` requires an argument that `work decision` does not have, if the person runs `work decision`, then `work` shall refuse the command and name the argument.

#### [g21] `work decision --verified-by` writes a route
- [r21] When the person runs `work decision` with the `--verified-by` option, `work` shall write a design-decision that has a route and commit the design-decision.

#### [g22] `model check` names a universal condition no decision verifies
- [r22] When the person runs `model check` on a universal condition that no design-decision verifies, `model` shall print the universal condition.

#### [g23] `model check` refuses a route outside the route list
- [r23] While a design-decision has a route that the route list does not list, if the person runs `model check`, then `model` shall exit with an error naming the design-decision.

### pr-review

language: codified-2

retired: [r2, r3, r5, r6, r7, r9]

- **propose** (verb, state): an item holds a requirement among its lines. Forms: proposes, proposed. Frame: item proposes requirement.

#### [g9] `pr-reviewer` reviews only pull requests
- [r10] `pr-reviewer` shall write only reviews of a pull request.

#### [g10] A first review reads the items' requirements and the batch's commits
- [r11] While a pull request of a batch has no review, when `pr-reviewer` writes a review of the pull request, `pr-reviewer` shall read every requirement that an item in the batch proposes and every commit of the batch.

#### [g11] A review reads only the batch's own commits
- [r12] When `pr-reviewer` writes a review of a pull request of a batch, `pr-reviewer` shall read only commits of the batch.

#### [g12] A fix-now finding sends the batch back to building
- [r13] While a review finding on a pull request of a batch is `fix now`, when a session runs `work batch reviewed` on the batch, `work` shall set the status of the batch to `building`.

#### [g13] The next review reads the commits for each fix-now finding
- [r14] While a review finding on a pull request is `fix now`, when `pr-reviewer` writes a review of the pull request, `pr-reviewer` shall read every commit for the review finding.

#### [g14] A pull request with no fix-now finding awaits the person's merge
- [r15] While a batch has a pull request and no review finding on the pull request is `fix now`, when a session runs `work batch reviewed` on the batch, `work` shall set the status of the batch to `awaiting-merge`.

#### [g15] Findings named with their grade and triage
- [r16] When `pr-reviewer` writes a review finding, `pr-reviewer` shall name the grade of the review finding and the triage of the review finding.

- [r13] While `work outcome refused` requires an argument that `work outcome refused` does not have, if a session runs `work outcome refused` on a request line, then `work` shall refuse the command and name the argument.
