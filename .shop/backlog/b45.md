# Harden work decision and work record's arguments

## Notes

From batch-2 review 1 (f2, f3): `work decision` with --summary or --decision missing exits with argparse's usage error and never names --tier, so check every missing argument at once; `work record --about` goes into the frontmatter unchecked, so run it through one_line and check it is an id.

## Requirements

### decision-tiers

- **argument** (kind): an option a command is given on its command line, such as `--tier`.
- **absent** (condition of argument): an argument that a command requires and that is not given.

#### [g9] `work decision` names every absent argument at once
- [r9] If the person runs `work decision` on an argument that is absent, then `work` shall exit with an error naming every argument that is absent and change nothing.

### design-model-check

- **unattributed** (condition of record): a record whose `--about` is not one line or is not the id of a node of the design model.

#### [g57] `work record` refuses an unattributed record
- [r57] If the person runs `work record` on a record that is unattributed, then `work` shall exit with an error naming `--about` and change nothing.
