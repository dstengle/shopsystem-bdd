# spec check and spec trace read an item's lines with --item, as spec parse does

## Notes

New-user trial of 2026-11-26 (quote-103): after b1 was ready on main, spec trace keep-up said 'job keep-up is served by no requirement group' and spec check still warned w_unserved_job and w_untriggered_actor; the trace appeared only in the batch worktree, and with no GitHub the batch never merges; the docs do not say the trace waits for a batch.
The person's trial of the product layer on an empty project (quote-103) found that a ready item's serves: and lines are seen by spec parse --item but not by spec check or spec trace, so the trace and the unserved warnings wait for a batch to merge; the person asks to shape and build these findings first (quote-104). check and trace take the item as parameter, read on a copy of spec/ with the item laid, as preview does.
Rated: value high (a new user sees the product layer's trace and checks only after a batch merges, which with no GitHub never happens), urgency high (the person asks for this wave first, quote-104), size medium (an --item option on two commands over spec_preview's copy).

## Requirements

### checking

#### [g150] A job an item's requirement group serves is not unserved in a check for the item
- [r150] While this bounded context holds a job and an item holds a requirement group that serves the job, when the person validates this specification with the item, the specification service shall return no job that violates `w_unserved_job`.

### product

#### [g37] A job's trace for an item holds the requirements of the item's groups that serve it
- [r37] While an item holds a requirement group and the requirement group serves a job and the requirement group has a requirement, when the person traces the job with the item, the product service shall return the requirement.

### specification model

```model
service specification
  operation check(specification, capability, item)  outcomes: passed → findings | failed → findings, an interpreter without clingo | refused: capability not in the language

service product
  operation trace(job, item)  outcomes: returned | refused: job that no requirement group serves
```

### cli adapter

```toml
[operations."specification.check"]
command = "spec check"
cli-only = { options = ["--limit"] }
[operations."specification.check".parameters]
item = { option = "--item" }

[operations."product.trace"]
command = "spec trace"
[operations."product.trace".parameters]
job = { positional = 1, example = "j1" }
item = { option = "--item" }
```
