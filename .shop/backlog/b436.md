# The live features generate --check timing test measures CPU time that a 32-worker suite still inflates past 5 s

## Notes

Release 0.42.0 (2026-11-20): with -n auto (32 workers) test_check_on_the_live_repo_is_fast_and_clean failed twice at 5.1 s of CPU time (2.7-2.8 s alone); with -n 4 the whole suite passes (2462 passed). Contended cores (SMT, shared cache) slow the child's own CPU time too. batch-56 review 1 f2 kept the 5 s limit; a measure that load does not inflate (instructions retired, or the time of the run with the parse cache warm taken alone, or the test serial) is needed rather than a raised limit.
