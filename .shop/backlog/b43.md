# Commands that write the file forms written by hand today

## Notes

Follows b41 "Skills and tools for writing every kind of artifact from scratch": for each file form `model forms` lists as written by hand (a design-decision, a record and its index row, a relations row, an upstream entry, a universal condition, a given block), a command that writes and commits it, so that no session writes one by hand; the person's words in quote-2.

Rescoped 2026-11-05 when b41 was reshaped: b41 writes decisions and records and indexes every file form in `model forms`; this item covers the spec pieces (a relation row, a universal condition, an upstream entry under `## Upstreams`, a group's given block), each written onto an item by a command like `work line --term` and laid into `spec/` with the item's lines, never straight onto the base. It is the same route as b13 "An item proposes a new capability or a glossary term".

Shaped 2026-11-06. Each form is a flag of `work line`, beside `--term`: `--relation "<row>"` and `--given g<n> "<block>"` take `--into <capability>`; `--universal "<statement>"` and `--upstream "<bullet>"` take none, and go in the item's `## Requirements` under a `### universal` and a `### index` block. Each is checked for its shape when written (a relation row's cells and kinds, an upstream entry's id and `github:`, a given block by `spec_read_given`'s shape test), and parsed only by `work ready`, as lines are. `lay_onto` and `unlay` carry all four: a relation row onto the end of the capability's `## Relations` table (the table made when the capability has none), a universal condition as the next `[U<n>]` of `spec/universal.md` (past its `retired:`), an upstream entry under `## Upstreams` of `spec/index.md`, a given block under its group's lines. `--given` names one of the item's own groups; a given block for a group already in `spec/` is a change of that group, which waits for b14 "Reword or remove an item's requirement line by command". `renumber` gives a universal condition a fresh `U<n>` as it does an `r<n>`. `model forms` names each command in place of "plugin item b43". A relation row for the glossary's table in `spec/index.md` waits for b13, as the glossary terms do; the glossary's **well-formed** says only that every requirement parses, so a universal condition of the item parsing is the bar's implementation until b13 can reword the term.

Rated: high-value, as quote-2 asks that no session write a file by hand, and these four forms are what is left of that in `spec/`; medium-urgency, as sessions write them by hand rarely today; medium size, as four writers and their lay, unlay and renumber are each small but touch backlog_lines, which is near the 300-line limit and will be split.

## Requirements

### readiness

- **relation row** (kind): a row of the `## Relations` table of a capability: from, word, to and cardinality.
- **upstream entry** (kind): a bullet of the `## Upstreams` of `spec/index.md`: the id of a bounded context and the GitHub repository it is hosted on, if any.
- **given block** (kind): the fenced `given` block of a requirement group, the example data its scenario starts from.
- **malformed** (condition of relation row): a relation row that is not four cells of a `## Relations` table, or whose from or to is no kind of the lexicon.
- **malformed** (condition of upstream entry): an upstream entry that does not start with a bounded-context id, or whose `github:` is not `<owner>/<name>`.
- **malformed** (condition of given block): a given block that is not example data in the form `spec_read_given` reads.

#### [g5] `work line --relation` writes a relation row onto an item
- [r5] Where `--relation` is given, when the person runs `work line` on an item, `work` shall write a relation row and commit the item.

#### [g6] `work line --relation` refuses a malformed relation row
- [r6] Where `--relation` is given, if the person runs `work line` on a relation row that is malformed, then `work` shall exit with an error naming the relation row and change nothing.
