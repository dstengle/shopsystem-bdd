# The batch brief's subagent rule on an XPASS allows a reworded line whose behaviour exists

## Notes

scripts/batch_driver.py's rule 'A scenario that passes before it is built (an XPASS) means a test step is too loose' contradicts building-a-batch's reword exception (plan-skills-4 review, finding 3): a new id of an item with retired: ids that passes before any code changes is a reworded line whose behaviour exists; its steps are confirmed against the line as now worded and its id taken out of unbuilt:. The driver hands its subagents the brief's rules, so the brief should say the same.
