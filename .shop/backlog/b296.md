# A count that restricts a written thing gets a counter-example: 'write a batch that holds at most three items' given one past the bound

## Notes

Release 0.35.0 review, 2026-11-16: features generate writes no Givens and no counter-example for a count inside a response object's restriction ('Then `notes` writes the file f1 / And the file f1 holds at most three notes'); b273's counter-examples cover a count on what is printed only. Related: b277.
A requirement whose response writes a thing restricted by a count over a holds row ('`notes` shall write a file that holds at most three notes') gets, from features generate, only the When, the act and the count said of the object (b272's spec_steps4_held), and no Givens a program writing too many could fail. The fix: spec_steps4_held (with spec_steps4_counter's upper, which states the count) brings in one K2 past the upper bound before the When, each with the K2's restriction (its values), and keeps the Then 'the file f1 holds at most three notes', so a program putting every given note into the file fails; 'at least' (no upper bound) keeps today's steps. The scenario (feature_file_tools_collections or feature_file_tools_capability's codified2_constructs holding/capping line) runs features generate on such a capability and checks the counter-example as r119's does. This is the case r119 already states (model logic gives r130 an L8 by r119; a warning, kept on purpose: r119's scenario never covered a count over a relation); b273's unchecked case, so arguably a defect of b273. Left out: only over a relation in a response (r113/r118) and b277's scope of more than one act. Related: b277, b273, b272. Rating as the triage gave: medium value, medium urgency, small.
