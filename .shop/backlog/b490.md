# tools check with no arguments checks the branch's change against its base, not nothing

## Notes

tools check with no paths and no --base runs ruff and vulture over nothing (scripts/tools_check.py cmd_check: paths = args.paths, empty, so both print 'nothing to check'); with no arguments it is to check the Python files the branch changed against its base branch (main, or the base .shop/delivery.toml names), as --base does. The person's words in quote-68.

## Requirements

### code-analysis

#### [g15] Linting this repository checks the Python files its branch changed
- [r15] While a kept change that the base branch does not hold touches a Python file and the Python file holds a finding of an analysis tool, when the person lints this repository, the code analysis service shall return the finding and fail the check.

#### [g16] Linting this repository leaves the Python files its branch did not change
- [r16] While a Python file holds a finding of an analysis tool and no kept change that the base branch does not hold touches the Python file, when the person lints this repository, the code analysis service shall complete the request.

### analysis model

```model
object base branch
  relations: holds → kept change (many)

service code analysis
  operation lint(file, repository)  outcomes: returned → the findings | failed → each finding
```

- **base branch** (noun) → object base branch. The branch a repository's work forks from: `main`, or the branch the `base` of `.shop/delivery.toml` names. This: the base branch of the repository the request is made in.
- **lint** (verb, action) → operation code analysis.lint. Forms: lints, linted. Frame: <actor> lints <repository>.
