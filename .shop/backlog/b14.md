# Reword or remove an item's requirement line by command

## Notes

from plan-3-implementation open problems; see .shop/records/2026-11-05-backlog-inventory.md row 14
Shaped from the 2026-11-16 triage (b14 and b271: rewording or dropping lines), on the person's quote-41 (take recommendations on the rest).

Shaping (2026-11-16): `work line <b> --reword <cap>#r<n> "<line>"` puts a new text in place of one of the item's own `- [r<n>]` bullets, keeping its id and group; `work line <b> --remove <cap>#r<n>` takes the bullet out of the item's `## Requirements`, its group too when it was the group's last line (and its given block with it), and, for a line written with `--retires`, the retired id under the block's `retired:` that it brought. Each commits only the item, and is refused, naming the id, for an id that is no line of the item: in particular the id of a live requirement of a capability (r44, r45), which only `--retires` (b128) or b271 touches. `takes` already refuses an item that is not idea or shaped. A reworded or removed line of a ready item is not possible (it is ready, so `takes` refuses); withdraw-and-reshape stays the route there. Modules: `scripts/work` (the two options on `work line`'s parser), `scripts/backlog_lines.py` (the two moves; split into a new `backlog_reword.py` if it nears 300 lines), `scripts/backlog_section.py` (a bullet replaced or dropped in `Blocks`, byte-stable `render`); handlers in `tests/scenarios/readiness_handlers_line.py` (the When with `--reword` and `--remove`) and `readiness_handlers_thens.py` (remove, write); the shaping-items skill's Overview and red-flag row on rewording by editing the bullet change to name the commands. The scenarios: an item with a requirement r1 is given `--reword` / `--remove` of r1's id, and the item file then holds the new text under r1's id / no r1 and one new commit; a requirement of a capability's id is refused and named. Left out: rewording or removing a term bullet, relation row, given block or universal condition of an item (a later item if wanted). Differs from b271: b271 retires a live requirement of `spec/` with no replacement (its id goes to `retired:`, the line is taken out when laid); b14 changes only lines that are still the item's own and never reach `retired:`, and its refusal of a capability's requirement id is where the two meet: `--remove` never retires. Rating kept (high value: every shaping session that rewords a line edits the file by hand today; medium urgency; small). Rests on quote-41 (recommendations taken on the rest). Reproduced: `python3 scripts/work line --help` lists no option that rewords or removes a line, and the shaping-items skill says "No command rewords or removes an item's own line: `work line` only adds one."

## Requirements

### readiness

#### [g42] `work line --reword` rewords a requirement of an item
- [r42] When the person runs `work line` with the `--reword` option set to the requirement id of a requirement in an item on the item, `work` shall remove the requirement, write a requirement in the item and commit the item.

#### [g43] `work line --remove` removes a requirement of an item
- [r43] When the person runs `work line` with the `--remove` option set to the requirement id of a requirement in an item on the item, `work` shall remove the requirement and commit the item.

#### [g44] `work line --reword` refuses a requirement of a capability
- [r44] If the person runs `work line` with the `--reword` option set to the requirement id of a requirement of a capability on an item, then `work` shall refuse the command and name the requirement id.

#### [g45] `work line --remove` refuses a requirement of a capability
- [r45] If the person runs `work line` with the `--remove` option set to the requirement id of a requirement of a capability on an item, then `work` shall refuse the command and name the requirement id.
