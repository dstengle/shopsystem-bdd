#### [g20] `work batch start` picks a ready item that passes the readiness bar and has no dependency on an item not delivered
- [r20] While an item is `ready` and the item passes the readiness bar and the item has no dependency on an item whose status is not `delivered`, when the person runs `work batch start`, `work` shall pick the item, write a batch whose status is `building` and write a batch plan of the batch.

#### [g21] A ready item that no longer passes the readiness bar is returned
- [r21] While an item is `ready` and the item does not pass the readiness bar, when the person runs `work batch start`, `work` shall set the status of the item to `shaped`.

#### [g22] An item with a dependency on an item not delivered is not picked
- [r22] While an item whose status is `ready` has a dependency on an item whose status is not `delivered`, when the person runs `work batch start`, `work` shall not pick an item that has the dependency.

#### [g23] `work batch resume` carries on without a person
- [r23] While a batch is `building`, when a session runs `work batch resume` on the batch, `work` shall use the batch plan of the batch and ask no question.

#### [g24] `work batch park` parks an item and leaves the rest building
- [r24] While an item in a batch is `in-batch`, when a session runs `work batch park` on the item, `work` shall set the status of the item to `needs-input`, write a question on the item and not set the status of the batch to `abandoned`.

#### [g25] A parked item's commits stay out of the pull request
- [r25] While an item in a batch is `needs-input`, when the person runs `work batch review` on the batch, `work` shall publish a pull request with no commit of the item.

#### [g26] `work batch abandon` returns the batch's items
- [r26] While a batch is `building`, when the person runs `work batch abandon` on the batch, `work` shall set the status of the batch to `abandoned` and set the status of every item in the batch whose status is `in-batch` to `ready`.

#### [g27] `work batch review` refuses a batch with a task that is not done
- [r27] While a task of a batch is not `done`, if the person runs `work batch review` on the batch, then `work` shall refuse the command and name the task.

#### [g28] `work batch review` refuses a commit that cites no item
- [r28] While a branch of a task of a batch has a commit that cites no item, if the person runs `work batch review` on the batch, then `work` shall refuse the command and name the commit.

#### [g29] The merge removes the batch's review folders
- [r29] When the person merges a pull request of a batch, `work` shall remove every review folder of the batch.

#### [g30] `work batch park` takes the parked item's lines out of the batch
- [r30] While an item in a batch is `in-batch` and the item proposes a requirement on a branch of the batch, when a session runs `work batch park` on the item, `work` shall remove the requirement.

#### [g31] A parked item's failing scenario does not hold up another item's task
- [r31] While an item in a batch is `needs-input` and a scenario of the item fails and an item in the batch is `in-batch` and a task of the item is `running`, when a session runs `work batch done` on the task, `work` shall set the status of the task to `done`.
