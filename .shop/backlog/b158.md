- **check out** (verb, state): a repository has a git branch as the one its working tree is on. Forms: checks out, checked out. Frame: repository checks out git branch.
- **push** (noun): one `git push` of a branch's commits to a remote. Plural: pushes. Kind of: thing.
- **reject** (verb, state): a remote declines a push made to it. Forms: rejects, rejected. Frame: remote rejects push.
- **answer** (verb, state): a remote replies to a push made to it, taking it or declining it. Forms: answers, answered. Frame: remote answers push.

#### [g22] `work idea` writes an item
- [r22] When the person runs `work idea`, `work` shall write an item whose status is `idea` and commit the item.

#### [g23] `work shape` shapes an idea
- [r23] While an item is `idea`, when the person runs `work shape` on the item, `work` shall set the status of the item to `shaped`.

#### [g24] `work shape` refuses an item that is not an idea
- [r24] While an item is not `idea`, if the person runs `work shape` on the item, then `work` shall refuse the command and name the status of the item.

#### [g25] `work rate` sets an item's ratings
- [r25] When the person runs `work rate --value high-value --urgency low-urgency --size small` on an item, `work` shall set the value of the item to `high-value`, set the urgency of the item to `low-urgency`, set the size of the item to `small` and commit the item.

#### [g26] `work backlog` prints each dependency on an item not delivered with the item that has it
- [r26] While an item has a dependency on an item whose status is not `delivered`, when the person runs `work backlog`, `work` shall print the dependency and every item that has the dependency.

#### [g27] `work backlog --json` prints one JSON object
- [r27] When the person runs `work backlog --json`, `work` shall print a JSON object and exit successfully.

#### [g28] `work withdraw` withdraws an idea
- [r28] While an item is `idea`, when the person runs `work withdraw` on the item, `work` shall set the status of the item to `withdrawn`.

#### [g29] `work withdraw` withdraws a shaped item
- [r29] While an item is `shaped`, when the person runs `work withdraw` on the item, `work` shall set the status of the item to `withdrawn`.

#### [g30] `work withdraw` withdraws a ready item
- [r30] While an item is `ready`, when the person runs `work withdraw` on the item, `work` shall set the status of the item to `withdrawn`.

#### [g31] `work withdraw` withdraws an item that needs input
- [r31] While an item is `needs-input`, when the person runs `work withdraw` on the item, `work` shall set the status of the item to `withdrawn`.

#### [g32] `work refuse` refuses an idea
- [r32] While an item is `idea`, when the person runs `work refuse` on the item, `work` shall set the status of the item to `refused`.

#### [g33] `work refuse` refuses a shaped item
- [r33] While an item is `shaped`, when the person runs `work refuse` on the item, `work` shall set the status of the item to `refused`.

#### [g34] `work answer` returns an item that needs input to shaped
- [r34] While an item is `needs-input`, when the person runs `work answer` on the item, `work` shall set the status of the item to `shaped` and commit the item.

#### [g35] `work backlog` prints the question of an item that needs input
- [r35] While an item is `needs-input`, when the person runs `work backlog`, `work` shall print the item and every question on the item.

#### [g36] `work idea` keeps its commit and names a remote that rejects a push
- [r36] While a remote rejects a push, when the person runs `work idea`, `work` shall write an item whose status is `idea`, commit the item, print the remote and exit successfully.

#### [g37] `work idea` keeps its commit and names a remote that answers no push
- [r37] While a remote answers no push, when the person runs `work idea`, `work` shall write an item whose status is `idea`, commit the item, print the remote and exit successfully.

#### [g38] `work idea` refuses the branch of a task
- [r38] While this repository checks out a git branch of a task, if the person runs `work idea`, then `work` shall refuse the command and name the task.

#### [g39] `work idea` keeps the upstream branch of the branch checked out
- [r39] While this repository checks out a git branch that has an upstream branch, when the person runs `work idea`, `work` shall write an item whose status is `idea`, commit the item and keep the upstream branch.

### batches

language: codified-2

retired: [r1, r2, r3, r5, r6, r7, r10, r12, r13, r16, r17, r18, r19, r8]

- **readiness bar** (noun): the checks `work ready` makes of an item on a copy of `spec/` with its lines laid in. This: the readiness bar of the plugin that runs the command. Kind of: thing.
- **pass** (verb, state): an item meets every check of the readiness bar. Forms: passes, passed. Frame: item passes readiness bar.
- **pass** (verb, state): the test that binds a scenario passes when it runs in a worktree. Forms: passes, passed. Frame: scenario passes in worktree.
- **fail** (verb, state): the test that binds a scenario fails when it runs in a worktree. Forms: fails, failed. Frame: scenario fails in worktree.
- **cite** (verb, state): a commit's message or a pull request's body names an item by its `Item: b<n>` line. Forms: cites, cited. Frame: commit cites item. Frame: pull request cites item.
- **propose** (verb, state): an item holds a requirement among its lines. Forms: proposes, proposed. Frame: item proposes requirement.

#### [g20] `work batch start` picks a ready item that passes the readiness bar and has no dependency on an item not delivered
- [r20] While an item is `ready` and the item passes the readiness bar and the item has no dependency on an item whose status is not `delivered`, when the person runs `work batch start`, `work` shall pick the item, write a batch whose status is `building` and write a batch plan of the batch.

#### [g21] A ready item that no longer passes the readiness bar is returned
- [r21] While an item is `ready` and the item does not pass the readiness bar, when the person runs `work batch start`, `work` shall set the status of the item to `shaped`.

#### [g22] An item with a dependency on an item not delivered is not picked
- [r22] While an item whose status is `ready` has a dependency on an item whose status is not `delivered`, when the person runs `work batch start`, `work` shall not pick an item that has the dependency.

#### [g23] `work batch resume` carries on without a person
- [r23] While a batch is `building`, when a session runs `work batch resume` on the batch, `work` shall use the batch plan of the batch and ask no question.

#### [g24] `work batch park` parks an item and leaves the rest building
- [r24] While an item in a batch is `in-batch`, when a session runs `work batch park` on the item, `work` shall set the status of the item to `needs-input`, write a question on the item and not set the status of the batch to `abandoned`.

#### [g25] A parked item's commits stay out of the pull request
- [r25] While an item in a batch is `needs-input`, when the person runs `work batch review` on the batch, `work` shall publish a pull request with no commit of the item.

#### [g26] `work batch abandon` returns the batch's items
- [r26] While a batch is `building`, when the person runs `work batch abandon` on the batch, `work` shall set the status of the batch to `abandoned` and set the status of every item in the batch whose status is `in-batch` to `ready`.

#### [g27] `work batch review` refuses a batch with a task that is not done
- [r27] While a task of a batch is not `done`, if the person runs `work batch review` on the batch, then `work` shall refuse the command and name the task.

#### [g28] `work batch review` refuses a commit that cites no item
- [r28] While a git branch of a task of a batch has a commit that cites no item, if the person runs `work batch review` on the batch, then `work` shall refuse the command and name the commit.

#### [g29] The merge removes the batch's review folders
- [r29] When the person merges a pull request of a batch, `work` shall remove every review folder of the batch.

#### [g30] `work batch park` takes the parked item's lines out of the batch
- [r30] While an item in a batch is `in-batch` and the item proposes a requirement on a git branch of the batch, when a session runs `work batch park` on the item, `work` shall remove the requirement.

#### [g31] A parked item's failing scenario does not hold up another item's task
- [r31] While an item in a batch is `in-batch` and a task of the item is `running` and an item in the batch is `needs-input` and a scenario of the item fails in the worktree of the task, when a session runs `work batch done` on the task, `work` shall set the status of the task to `done`.

#### [g32] Another item's passing scenario does not hold up a task
- [r32] While a task of a batch is `running` and an item in the batch is `in-batch` and a scenario of the item passes in the worktree of the task, when a session runs `work batch done` on the task, `work` shall set the status of the task to `done`.

#### [g33] `work batch review` publishes the pull request
- [r33] While a batch is `building` and the batch has no task whose status is not `done`, when the person runs `work batch review` on the batch, `work` shall publish a pull request of the batch and set the status of the batch to `in-review`.
