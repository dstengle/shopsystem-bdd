# the adapter contract commands: write spec/adapters/<port>.toml's operation tables by command

## Notes

The domain contract (design §4.5, §6.1): spec/adapters/cli.toml is written by hand on the branch; a command writes an operation's table and its parameters, checked by adapter_cli_check (v_a1-v_a4). Raised by phase 4 for model forms.
UX trial 2026-11-19 (a checklists CLI bootstrapped from an empty repository at 0.39.0): a fresh context reached `work batch start` with no spec/adapters/cli.toml and nothing asked for one: `spec annotate` and `--check` exit 0 silently without it, and the first task has no operation-to-command map to bind its Whens through. See also b389.

## Requirements

### drafting

#### [g27] An operation table exposed in an item is kept
- [r27] When the person exposes an operation table in an item, the drafting service shall keep the operation table in the item.

#### [g28] An operation table of an operation that does not exist is refused
- [r28] If the person exposes an operation table of an operation that does not exist in an item, then the drafting service shall refuse the request and name the operation table.

#### [g29] An operation exposed again keeps only its new operation table
- [r29] While an item holds an operation table of an operation, when the person exposes another operation table of the operation in the item, the drafting service shall keep only one operation table of the operation in the item.

#### [g30] An operation withheld in an item is kept
- [r30] When the person withholds an operation in an item, the drafting service shall keep the operation in the item.

### batches

#### [g77] An operation table of an item is laid into the adapter contract
- [r77] While an item is `ready` and the item meets the readiness bar and the item holds an operation table, when the person opens a batch, the batches service shall keep an adapter contract that holds the operation table.

### specification model

```model
object operation table kind of text
  relations: names → operation (one)

object adapter contract
  relations: holds → operation table (many)

object operation
  relations: has → operation table (one)
```

- **operation table** (noun) → object operation table. How an adapter requests one operation of the domain model, kept in its adapter contract: for the CLI adapter, the command, each parameter as a positional argument or an option with its example, its flags and its cli-only options. Plural: operation tables.

### tracking model

```model
service drafting
  operation expose(operation table, item)  outcomes: done | refused: operation table of no operation
  operation withhold(operation, item)  outcomes: done

object item
  relations: holds → operation table | operation (many)
```

- **expose** (verb, action) → operation drafting.expose. Forms: exposes, exposed. Frame: <actor> exposes <operation table> in <item>.
- **withhold** (verb, action) → operation drafting.withhold. Forms: withholds, withheld. Frame: <actor> withholds <operation> in <item>.
