# work line --serves before a line's text takes the job, not the line as a group

## Notes

New-user trial 4 of 2026-11-26 (quote-104): work line b1 --into bookings --group '...' --serves book-repair 'When the visitor books a slot, ...' -> "--serves: 'book-repair' is not a requirement group <capability>#g<n>": --serves takes one or more arguments and swallows the line; the docs show no example. MAJOR
New-user trial 4 (the person's words in quote-104 and quote-106): 'work line <b> --into <cap> --group <t> --serves <job> "<line>"' is refused as '--serves: <job> is not a requirement group', since --serves takes one or more arguments (nargs='+') and swallows the line. The domain request is the same as drafting#r93's (dedicate a requirement group to a job with an item and a requirement), which r93 already says; what goes wrong is the CLI adapter's reading of the words, so the item is a chore, not lines: --serves reads one argument, the job, when a line follows or --into is given, and two ('<cap>#g<n> <job>') only when its first has the group form; a test in tests/scripts/test_backlog_serves.py of --serves before the line, the r93 handler run with --serves before the line, and docs/reference/commands.md showing that order.
