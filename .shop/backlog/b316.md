# A chore item reaches ready without requirement lines: it names its files and the check that shows it done

## Notes

From the 2026-11-16 triage (.shop/records/2026-11-16-backlog-triage.md): about 45 open items are chores (docs, skill text, an agent definition, module-map rows, a test fix, a refactor) with no behaviour a generated scenario checks, and the readiness bar refuses an item with no requirement line, so none of them can be batched (b34 has sat shaped since batch-1 for this). A chore item names the files it changes and a check that shows it done (a test, a grep, a command's exit); work ready readies it on that, work batch done runs the check, and the batch builds it like any task. The person's standing direction to work through the backlog: quote-42.
Design (shaped 2026-11-16, the session's call in the person's absence, quote-42: work through the backlog, make the calls when the person is away). An item with no behaviour a scenario checks carries a chore in place of requirement lines: `work chore b<n> --file <path> [--file <path> ...] --check "<command>"` writes (and, run again, replaces) a section `## Chore` in the item file, `Files:` with one bullet a path (a file or a directory of the repository) and `Check: \`<command>\``, and commits the item; a path under spec/, features/ or .shop/ is refused (lines own spec/ and features/, work owns .shop/). A chore and requirement lines exclude each other: `work chore` refuses an item holding a requirement, `work line` refuses an item holding a chore. `work ready` readies a shaped item that holds a chore and no requirement when its request lines are settled; it does not run the check, which is expected to fail until the work is done. `work batch start` picks a ready chore item like any other, lays nothing into spec/ and adds no unbuilt id, and the batch brief gives its task the chore's files and check in place of ids. `work batch done` runs the check in the task's worktree after the tests and refuses the task while it exits non-zero, naming the chore, and refuses a commit of the task's branch that touches a path neither named nor under a named directory, naming it. Modules: a new scripts/backlog_chore.py (`work chore`, the section read and written, its refusals) with a module-map row; backlog_items (the section kept by parse/render), backlog_cli (the parser), backlog_lines (`work line`'s refusal), readiness_bar (the chore branch), batch_pick and batch_start (no lay for a chore item), batch_tasks (`done`'s check run and scope check), batch_driver (the brief), batch_brief (pr-reviewer's brief shows the chore in place of lines), model_forms (the section's form, written by `work chore`). Skills: shaping-items says that an item with no behaviour a scenario checks takes `work chore` with a check that fails now and passes once done, in place of lines (and the shaping brief's chore fallback points at it); building-a-batch says a chore task is built until its check passes and `work batch done` runs it. Scenarios: readiness, an item with a chore and no line readied, `work chore` writing the section, the two exclusions; batches, a chore whose check exits 1 refused at done, a commit touching an unnamed file refused, the brief holding the chore. Left out: the bar running the check; a chore beside lines. No dependency. Rating: high value (about 45 triaged chore items, b34 among them, cannot be batched without it), high urgency (the backlog work of quote-42 waits on it), medium size (one command, the bar, done and the brief, two skills).
