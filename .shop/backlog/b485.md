# Parking an item whose model line restates an operation identically keeps the operation

## Notes

batch-61 review-1 observation (b463): backlog_model_ops.restated treats an identical line as a restatement; the unlay walks history to before the operation existed and removes it. Same for a model line that repeats an operation unchanged.
r89 retires r88: r88's 'does not hold the model line' is false when the model line repeats the operation unchanged (that line is the operation as the base held it). r89 says what parking must give in both cases: the operation as the domain model held it before the lay. Its scenario must catch the defect: the model line repeats the operation byte for byte (backlog_model_ops.restated then held() walks history past the operation's creation and the unlay removes it). Rating: medium-value (a park or unlay silently deletes a delivered operation from spec/model), medium-urgency (b463 shipped; any item restating an operation unchanged hits it), small (restated/held in backlog_model_ops.py and one scenario).
