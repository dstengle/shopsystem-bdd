# The UserPromptSubmit hook keeps the session in a repository migrate init founds in that same turn

## Notes

UX trial 2 (2026-11-20, 0.40.0): the hook keeps a session only where .shop/ exists, so in a fresh repository the person's first words (said in the turn that ran migrate init) gave 'work quote: no session is known'; the session found its transcript under ~/.claude/projects and passed --transcript. migrate init could keep the pointer for the session that ran it, or the refusal name --transcript and where transcripts are.
Shaping (2026-11-20): a chore, no new line. quotes#r2 already says 'When the person prompts a session, the conversation service shall keep the transcript of the session' with no condition on .shop/; conversation_prompt.keep breaks it in a git repository with no .shop/ (the turn that runs migrate init). Fix: keep writes the pointer in the git dir of any git repository the cwd is in (the pointer is never committed, so a repository that never becomes a context gains only an untracked file in its git dir); the 'no .shop' case of test_the_prompt_hook_never_fails changes to expect the pointer, and a new test test_a_repository_without_a_shop_keeps_the_session prompts in a bare git repository, then runs migrate init and work quote there with no --transcript. The module docstring and CLAUDE.md's row stay true. Rated: medium value (a fresh context's first quote), medium urgency, small size.
