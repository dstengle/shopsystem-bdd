# Entailment carried into the implementation and the tests: a consequence the spec entails (a refusal exits with an error and changes nothing, U11) is guaranteed by one code path and tested once, not repeated as a step in every scenario

## Notes

The person, quote-18. From b112's brainstorming (2026-11-09): refusal lines say only 'shall refuse the command and name X'; U11 and the CLI pack's definition of refuse (b122) entail 'exit with an error' and 'change nothing'. The entailed-Then check (b119's studies, .shop/records/2026-11-09-model-logic-at-scale.md: comp.py, each entailment naming its premise) finds them. In the implementation: every command's refusal goes through one shared path that exits with an error naming the reason and leaves the repository unchanged (a structural rule, verified once: a design-decision and a test of that path, or the check that runs after every scenario, as vocab.py does for U11 today). In the tests: the generator leaves the entailed Thens out of each scenario (or marks them as covered by the universal check), so a scenario holds only what its line says. Generalises to any universal statement or pack definition whose consequence one code path guarantees.

Folded into b142 (I13a, the check side), b144 (I14a, the generator side) and b145 (I14b, the one refusal path, a plan) (2026-11-10), as the 4.0 design records (.shop/records/2026-11-09-cnl-4/design.md, section 8 and section 10.3 I13a, I14a, I14b); withdrawn here.
