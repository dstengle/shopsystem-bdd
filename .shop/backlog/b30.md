# work reply and work turn check the side

## Notes

Split from b26 (design, the r34 side check): work reply and work turn refuse to run on the side whose part it is not, as the other request commands do; left out only because the asker answered in the upstream's repository.

## Requirements

### requests

- **received** (condition of request): a request whose record is kept in the repository of its upstream and whose asker is another bounded context.
- **sent** (condition of request): a request whose record is kept in the repository of its asker and whose upstream is another bounded context.

#### [g45] `work reply` refuses a request this context received
- [r45] If the person runs `work reply` on a request that is received, then `work` shall exit with an error naming the request.

#### [g46] The upstream's `work turn` refuses the asker's turn
- [r46] While a request is received and the request is `awaiting-asker`, if the person runs `work turn` on the request, then `work` shall exit with an error naming the request.

#### [g47] The asker's `work turn` refuses the upstream's turn
- [r47] While a request is sent and the request is `open`, if the person runs `work turn` on the request, then `work` shall exit with an error naming the request.
