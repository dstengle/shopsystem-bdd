# The spec says every committing command is refused on a task's branch

## Notes

From .shop/batches/8/review-1.md (f3, observation, b57): refuse_task_branch is called from shop_files.committed, so every committing command (work record, decision, quote, outcome, line, ...) is refused on a task's branch batch-<n>-b<j>, but backlog#r20 names only work idea. Batch commands commit through batch_plan.commit on the base and are unaffected. Put the wider refusal in the spec: a universal condition (work line --universal) or a line per command.
The readiness bar (readiness_bar.well_formed) refuses an item whose only line is a universal condition: backlog_section.ids counts capability requirements only, so U20 alone gives 'it has no requirement line'. U20 parses to one meaning (spec parse --form: while in(repository, workspace of task), if a service keeps a kept change, refuse the request and name the task).

## Requirements

### universal

- [U20] While this repository is in the workspace of a task, if a service keeps a kept change, then the service shall refuse the request and name the task.
