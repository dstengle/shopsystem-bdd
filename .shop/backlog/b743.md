# spec obtain registers all or none of a provider's adapter specs, and a counter-example is written or the group refused when no boxes deny every other value

## Notes

batch-134 review observations: when the registry refuses a later adapter spec, contracts already registered for earlier ones stay committed though the command exits 1; when no boxes rule out every other value, b732 writes no counter-example at all, untested.
Two behaviours from batch-134's review: spec obtain keeps all or none of a provider's contracts when the contract registry refuses a later adapter spec's registration (decisions 0147, 0149; checking r137-r140, contract-registry r4), and features generate writes a counter-example of every when the precondition's no boxes deny every other value of the restriction's attribute (b732's spec_steps4_counter.denied).

## Requirements

### checking

#### [g141] A registration the contract registry refuses deregisters the contract registered for another adapter spec of the provider
- [r141] While an adapter spec has a provider, when the contract registry service refuses the request to register a contract for the adapter spec, the specification service shall deregister the contract for a different adapter spec that has the provider.

### contract-registry

#### [g5] A contract deregistered for an adapter spec is no longer kept by the registry
- [r5] When the specification service deregisters a contract for an adapter spec, the contract registry service shall complete the request.
Relied on by: checking#r141

### scenarios

#### [g49] generation writes a counter-example with no value of the attribute when the no boxes of the precondition deny every other value
- [r49] While a requirement of a requirement group of a capability uses `every` and the requirement has a restriction and the precondition of the requirement uses `no-noun` and `and-condition`, when the person generates the feature of the capability, the scenarios service shall keep a counter-example that uses `has-no-value`.

### registry model

```model
service contract registry
  operation register(contract, adapter spec, provider, version)  compensated by deregister  outcomes: done → the contract | refused: contract not registered
  operation deregister(contract, adapter spec, provider, version)  outcomes: done → the contract
```

- **deregister** (verb, action) → operation contract registry.deregister. The specification service has the contract registry undo a registration of a contract for an adapter spec, so that the registry no longer keeps the contract for it. Forms: deregisters, deregistered. Frame: <actor> deregisters <contract> for <adapter spec>.
