# One actor across two vocabularies

## Notes

L-2 of the contracts design, first slice. Entries in different layers naming one model element are one referent in the logical form and the facts; today a provider's 'the client' aliased to the port's service stays a constant of its own. Needed so a provider line on the client applies to the adapter's request (decision 0118).

## Requirements

### parsing

#### [g23] Two terms of one element are one referent of the logical form
- [r23] While a term means an element and a requirement uses the term and another term means the element and the requirement uses the term, when the person parses the requirement with the logical form, the language service shall return a logical form that holds one referent of the element.

### specification model

```model
object element
  relations: has → referent (many)

object term
  relations: means → element (one)

object logical form
  relations: holds → referent (many)
```

- **element** (noun) → object element. One thing the domain model declares, an object, an attribute, a value, a relation, a service, an operation, an event or an actor, which a vocabulary entry names after its arrow. Plural: elements.
- **mean** (verb, state) → relation term.means. A vocabulary entry names one element of the domain model, so that entries of different layers that name one element are one referent of a line. Forms: means, meant. Frame: <term> means <element>.
