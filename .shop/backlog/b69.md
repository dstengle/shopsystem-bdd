# A person's comment on a batch's pull request reopens the batch with a finding

## Notes

From the person's comment on PR #24 (batch-9, awaiting-merge, 2026-11-06), which asked for recovery when a post succeeds and the commit recording its URL fails. No command takes a batch that is awaiting-merge back to review with the person's finding: work batch brief and reviewed take only an in-review batch, and a fix commit must cite an open finding of a recorded review. For batch-9 the batch file's status was set back to in-review by hand, and the person's comment was saved as review 3's findings file. Wanted: a command (for example work batch reopen <batch> --finding <file>, or reviewed taking a person's findings) that records a person's pull-request comment as a review with a fix-now finding and sets the batch to building.

## Requirements

### reviews

#### [g11] A person's finding on a batch awaiting its merge reopens the batch
- [r11] While a batch is `awaiting-merge`, when the person reopens the batch with a review finding, the batches service shall keep a review of the batch that holds the review finding and set the status of the batch to `building`.

#### [g12] A batch not awaiting its merge is not reopened
- [r12] While a batch is not `awaiting-merge`, if the person reopens the batch with a review finding, then the batches service shall refuse the request and name the batch.

### execution model

```model
object batch kind of file
  lifecycle status: awaiting-merge → building

object review kind of text
  relations: holds → review finding (many)

service batches
  operation reopen(batch, review finding)  outcomes: done → the review | refused: batch not awaiting merge
```

- **reopen** (verb, action) → operation batches.reopen. A batch that awaits its merge taken back to building with a finding the person wrote on its proposed change, kept as a review. Forms: reopens, reopened. Frame: <actor> reopens <batch>.
