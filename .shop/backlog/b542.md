# State invariants in grammar 4: a line that states what always holds between two states of things, read by spec logic as a premise

## Notes

The person, 2026-11-24 (quote-74): state invariants are a bigger change to the grammar and should not be buried in the adapter effort. Found by the adapter specs example (2026-11-24): an L1 between an adapter's store ('an order has no entry') and the port's state ('a reservation for the order exists'); grammar 4 has no form for a state invariant (R12 needs a trigger, or always/never with a response). A language change for every context: construct, logical form, facts, check.lp and entail.lp premises, scenarios.
This item is L-4 of the contracts design; it is not on the first slice: until it lands, an adapter spec shows the clash of its store against the port's state as a known L1.
