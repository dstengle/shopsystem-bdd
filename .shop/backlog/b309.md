# holds-exactly in a precondition read by model logic and features generate

## Notes

Found shaping b297 (2026-11-16): 'While a worktree holds exactly the files that cover a line, ...' gives 'no translation of every there' in model logic and features generate, though b274's note says the precondition form works. Reproduction in the scratch copy b297 left (scratchpad/b297/).
Shaped 2026-11-16 (no quote: a defect of b274/b297 found shaping b297; the triage, .shop/records/2026-11-16-backlog-triage.md, lists it among the translation gaps b306 would catch). Reproduced on a copy of the construct catalogue's context (grammar/corpus/constructs/spec/index.md) with one capability c1: r1 'While a worktree holds exactly the files whose version is `2.0.0`, when the person runs `work start` on the worktree, `work` shall print the worktree.' reads in model logic (with r2 forbidding the print on a worktree holding a `2.0.0` file: L1; on one holding a `1.0.0` file: no findings, so the only half is read) but features generate writes Givens that contradict each other: 'the worktree w1 holds the file f1' and 'the worktree w1 holds no file' (the only half's restriction dropped). With 'the files that cover a line' or 'the files whose version is not `2.0.0`' both tools give 'no translation of every there' (model logic: unread c1#r1). Two faults: (1) spec_lf_quant's every in a condition reads a restrictor only of plain values and rows to a thing outside the box, not a relative clause with a K2 of its own ('that cover a line', a referent in the box) nor a negated value (a not box); the change reads such a restrictor (the K2 as uex reads one, a not box as a negated uattr/urel) with check.lp's umatch extended to it, and spec_lf_none's nobox reads the only half as it does for the value; (2) spec_steps4_boxes/spec_steps4_counter give the precondition's only half as a K that fails P brought in with the Given that the collection does not hold it ('a file f2', 'the version of the file f2 is `1.0.0`', 'the worktree w1 does not hold the file f2'), in place of the unrestricted 'holds no file'. Checks: design-model-check's line that model logic translates a requirement whose precondition uses holds-exactly with rc-subject (as r289; the world in design_model_check_worlds); feature-file-tools' two lines that the scenario of a precondition using holds-exactly, with a value and with rc-subject, holds a step using not-condition (as r120/r125, the world in feature_file_tools_uses, the step told by model constructs). Leaves out: holds-exactly with rc-object or a negated value in a precondition get no line of their own (the same restrictor reading covers them); b315 (holds-exactly on a response's object with a relative clause reaching a second thing) is shaped apart. Rating: value medium, urgency medium (a delivered construct that reads wrong where b274's note claimed it works), size medium, up from small: shaping found the second fault (the contradictory Givens) and the restrictor needs check.lp's umatch extended, not only a translation. No dependency.
