# Skills and tools for writing every kind of artifact from scratch

## Notes

Every artifact type (capability file, glossary term, relation, decision, record, request, item, ...) and every action on it gets a skill or a command, so an agent writes one from scratch without copying or reading existing ones; the person's words in quote-2.

Rated high value and high urgency because the person called it important (2026-11-05) and agents today copy existing files to learn a form. Size medium: one new module of forms and two subcommands of `model`.

This item is the first slice, the catalogue and the blanks:
- `model forms` prints one line for each file form: its name, its path pattern, and what writes it, either a command (`work idea`, `work request`, `work quote`, `work line`, `measure batch`, `measure defect`, `features generate`, `model decisions`, ...) or "by hand from `model form <name>`".
- `model form <name>` prints the blank. A blank names every frontmatter field with its allowed values (the glossary's values where there are any), every section in order, and a one-line comment in each section saying what goes there.
- The file forms come from the readers, kept in one new module (a row in CLAUDE.md's module map): a capability file (codified-1: frontmatter, Purpose, Terms, Behaviour groups with a given block, Implementation, Not yet, Dropped), a glossary term bullet of each category, a `## Relations` row, a `## Upstreams` entry (with `github:`), a universal condition, a design-decision (with `tier:`), a record and its `.shop/records/README.md` row, an item, a request, a quote, a batch plan, `.shop/delivery.toml`, a measurement, a defect, and a review findings file.
- A test reads each blank back through the reader of its form, so a form cannot drift from what is read.
- The skills that tell a session to write such a file by hand (shaping-items, raising-a-request, taking-in-a-request, building-a-batch, analyzing-a-batch) and CLAUDE.md's rule on records point to `model form <name>`.

Commands that write the forms that have none yet are b43 "Commands that write the file forms written by hand today". b13 "An item proposes a new capability or a glossary term" covers a new capability and a glossary term.

## Requirements

### design-model-check

- **file form** (kind): one kind of file a bounded context keeps, with its path, its fields and sections, and the command or skill that writes it. Plural: file forms.
- **blank** (kind): a file of one file form with each of its fields and sections named and none filled in, that the form's reader reads without a refusal. Plural: blanks.
- **unknown** (condition of file form): a file form that `model` does not have.

#### [g55] `model forms` lists every file form
- [r55] When the person runs `model forms`, `model` shall print every file form and exit successfully.

#### [g56] `model form` prints the blank of a file form
- [r56] When the person runs `model form` on a file form, `model` shall print a blank and exit successfully.

#### [g57] `model form` refuses an unknown file form
- [r57] If the person runs `model form` on a file form that is unknown, then `model` shall exit with an error naming every file form.
