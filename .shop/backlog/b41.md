# Skills and tools for writing every kind of artifact from scratch

## Notes

Every artifact type (capability file, glossary term, relation, decision, record, request, item, ...) and every action on it gets a skill or a command, so an agent writes one from scratch without copying or reading existing ones; the person's words in quote-2.

Rated high value and high urgency because the person called it important (2026-11-05) and agents today copy existing files to learn a form. Size medium: two `work` commands and one `model` subcommand.

Reshaped 2026-11-05 at the person's word: commands write each file whole, so no blank to copy is needed; `model forms` stays as the index of which command writes which file.
- `work decision "<title>" --summary "<one sentence>" --tier check|requirement|judgement --decision "<text>"`, with `--context`, `--alternatives` (text, or `@<file>` for a file's text), `--source` and `--by`: writes `spec/decisions/<next nnnn>-<slug>.md` (frontmatter id, summary, date, status `accepted`, tier; `# <nnnn>. <title>`; `## Context`, `## Decision`, `## Alternatives`), rewrites the decisions index as `model decisions` does, and commits both. With no `--tier`, it is refused, naming `--tier`, and writes nothing.
- `work record "<title>" --kind <record kind> --summary "<the index row's text>" --body <file>` (with `--slug`, default from the title, and `--date`, default today): writes `.shop/records/<date>-<slug>.md` with its frontmatter (id, kind, about, date) and `# <title>` over the body, appends the row to `.shop/records/README.md`, and commits both. An existing path is refused.
- `model forms` prints one line for each file form: its name, its path pattern and the command that writes it (`work idea`, `work line`, `work request`, `work quote`, `work decision`, `work record`, `measure batch`, `measure defect`, `features generate`, `model decisions`, ...), or the item that will give it one (b13 for a capability and a glossary term, b43 for the other spec pieces). The table lives in one new module with a row in CLAUDE.md's module map; a test checks that each command it names exists.
- The skills and CLAUDE.md's rules that tell a session to write a decision or a record by hand point to `work decision` and `work record`, and to `model forms` for the rest.

b43 "Commands that write the file forms written by hand today" covers the spec pieces (a relation row, a universal condition, an upstream entry, a given block), which go through an item like a term, and b13 "An item proposes a new capability or a glossary term" covers a new capability and a glossary term.

## Requirements

### design-model-check

- **file form** (kind): one kind of file a bounded context keeps, with its path and the command that writes it. Plural: file forms.

#### [g55] `model forms` lists every file form
- [r55] When the person runs `model forms`, `model` shall print every file form and exit successfully.

#### [g56] `work record` writes and commits a record
- [r56] When the person runs `work record`, `work` shall write a record and commit the record.

### decision-tiers

#### [g7] `work decision` writes and commits a decision
- [r7] When the person runs `work decision`, `work` shall write a design-decision, write the decisions index and commit the design-decision.

#### [g8] `work decision` refuses a decision with no tier
- [r8] If the person runs `work decision` on a design-decision that is untiered, then `work` shall exit with an error naming `--tier` and change nothing.
