# work ready names every failing line in one run

## Notes

From the feed product's session on 0.35.0 (feedback relayed by the person, 2026-11-16), item 11: one failing line per run; rewording two lines took three runs.
Shaped 2026-11-16 (triage: shape, `.shop/records/2026-11-16-backlog-triage.md`; no quote names b305). Reproduced: readiness_bar.check called on a stand-in b305 with readiness lines (a throwaway script; nothing written). Two lines that do not parse are both named already (`_parses` loops over every line). The fault is the stages: `well_formed` returns at the first stage with a reason. An item with r90 (`... shall frobnicate the item.`, no parse) and r91 ("When the person runs `work ready` on an item, `work` shall ask a question.") gave only `readiness#r90: does not parse at frobnicate`; r91 alone gave `L1 readiness#r4 and #r91 clash`. So rewording the first line only shows the second on the next run. Decided: `readiness_bar.well_formed` runs every stage over every line: the parse, then `model logic` (L0, L1, unread) and `features generate` on the copy whatever the parse found, each line named by the first stage that refuses it (an unparsed line is not named again as unread, and a capability whose generate fails only because of an unparsed line of the item gives no second reason). The capability-file and lexicon problems still stop the bar before the parse, since a broken lexicon breaks grammar 4's compile; that gate is left as it is. Module: `readiness_bar.py` only (its module-map row unchanged in meaning). The scenario: a shaped item with one line grammar 4 refuses and another that parses but has no translation (as r41's handlers build one); `work ready` exits with an error naming both requirement ids. Left out: running the lexicon stage beside the parse. With b77 (ready, not built; adds a v15n stage after `_parses`): b305 depends on b77, so b77's stage is built first and b305 makes it run with the others, not behind the parse; if the order changes, whichever is built second keeps every stage after the lexicon ungated. batch-40's readiness_bar change is not this. Rating kept: medium value (two rewordings in one run, item 11 of the feed product's 0.35.0 feedback), medium urgency, small.
