# work sync applies only the poster's side of a comment

## Notes

From batch-1 review 1 (.shop/batches/1/review-1.md, the Important observation): work sync writes every section a readable comment carries and its status and turn, whoever posted it, so a comment can write the upstream's outcomes, into and resolution on the upstream's record (against decision 0067); and a new ask is recorded without the allow list of decision 0071. Apply only the poster's part per step, and gate a new ask. Related to b32.
Also from batch-1 review 2 (.shop/batches/1/review-2.md): since sync reads closed records' issues too, a comment carrying `status:` or `turn:` on a closed request's issue can reopen a delivered record; ignore those fields on a closed record, or read such a comment as unreadable.
Shaping (2026-11-06): a comment carrying an entry of the other side's part (a foreign entry) is still written, so it is no longer unrecorded and `work watch` does not wake on it again, but that entry is not applied; the poster's own entries are (r32). The poster's side is read off the step, a `turn` being the side's whose turn the request was. A comment on a closed request is written but its `status` and `turn` are not applied (review-2 f11), rather than read as unreadable, for the same reason. Gating a new ask through the allow list of design-decision 0071 is left to b32 "Tell one asker of a request from another", which holds the allow list (requests' Not yet names it), so this item has no line for it.

### requests

- **foreign entry** (kind): an entry of a comment (`<field> <n>: <text>`) of the part of the side that did not post the comment's step: an entry of the upstream's part (`question`, `outcome`, `counter`, `reason`, `into`, and `resolution` but on a `fits`) in a step of the asker (`ask`, `fits`, or a `turn` posted in the asker's turn), or an entry of the asker's part (`line`, `answer`) in a step of the upstream (`offer`, `accept`, `resolve`, or a `turn` posted in the upstream's turn).

#### [g52] `work sync` writes no entry of the other side's part
- [r52] While a comment that is unrecorded holds a foreign entry, when a session runs `work sync`, `work` shall write the comment, and `work` shall not write the foreign entry.

#### [g53] `work sync` reopens no closed request
- [r53] While a request is closed and a comment on the request is unrecorded, when a session runs `work sync`, `work` shall write the comment, and `work` shall not change the status of the request or change the side of the request.
