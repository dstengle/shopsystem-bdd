# The batch service says the next step of a batch, so any driver can run it

## Notes

quote-98: orchestration made service oriented, so different drivers can be tried: work batch next returns the batch's next step as a response (dispatch these tasks with their briefs; close this task; publish; review with this brief; record these findings; fix these findings; park; stop at awaiting-merge), and each step's result is reported back through the existing operations (done, park, reviewed, review). A driver is then any implementation looping on it: today's LLM driver from the brief, a Workflow script, a headless runner; the agent runner behind a driven port with adapters (decision 0125: which is wired is a technical decision). The batch service says what a batch needs next, so that any driver (the one that runs the batch's tasks and reviews: today's agent from the batch brief, a script, a headless runner) loops on it; each step's result goes back through the existing operations (finish, park, submit, review, conclude). ## Requirements

### batches

#### [g132] A batch with a pending task asks the driver to build the task with its brief
- [r132] While a batch is `building` and a task of the batch is `pending`, when the driver polls the batch, the batches service shall return a batch step whose instruction is `build task`, the task and the batch brief of the batch.

#### [g133] A batch with a running task asks the driver to finish the task
- [r133] While a batch is `building` and a task of the batch is `running`, when the driver polls the batch, the batches service shall return a batch step whose instruction is `finish task` and the task.

#### [g134] A batch whose every task is done asks the driver to submit it
- [r134] While a batch is `building` and every task of the batch is `done`, when the driver polls the batch, the batches service shall return a batch step whose instruction is `submit batch`.

#### [g135] A batch awaiting its merge tells the driver to stop
- [r135] While a batch is `awaiting-merge`, when the driver polls the batch, the batches service shall return a batch step whose instruction is `stop`.

#### [g136] A batch in review asks the driver to review its change with the review folder
- [r136] While a batch is `in-review`, when the driver polls the batch, the batches service shall return a batch step whose instruction is `review change` and a review folder of the batch.

### execution model

```model
object batch step
  attributes: instruction: build task | finish task | submit batch | review change | fix finding | park item | stop
  relations: holds → task | batch brief | review folder | review finding (many)

actor the driver kind of agent

service batches
  operation poll(batch)  outcomes: returned → the batch step

object batch
  relations: has → batch brief (one)
```

- **batch step** (noun) → object batch step. What a batch needs done next, as the batches service says it to the driver: its instruction and the tasks, brief, review folder or findings it is about.
- **instruction** (attribute) → attribute batch step.instruction. What a batch step asks the driver to do.
- **build task** (noun) → value batch step.instruction build task.
- **finish task** (noun) → value batch step.instruction finish task.
- **submit batch** (noun) → value batch step.instruction submit batch.
- **review change** (noun) → value batch step.instruction review change.
- **fix finding** (noun) → value batch step.instruction fix finding.
- **park item** (noun) → value batch step.instruction park item.
- **stop** (noun) → value batch step.instruction stop.
- **the driver** (proper noun) → actor the driver. Whatever runs a batch by asking the batches service for its next step and reporting each step's result back: an agent, a script or a runner.
- **poll** (verb, action) → operation batches.poll. The driver asks the batches service for the next step of a batch. Forms: polls, polled. Frame: <actor> polls <batch>.
