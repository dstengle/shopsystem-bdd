# Object comparisons: one thing's value compared with another's, and a thing said to be the same as or another than one named before

## Notes

Reach: the comparison of two things' values ('the publication time of x is after the publication time of y', equal, before) in the grammar, the logical form, model logic's check and spec_steps4's Givens (each thing given a value that meets it); identity of a response's thing with a trigger's ('the video list it requested', R2's 'the K' in a response) shown in a construct and a Gherkin example. Retires known limit #6 and lets migration-tools r77-r80 compare the repository's release with the plugin's.
Shaped 2026-11-15 from the person's quote-29 ("Shape all four, fixes first, then ordering and comparisons"), quote-30 and quote-31, over decision 0093 and the record .shop/records/2026-11-15-collections-review.md (limit #6: 'the release of a repository is after the release of the plugin' does not parse). Builds two constructs. `value-compare`: 'the T of x is after|before the T of y' and 'is not after|before', T one attribute word (two entries of it, as the release of a repository and of a tool, both with the same Order:: by number, or as listed with the same Values:); an attribute with no Order: is refused naming the term (r290), as are two attributes of different words or orders. `value-same`: 'the T of x is the same as the T of y' and 'is not the same as', for any attribute, ordered or not. Form: one atom, cmp(release(x1), after, release(x2)) and cmp(release(x1), same, release(x2)), negation under not (spec_lf_order's cond and show; spec_rgl_np's T_CmpT and T_SameAs, positive and negative). Check (check.lp, spec_lf_facts_atoms, spec_lf_order's literal): a two-place ccmp2(R, X, T, Op, Y, Pol); each thing of a pair takes a cell of the points the pair names (as ccmp does today), and two things' comparison holds by their cells; in one gap of a dense (by number) order two things' order is left open. It decides exactly two lines whose comparisons of the same two values contradict (they never fire together, so their opposite acts are no L1: r292) and a comparison against the named values either side states; it does not decide a cycle of comparisons through three or more things in one gap, which it treats as able to hold (an L1 it may report that could never fire; never a clash it hides). Scenario (spec_steps4 by spec_lf_order's given): each thing given a value that meets every comparison and value the line names, a listed value first ('the release of the repository r1 is `0.99.0`', 'the release of `migrate` is `0.34.1`'); generation is checked through r108 on the constructs' shall examples. Value types: the lexicon declares none today (an attribute's values are codes, ordered only by Order:; a moment of the time pack already compares with a moment, moment-compare); this item adds none, so decision 0093 point 3 holds with nothing new. Dropped from the title: a thing said to be the same as or another than one named before is what DetSame, DetAnother, DetDifferent and R2's 'the K' in a response already do (spec_lf_distinct; 'shall print the item and not print another item' reads distinct(x5, x3)); 'the stage that the session ends' (an object relative clause on an action verb) adds nothing 'the stage' does not, and is left out. Also: grammar/language.md's ordered comparison section gains the two forms and known limit #6 goes; model_constructs_table gains value-compare and value-same with shall examples. Rewording, in the batch by hand once the constructs parse (the bar cannot check a line the item's own grammar makes parse): migration-tools r77, r78, r79 retired for new lines saying 'the release of this repository is the same as the release of `migrate`' (r77, r79) and 'is after the release of `migrate`' (r78), their given blocks unchanged, using the item's term release (attribute of tool); r80 stays (its 0.33.0 names the step it upgrades from, not the plugin's release). Reconciled with b267 (2026-11-15): b266 owns the order of an attribute's values. It builds the field `Type: number|time|text` on an attribute entry, read by spec_lexicon and spec_value_kinds (beside `Values (adjective|noun):` and `Order:`); a value of a typed attribute is any literal of that type (a number, a moment, a quoted text), not only a listed code, and a typed attribute needs no `Order:` (decision 0093 point 3). The term value order (noun, of term, one) replaces the dropped `order (attribute of term)`, whose word collided with b267's order (noun); r290 refuses `value-compare` on a term that has no value order (no `Order:` and no `Type:`). This brings two typed numbers or two times into reach of `value-compare`: it takes after and before for every ordered type, a number's after its greater; "more than", "less than", "at least", "at most" between two values are left to later (they stay the count's words). b267 depends on b266 for value order and `Type:`.

## Requirements

### design-model-check

- **comparison** (noun): one thing's value of an attribute said against another thing's value of the attribute, as "the release of x is after the release of y" or "is the same as", in the precondition of a requirement. Kind of: thing.
- **contradict** (verb, state): no values of two things meet both of two comparisons of the same two things' values of one attribute. Forms: contradicts, contradicted. Frame: comparison contradicts comparison.
- **value order** (noun): the order of an attribute's values: the order its entry's `Order:` gives, or the order of the type its entry's `Type:` declares (a number, a time or a text). Kind of: thing.

| comparison | of | precondition |  |
| value order | of | term | one |

#### [g288] `model parse` reads one thing's value compared with another's
- [r288] When the person runs `model parse` on a requirement that uses `value-compare`, `model` shall exit successfully.

#### [g289] `model parse` reads one thing's value said to be the same as another's
- [r289] When the person runs `model parse` on a requirement that uses `value-same`, `model` shall exit successfully.

#### [g290] `model parse` refuses a comparison of an attribute that has no order
- [r290] While a term has no value order and a requirement uses the term and `value-compare`, if the person runs `model parse` on the requirement, then `model` shall refuse the command and name the term.

#### [g291] `model logic` finds the clash of two lines under one comparison
- [r291] While a requirement of a capability uses `value-compare` and the requirement obliges an act and another requirement of the capability that has the trigger of the requirement forbids the act, when the person runs `model logic`, `model` shall print `L1`.

#### [g292] `model logic` finds no clash between two lines whose comparisons contradict
- [r292] While a requirement of a capability obliges an act that another requirement of the capability forbids and a comparison of the precondition of the requirement contradicts a comparison, when the person runs `model logic`, `model` shall exit successfully.
