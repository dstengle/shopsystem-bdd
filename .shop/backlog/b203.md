# A universal condition's grammar falls back to the index's marker when spec/universal.md is absent

## Notes

work line --universal creates a missing spec/universal.md with language: codified-1 (backlog_forms.py), and spec_language.four(..., universal=True) reads only that file's marker, so a fully codified-2 context with no universal.md has its universal conditions read in the old grammar. The created file's marker should follow spec/index.md, or four should fall back to the index's marker when the file is absent (review of plan-cnl4-foundation, finding 2).
Shaped 2026-11-16 (triage: worse than written). Reproduced on a copy of spec/ without universal.md: backlog_forms.lay_spec (what work ready and work batch start lay) created spec/universal.md with language: codified-1; spec_language.four(universal=True) then said False, so spec_context read none of its conditions (model logic never checks them, an untranslatable one is not refused by the bar) and model --root <copy> check printed v_p0 for spec/universal.md, naming migrate upgrade. Fix: backlog_forms._universal_file writes language: codified-2 (the one language since I19; alpha, no compat), module map row of backlog_forms unchanged. The fallback of four to the index's marker is left out: with no file there are no conditions to read. readiness r42 (work ready names a universal condition with no translation when universal does not exist; scenario: a context with no spec/universal.md, an item with a universal condition grammar 4 reads no translation of) and batches r? (work batch start writes universal at codified-2). Relation row translation of universal condition added in readiness. No dependencies.
