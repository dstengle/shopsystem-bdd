# Base kinds live in a pack every context imports

## Notes

text, file, repository, bounded context and version are named by 91 of 251 cross-area model references; a pack removes that coupling. Part of the disentangling of this repository into hosted contexts (decisions 0129-0133).
Decisions 0129-0133, 0131 (the plugin's packs a published language every context may import). Technical calls: the plugin's pack base (grammar/packs/base.md) holds the nouns text, file, version, repository and bounded context; in a context with a domain model, a kind of a pack the index imports is a declared object for the model (an object kind of it, a relation's or an attribute's target, a parameter's type), so v_m8 names none of them; migrate init writes imports: [base, request]. A consumer founded before keeps its imports (no upgrade step: adding base to a context with its own file or text would raise v_t16 there). This repository's own adoption (base imported, file, text, version, repository and bounded context out of spec/model/specification.md and spec/vocabulary/shared.md, a model object of a pack noun keeping its relations) is b618, which needs a way on an item to import a plugin pack and take a live element out.
Rated: high value (91 of 251 cross-area model references are kind of text or file), medium urgency, medium size (a pack file, the domain model reading imported pack kinds in domain_model_check and spec_vocabulary_terms, migrate init's imports; about 300-500 changed lines).

### specification model

```model
object element
  relations: refers to → term (many)
```

- **refer** (verb, state) → relation element.refers to. An element of the domain model names a term as its kind (kind of) or as the target of a relation or an attribute. Forms: refers, referred. Frame: <element> refers to <term>.
