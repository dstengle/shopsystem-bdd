# A response's request without parameters is read as a request by the model's line facts

## Notes

b571 keyed such a response as req(O,()) in spec logic's facts, but model_domain_lines' asks reads only a request with parameters: of b578's eight operations only suspend becomes an asks fact (deliver, allocate, restore, reopen, resolve read as plain events), so the request chain and a job's trace miss them.
World to fail before the fix: as checking_handlers_response.py's r71 world (domain-model fixture with the driven port stock beside it, stock.reserve governed by no requirement, no CLI table), but r1's response asks the stock service to reserve the note with no parameter (no 'with ...'); before the fix model_domain_lines.Lines.facts reads only a response's request atom, so r1 gives no asks fact, v_m7 names stock.reserve and spec check fails; the fix reads a response's act of a verb naming an operation (as spec_lf_facts_request.operated, b571) as asks too.
