# A lifecycle transition that an operation of another area performs is a violation

## Notes

a rule naming each lifecycle transition that no operation of the object's own service performs (b578 fixed item's four; the rule keeps it fixed). Part of the disentangling of this repository into hosted contexts (decisions 0129-0133).
Decisions 0129-0133, 0133 (tracking owns the item's lifecycle, execution changes it through tracking's operations; b578 fixed item's four transitions, this rule keeps it so). Technical calls: a new model.lp rule v_m9, severity error, beside w_m5: a lifecycle transition of an object is performed when a line whose trigger requests an operation of a service of the area declaring the object sets the object's attribute along that transition (sets/5 with requester/3); a transition only lines of other areas' operations set, or none, is v_m9 naming the object, attribute and transition (w_m5 keeps saying the one no line causes). New facts: each operation's and each object's area. If the built rule finds a violation in this repository's spec, the batch parks the item naming the transitions, as their lines are another item's.
Rated: medium value (keeps decision 0133's lifecycle ownership checked), medium urgency, small size (one rule, two facts, its catalogue entry; about 150-250 changed lines).
The line, and v_m9, say it from the other side: a transition that an operation of another area performs is a violation (an operation of the object's own area beside it does not excuse it, as decision 0133 has execution change an item only through tracking's operations); a transition no line performs stays w_m5's.

## Requirements

### checking

#### [g95] A lifecycle transition that no operation of its own area performs fails the check
- [r95] While an area holds a lifecycle and the lifecycle has a transition and another area holds an operation that performs the transition, if the person validates this specification, then the specification service shall fail the check and name the transition.

### specification model

```model
object lifecycle
  relations: has → transition (many)

object transition

object area
  relations: holds → lifecycle (many)

object operation
  relations: performs → transition (many)
```

- **lifecycle** (noun) → object lifecycle. The transitions an attribute of an object of the domain model may take, its `lifecycle <attribute>:` line. Plural: lifecycles.
- **transition** (noun) → object transition. One step of a lifecycle, from one value of its attribute to another, `<from> → <to>`. Plural: transitions.
- **perform** (verb, state) → relation operation.performs. A line whose trigger requests the operation sets the attribute of the operation's object from the transition's first value to its second. Forms: performs, performed. Frame: <operation> performs <transition>.
