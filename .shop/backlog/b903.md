# A capability named after a retired area is read in no area

## Notes

batch-181 review 1 observation: backlog_retire_area's lay takes area: out of each capability of the retired area, but a capability whose file name is the area's name (spec/capabilities/laying.md for laying, b899) falls back to its file name in backlog_retire_area.capabilities and spec_composition and is still read as in the area, against applying#r50. Fix before or in b899: a fallback that skips a name with no model file, or a capability written in no area the fallback cannot reach.
Defect of b898 (measure defect, batch-181 defect-1). Fix direction: the file-stem fallback (backlog_retire_area.capabilities, spec_composition.held, domain_model, adapter_uses, spec_vocabulary) applies only when the stem names an area that has a model file; the stem relations of capability and area give the line its words. Rating: medium-value, without it applying#r50 does not hold for a capability named after its area, which b899 retires (laying); medium-urgency, b899 waits on it; small size, one shared fallback and its readers.

## Requirements
