# The backlog's naming-the-task handler passes a step on in either registration order

## Notes

From .shop/batches/8/review-1.md (f4, observation, b57): batches_handlers.refused_naming_task returns False for a step whose last run was not work batch, so the backlog handler (tests/scenarios/backlog_handlers_upstream.py) gets it; the backlog handler never returns False and reads step.context['task_branches'] unchecked, so it works only by registration order, and a change of order fails the batches scenarios with a KeyError. Return False when task_branches is missing.
