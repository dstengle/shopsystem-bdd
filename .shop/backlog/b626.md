# A reply trigger names the request's object

## Notes

grammar 4 cannot tie a reply to the object it is about ('If the notebook service refuses the request ... the invitation' is refused for lack of an antecedent), so a compensation or a lifecycle waiting on a reply cannot be written. found by the notes product worked example (2026-11-25).
The construct reply-trigger (grammar 4): a trigger on a port's reply to a request the core made, said with the request it is on, 'the request to <operation verb> <np>' after the request pack's complete, return, refuse or fail ('When the registry service completes the request to publish the design-decision, ...', 'If the contract registry service refuses the request to retrieve the contract, then ...'), so a compensation and a lifecycle waiting on a reply can be written (decisions 0121, 0127, 0134) and v_pb2 met (b636's deposit done, retrieve returned, retrieve refused). Technical call: the replied request is 'the request to V <np>', generated for every verb naming an operation (spec_rgl_ops, beside its Params, over its frame's object), not a noun of each operation (deposit, retrieval), so no lexicon field is added and the request pack's words carry it (directive-6); its parameters are not said in it. Its logical form: a referent r of kind request with request(r, O, object: x), the reply's act (complete/return/refuse/fail) on r; R2 binds x as usual. b626 keeps the construct (parse, logical form, construct catalogue entry via spec catalogue entry and spec constructs --write, corpus sentences in grammar/corpus/constructs/request/, its tested lines in grammar/language.md): parsing r25, r26; the check's reading (v_pb2, spec logic's facts, features generate) is split to its own item. Worlds that fail first: r25's world is the construct catalogue's request context (design_model_check_worlds_response's registry port) with r1 'When the registry service completes the request to publish the design-decision, the decisions service shall keep the design-decision.', which grammar 4 refuses today; r26's runs spec parse --form on it and reads a request(r, registry.publish, object: x) atom beside complete(e, ..., object: r), which no form holds today.
Rated: high value and urgency (b636's port outcomes cannot be handled without it, decision 0127), medium size (a generated noun phrase, its logical form, a catalogue entry and two scenarios).
