# Two items of one batch that retire ids one decision enforces give one successor naming every line that retires them

## Notes

batch-135 review 1 observation: decision_successor.lay skips a decision already superseded by an earlier item's lay, so the successor keeps the second item's retired id under enforced_by; parking the first sets the decision accepted again.
Fix (technical call): decision_successor.lay gathers, per accepted decision, the retirements of every item of the lay (not item by item), writing one successor whose enforced_by replaces each retired id by the retiring lines of whichever item retires it and whose source lists each such item; unlay of some items rewrites a successor that other items' retirements still need from the old decision with only theirs (old stays superseded), and takes it out and sets the old accepted again only when no remaining item retires its ids. r174's one-item world is unchanged. Worlds to fail first: r1 (open) - two ready items of batches_world, each with a line retiring a different requirement id that one accepted decision names under enforced_by (two enforcers); today the second item's lay skips the already-superseded decision, so no decision names the second item's line and the Then fails. r2 (park) - that batch opened, then park the first item; today the unlay deletes the shared successor and sets the old decision accepted, so no decision names the second item's line. Source: batch-135 review 1 observation.
