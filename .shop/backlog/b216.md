# Grammar 4: a response that sets an attribute of a thing to a value

## Notes

Found writing b153 (reword requests): grammar 4 has no response that changes an attribute of an earlier referent. 'set the status of the request to `delivered`' does not parse (a declared value is no noun phrase after 'to'; 'set' is a word the old grammar spells itself, v_t6), and 'the request whose status is `delivered`' in a response is read by spec_lf_facts.restrict as a presupposition of the pre-state, so model logic reports the line contradicting itself. The design names set among initiates/terminates (section 7.2) and the old core had it. Needed: 'set the T of X to v' (and 'set its T to v') in the base grammar or the CLI pack, read as initiates(e, T(X)=v) by the form and the check, and its steps in spec_steps4. requests r73, r74, r78, r79, r81, r83, r85 (b153) wait on it; backlog and batches (b158) set statuses too.
Shaped 2026-11-10 for the rewords b153, b157, b158, b159: lines in design-model-check and feature-file-tools (codified-1, so the construct is the term setting): grammar 4 parses 'set the T of X to v' and 'set its T to v' in a response, model parse --form reads it as initiates(e, T(X)=v), model logic finds no clash in it (the value is the post-state, not a presupposition of the pre-state), features generate writes its steps (spec_steps4, Steps4.gf). Rated high value and high urgency: four reword items wait on it.
