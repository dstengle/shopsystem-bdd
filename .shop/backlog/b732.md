# A counter-example of an every box respects the no box of the same precondition

## Notes

batch-130 review 1 (b716): batches r153's feature says 'no task of the batch b1 whose status is `running` exists' and then brings in task t5 of b1 with status `running` as the every box's counter-example; the Givens contradict each other and batches_handlers' given_task_is ignores the no Given, so the world holds a running task the precondition says there is none of.
The counter-example of an every box in a response (spec_steps4_counter.counter/unmet) takes the first other value of the restriction's attribute, blind to a no box of the precondition over the same kind: batches#r153's feature says "no task of the batch b1 whose status is `running` exists" and brings in t5 of b1 with status `running` (batch-130 review 1 of b716), and batches_handlers' given_task_is ignores the no Given. Technical call: unmet picks the first other value of the attribute that no "no" box of the precondition denies of the counter-example member (a no box over the member's kind whose atoms, the member put in, hold of it but its value; r153 then takes `done`); when every other value is denied, generation writes no counter-example for that box (its two members and their Thens stay), never the atom negated, which would contradict the no box too. The line is scenarios' r12-style "a scenario that satisfies the precondition", under a While that the requirement uses every with a restriction and its precondition uses `no-noun`.
