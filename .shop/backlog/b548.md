# A driven port is an area and its needs are port lines

## Notes

C-3 of the contracts design, first slice. Area kind port; a port contract capability in it whose lines carry Relied on by: <core ids>; port operations left out of v_a1 (they have no CLI table) (decisions 0122, 0116).

## Requirements

### checking

#### [g64] An area of kind port is a driven port
- [r64] While the kind of an area is `port`, when the person validates this specification, the specification service shall complete the request.

#### [g65] A port's operation needs no table in the CLI contract
- [r65] While an area whose kind is `port` holds an operation and no adapter contract holds an operation table of the operation, when the person validates this specification, the specification service shall complete the request.

#### [g66] A port line relied on by a line that does not exist is refused
- [r66] While a requirement supports a requirement id that no requirement has, if the person validates this specification, then the specification service shall fail the check and name the requirement id.

### specification model

```model
object area
  attributes: kind: core | supporting | generic | port
  relations: holds → operation | capability (many)

object requirement
  relations: supports → requirement id (many)
```

- **area** (noun) → object area. One part of the domain model, a file `spec/model/<area>.md` with its `kind:`: a core, supporting or generic part of the business, or a driven port, whose operations and words are this bounded context's own. Plural: areas.
- **kind** (attribute) → attribute area.kind. What an area is, the `kind:` of its model file.
- **port** (noun) → value area.kind port.
- **support** (verb, state) → relation requirement.supports. A line of a port contract stands under a core line, which the port line names under its `Relied on by:`. Forms: supports, supported. Frame: <requirement> supports <requirement id>.
