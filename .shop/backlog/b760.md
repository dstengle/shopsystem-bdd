# work line --remove takes back a retirement written with --no-line

## Notes

Found shaping b758: a batches line retired with --retires <cap>#r<n> --no-line cannot be taken back (--remove refuses an id that is no line of the item), so b758 keeps batches#r167, r169 retired and their successors laying#r19, r20 with it.

## Requirements

### tracking model

```model
service drafting
  operation reinstate requirement(requirement id, item)  outcomes: done | refused: requirement id not retired by the item
```

- **reinstate** (verb, action) → operation drafting.reinstate requirement. The person takes a live requirement's retirement back out of an item, so that its batch keeps the requirement. Forms: reinstates, reinstated. Frame: <actor> reinstates <requirement id> in <item>.

### cli adapter

```toml
[operations."drafting.reinstate requirement"]
command = "work line"
[operations."drafting.reinstate requirement".parameters]
item = { positional = 1 }
"requirement id" = { option = "--remove" }
```
