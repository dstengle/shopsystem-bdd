# An offer quotes a capability's lines, not its raw file

## Notes

From the black-box test of b26 (.shop/records/2026-11-05-b26-github-blackbox.md): `work offer` pastes the whole capability file into the comment, frontmatter, given blocks and all, with the glossary; the asker needs the groups' lines and the terms they use. Overlaps b28 (what a context publishes).

## Requirements

### requests

| requirement | in | comment |  |
| term | in | comment |  |
| given block | in | comment |  |
| term | in | bounded context |  |
| given block | in | capability |  |

#### [g104] `work offer` quotes a capability's requirements and the terms they mention
- [r104] When a session runs `work offer` with the `--capability` option set to a capability on a request, `work` shall post a comment that holds every requirement of the capability.
- [r105] While a requirement of a capability mentions a term, when a session runs `work offer` with the `--capability` option set to the capability on a request, `work` shall post a comment that holds the term.
- [r106] While a capability holds a given block, when a session runs `work offer` with the `--capability` option set to the capability on a request, `work` shall post a comment that does not hold the given block.

#### [g105] `work offer` leaves out a term no requirement of the capability mentions
- [r107] While a term is in the bounded context and a capability has no requirement that mentions the term, when a session runs `work offer` with the `--capability` option set to the capability on a request, `work` shall post a comment that does not hold the term.
