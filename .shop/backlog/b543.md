# A response can make a request with its parameters

## Notes

L-1 of the contracts design (quote-77), first slice. A response act whose verb names an operation of another service read as a request with param and noparam, in the trigger's Params syntax ('hold the stocked product of the entry with the quantity of the order'), which today does not parse at with. Requester facts count it, which ends v_m7 on port operations; a core line triggered on its refusal states its reasons (v_m4). Absorbs b363's spec_lf_request.as_events. Decisions 0122, 0115.

## Requirements

### parsing

#### [g23] A response that makes a request with its parameters is parsed
- [r23] When the person parses a requirement that uses `response-request`, the language service shall complete the request.

#### [g24] The logical form reads a response's request with its parameters
- [r24] When the person parses a requirement that uses `response-request` with the logical form, the language service shall return a logical form that uses `request-params`.

### consistency

#### [g35] spec logic translates a response that makes a request
- [r35] While a requirement of a capability uses `response-request`, when the person examines this specification with the capability, the specification service shall return a translation of the requirement.
