# spec obtain writes a contract only into the adapter specs that pin its version

## Notes

From batch-95 review 1's observation f3: holders matches a providers: entry at any version, so spec obtain with no --version writes the published contract (say 1.3.0) into an adapter spec that pins the provider @1.2.0, whose r86 check still fails beside a contract it does not read. Settle by a line, e.g. obtain the pinned version for an adapter spec that pins one.
An adapter spec that pins its provider at a version reads only that version's contract, so spec obtain keeps that version for it, not the latest published.
Rated medium value and urgency: an adapter spec that pins a version fails r86 after obtain; small: spec obtain's holders and the version it fetches.

## Requirements

### checking

#### [g95] An obtained contract is kept at the version its adapter spec pins, not a later one
- [r95] While an adapter spec has a provider and the provider has the `1.2.0` version and the provider has a contract that has the `1.3.0` version, when the person obtains a contract from the provider, the specification service shall keep a contract that has the `1.2.0` version and keep the adapter spec that holds the contract.
