# work line --retires: a line that replaces another

## Notes

Design record .shop/records/2026-11-09-cnl-4/design.md, section 10.3 I0 (and section 13 point 1): `work line --retires <cap>#r<n> "<line>"` gives the new line the next id of its capability and writes the old id under the capability block's `retired:` in the item's ## Requirements (backlog_section reads and writes it; backlog_lines.lay_onto moves the old line out of Behaviour and its id into retired:, unlay puts both back, renumber keeps the retired id); the new id goes into unbuilt: like any laid line; an id the capability does not hold, or holds only under retired:, is refused. Its part of b112 (the person's words are in b112's notes): the rewords I21-I27 retire every reworded line through it.

## Requirements

### readiness

- **nonexistent** (adjective of requirement): a requirement named by an id that no capability holds as a live requirement.

#### [g13] A line that retires another
- [r13] Where `--retires` is given, when the person runs `work line` on an item, `work` shall write a requirement and commit the item.

#### [g14] A retired id that no capability holds
- [r14] Where `--retires` is given, if the person runs `work line` on a requirement that is nonexistent, then `work` shall exit with an error naming the requirement and change nothing.
