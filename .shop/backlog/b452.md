# spec parse --item b<n> reads lines with an item's words laid

## Notes

From the missing-commands and new-user-flow research of 2026-11-21: `spec parse`, `--form` and `spec explain` cannot read an item's new terms or model lines, so a session has to run `work ready` to find out why a line is refused. Lay the item on a copy, as the readiness bar does. The person's words in quote-68.

## Requirements

### parsing

#### [g19] A requirement that uses an item's term is parsed for the item
- [r19] While an item holds a term, when the person previews a requirement that uses the term for the item, the language service shall complete the request.

#### [g20] The logical form of a requirement that uses an item's term is returned for the item
- [r20] While an item holds a term, when the person previews a requirement that uses the term for the item with the logical form, the language service shall return one logical form of the requirement and complete the request.

#### [g22] A requirement outside the language is refused for an item
- [r22] If the person previews a requirement that does not conform to the language reference for an item, then the language service shall refuse the request and name the requirement.

### specification model

```model
service language
  operation preview(text, item, logical form (flag))
    outcomes: returned → the reading | refused: requirement not in the language, requirement of more than one logical form, reading rule broken, construct with no catalogue entry, fragment
```

- **preview** (verb, action) → operation language.preview. A person parses a requirement as it reads once the terms and model lines an item holds are laid into the specification, as `spec parse --item` does. Forms: previews, previewed. Frame: <actor> previews <text> for <item>.
