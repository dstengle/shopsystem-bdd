# A shop's hosted bounded contexts configured in .shop

## Notes

quote-82, decision 0129: .shop declares the bounded contexts the shop hosts, each with its id under the product; spec/index.md's context id and the area table read from it; replaces the area as the unit of a context.
Technical calls: a new service hosting in the execution area (the shop's management, beside its settings), capability hosting; operations host(bounded context, context id) and query(shop) in business terms, the CLI adapter's command work host <context id> and work hosts. A context id is under the product of the shop (the product path of this bounded context's id until the product identity of b602 exists); a shop that declares no hosted context hosts this bounded context alone (decision 0131 keeps one flat spec/). Where the shop keeps them (.shop) is an adapter decision, never a line. Reading spec/index.md's id and the area table from it is left to the disentangling items b613-b616.
Technical call (in place of the capability hosting above): the lines go into the batches capability (execution area, beside work settings set), a new operation host of the batches service, since a new capability cannot yet name its area (b645).

## Requirements

### batches

#### [g116] A bounded context hosted in the shop
- [r116] When the person hosts a bounded context with an id, the batches service shall keep the shop that holds the bounded context and complete the request.

#### [g117] A bounded context not hosted by an id out of the context id form
- [r117] If the person hosts a bounded context with an id that does not conform to the context id form, then the batches service shall refuse the request and name the id.

#### [g118] A bounded context not hosted by an id outside the product of the shop
- [r118] If the person hosts a bounded context with an id that the product id of the shop does not cover, then the batches service shall refuse the request and name the id.

### execution model

```model
service batches
  operation host(bounded context, id)  outcomes: done → the shop | refused: id not in the context id form, id outside the product id, id hosted already
  operation query(shop)  outcomes: returned → every bounded context

object shop
  relations: holds → bounded context (many); has → product id (one)

object product id kind of text
  relations: covers → id (many)
```

- **host** (verb, action) → operation batches.host. The person takes a bounded context into the shop under its id, beside the bounded contexts the shop holds already. Forms: hosts, hosted. Frame: <actor> hosts <bounded context>.
- **query** (verb, action) → operation batches.query. The person asks which bounded contexts a shop holds. Forms: queries, queried. Frame: <actor> queries <shop>.
- **shop** (noun) → object shop. The bounded contexts one product keeps together in one repository, each under its id, as `.shop/` lists them. Plural: shops. This: the shop of the repository the request is made in.
- **product id** (noun) → object product id. The id of the product a shop belongs to, the part of the id of this bounded context before its last part, as `missingmass.io/shopsystem`. Plural: product ids.
- **cover** (verb, state) → relation product id.covers. An id lies under a product id: the path of the id opens with the product id. Forms: covers, covered. Frame: <product id> covers <id>.
