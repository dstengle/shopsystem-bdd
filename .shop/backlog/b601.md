# spec obtain's refusals are ordered by a line when more than one If line applies

## Notes

From batch-95 review 2's observation: an unreachable upstream (r89) or one whose id is out of the context id form (r88) that no adapter spec has (checking#r94) meets two If lines on one trigger; the code names r88's or r89's reason only, and no line orders them. Condition r94 on a reachable upstream in the context id form, or add a line that orders the refusals.
spec obtain refuses an id out of the context id form (checking#r88) and an unreachable bounded context (r89) with their own reasons, before it looks for an adapter spec; r94 is retired by a line that holds only for an available provider whose id is in the context id form, so no two If lines meet on one request.

### checking

retired: [r94]
retires: [r95 r94]

#### [g95] A contract of an available provider in the context id form is obtained only for an adapter spec of the provider
- [r95] While the id of a provider conforms to the context id form and the provider is `available`, if the person obtains a contract from the provider that no adapter spec has, then the specification service shall refuse the request and name the provider and the `no adapter spec has the provider` reason.
