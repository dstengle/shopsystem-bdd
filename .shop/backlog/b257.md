# A value reads as an adjective or a noun: the short form 'an item is `v`' only for adjective values, the full form 'whose status is `v`' for noun values

## Notes

The person, quote-25 (2026-11-11): generated Gherkin is always fully expanded, whatever the value's kind: "Given the status of the item i1 is `idea`", never "the item i1 is `idea`"; an implementer binding steps (by hand, or with plain pytest-bdd as docs/getting-started.md teaches) must not have to look up the glossary to know `idea` is a status. features generate writes the full form for every attribute value in Givens and Thens; features regenerated; the step grammar, the handlers and the docs' examples follow.

The person, 2026-11-11: "I think my problem is that the status \"idea\" is a normally a noun while all of the other statuses are adjectives. When the shorthand is used, it looks unnatural because the shorthand isn't itself good english." (work quote crashed on it: b258), then quote-24 ("Option one also allows the rename to work as well, right? Go with #1"), reading the README's example line "While an item is `idea`, when the person runs `work shape` on the item, ...": the short form "X is `v`" (grammar 4 fills in the attribute whose value v is) reads as good English only when v is an adjective or participle (shaped, accepted, building); with a noun or a verb phrase it does not ("an item is `idea`", "an item is `needs-input`", "a design-decision is `check`", "a repository is `0.23.1`"). Chosen (option 1): each attribute declares the kind of its values (e.g. Values (adjective): ... / Values (noun): ...); the short form is accepted only for adjective values and refused for noun values with a hint naming the full form ("an item whose status is `idea`", "the tier of the design-decision is `check`"); renaming a value later to an adjective only changes its declaration. Not chosen: renaming the values (they are user-facing state names; tiers and versions have no adjective form), dropping the short form (verbose where it reads well).
Scope: the glossary reader and grammar 4 (the value kind, the refusal and its hint, the construct catalogue); this repository's attribute entries declared; every line using the short form with a noun value reworded to the full form (new ids, old retired, corpus blocks first, features regenerated); the README example, docs/writing-requirements.md, docs/reference/capability-file.md and the skills updated; migrate upgrade's 4.0 report (or a 4.1 step) names lines a consumer must reword. Release as a minor version if an undeclared value kind keeps today's behaviour with a model check warning, else say why not.
