# Negotiate new glossary terms between contexts and with the product

## Notes

A way to add new glossary terms and negotiate them between contexts, or between a context and the product, e.g. when the product asks for something it expects an external dependency to have, or something wholly new. b13 "An item proposes a new capability or a glossary term" covers a term within one context; this is the exchange across contexts. The person's words in quote-3.
Re-rated 2026-11-17 to high urgency (quote-49): the person's first product already has a downstream context that needs a new term from its upstream, so a product getting started meets this at once. Shape before the next release, with b13 (a term within one context) and the new item for a context asking another for its context.

## Requirements

### context-requests

#### [g51] A term proposal suggested is kept on its context request
- [r51] When the person suggests a term proposal for a context request, the context requests service shall keep the term proposal in the context request and keep an entry on the context request.

#### [g52] A term proposal out of the vocabulary-entry form or out of turn is refused
- [r52] If the person suggests a term proposal that does not conform to the vocabulary-entry form, then the context requests service shall refuse the request and name the term proposal.
- [r53] While a context request is `awaiting-upstream`, if the person suggests a term proposal for the context request, then the context requests service shall refuse the request and name the context request.

#### [g53] An accepted term proposal brings its term into the item
- [r54] While a term proposal in a context request is `accepted`, when the person accepts the context request, the context requests service shall keep an item that holds every term that the term proposal concerns.

### tracking model

```model
object term proposal kind of request line
  relations: concerns → term (many)

object context request
  relations: holds → term proposal (many)

object vocabulary-entry form kind of artifact

service context requests
  operation suggest(context request, term proposal) by the person
    outcomes: done → the term proposal | refused: term proposal not in the vocabulary-entry form, context request not this side's turn
```

- **term proposal** (noun) → object term proposal. A request line that proposes a term, with the model elements the term names, for the upstream to take into its own vocabulary in its own words.
- **suggest** (verb, action) → operation context requests.suggest. Forms: suggests, suggested. Frame: <actor> suggests <term proposal>. Frame: <actor> suggests <term proposal> for <context request>.
- **the vocabulary-entry form** (proper noun) → object vocabulary-entry form. A bullet `- **<word>** (<part of speech>) → <model element>. <definition>`, with the model lines that declare the element when the upstream has none.
- **concern** (verb, state) → relation term proposal.concerns. A term proposal is about a term: the term it adds, or the term whose entry it changes. Forms: concerns, concerned. Frame: <term proposal> concerns <term>.
