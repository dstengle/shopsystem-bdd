# Short-term directives recorded, reviewed and promoted to backlog items

## Notes

from observation 2026-10-30-log-of-temporary-rules and the board design; see .shop/records/2026-11-05-backlog-inventory.md row 20
Decided in the 2026-11-16 triage (.shop/records/2026-11-16-backlog-triage.md), quote-38: the person: Claude Code's memory must not be used, and CLAUDE.md must not be cluttered with ephemera. A short-term directive the person gives a session is recorded in the repository (a command writes it, with its words and date), shown to each session while live, reviewed, and promoted to a backlog item, a decision or CLAUDE.md, or dropped. The first directive to hold: quote-42, the standing authorization to merge, release and make the calls when the person is away.
Design, settled here (quote-38: Claude Code's memory MUST NOT be used and CLAUDE.md is not for ephemera; quote-42 is the first directive to hold). The form: a directive is the file .shop/directives/<n>.md, named directive-<n>, kept in the conversation capability beside quotes; frontmatter id directive/<context>/directive-<n>, kind directive, status (live, promoted or dropped), date, quote (the quote-<n> holding the person's words), and once reviewed promoted_to (b<n>, a design-decision id or CLAUDE.md) or why (the reason it was dropped); its body is the person's words. The commands: work directive "<the person's words>" (matched as work quote matches them, with --session and --transcript) writes the quote and a live directive citing it in one commit; work directive --quote quote-<n> writes one from an existing quote (how quote-42 is seeded once this is built); work directives lists the live ones with id, date, age and words (--all every one); work show directive-<n> prints it with its quote. Shown to sessions: the SessionStart hook runs scripts/conversation_hook directives, the same as work directives --hook, which prints the live directives' words under one line telling the session to follow them and to pass them in every brief it gives an agent (a dispatched agent sees no SessionStart output), prints nothing with none, and never fails. Review: work promote directive-<n> --to <target> after the session has written the target (work idea for an item, work decision, or a CLAUDE.md line), refused when the directive is not live or the target does not exist, status promoted and the target recorded; work drop directive-<n> --why "<reason>" (refused when not live), status dropped. A live directive stays shown until it is reviewed; no expiry. Modules: a new scripts/directive.py (the form: render, parse, write, promote, drop) with its parsers in conversation_cli.py, scripts/conversation_hook's directives, hooks/hooks.json's SessionStart, model_forms.FORMS's directive row (work directive), CLAUDE.md's module map and a working rule (a short-term direction of the person is written with work directive; nothing is kept in Claude Code's memory). Scenario: features/conversation.feature's groups, handlers in tests/scenarios/conversation_handlers*.py: a repository with directives of each status, the command run, the files and the hook's output read. Left out: migrating the entries of the current Claude Code memory (each to a directive or a CLAUDE.md line, then memory emptied) is a follow-up step once delivered, not a line; skills' text naming work directive is a chore. No dependency.

## Requirements

### conversation

- **directive** (noun): a file under `.shop/directives/` that cites a quote of the person's words which every session follows until the directive is promoted or dropped. Kind of: file.
- **status** (attribute of directive): Values (adjective): `live`, `promoted`, `dropped`. Transitions: `live` → `promoted`: `work promote`; `live` → `dropped`: `work drop`.

| quote | of | directive | one |

#### [g9] `work directive` keeps the person's words as a live directive
- [r9] When a session runs `work directive`, `work` shall write a directive whose quote cites a message and commit the directive.

#### [g10] The SessionStart hook shows the live directives
- [r10] When the SessionStart hook runs `work directives` with the `--hook` option, `work` shall print the quote of every directive whose status is `live`.

#### [g11] `work promote` promotes a live directive to what it became
- [r11] When a session runs `work promote` with the `--to` option set to an item on a directive whose status is `live`, `work` shall set the status of the directive to `promoted` and commit the directive.
- [r12] When a session runs `work promote` with the `--to` option on a directive whose status is not `live`, `work` shall refuse the command and name the directive.
- [r13] When a session runs `work promote` with the `--to` option set to an item that does not exist on a directive, `work` shall refuse the command and name the item.

#### [g12] `work drop` drops a live directive with its reason
- [r14] When a session runs `work drop` with the `--why` option on a directive whose status is `live`, `work` shall set the status of the directive to `dropped` and commit the directive.
- [r15] When a session runs `work drop` with the `--why` option on a directive whose status is not `live`, `work` shall refuse the command and name the directive.
