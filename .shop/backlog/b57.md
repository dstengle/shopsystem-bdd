# work's push leaves a branch's upstream and task branches alone

## Notes

From .shop/batches/7/review-1.md (observation 2): shop_files' push runs git push -u on the branch checked out, so every committing work command rewrites branch.<b>.remote/merge, and one run inside a task worktree publishes the task branch batch-<n>-t<k> to origin. Push without -u when the branch already has an upstream, and decide whether a task branch is pushed at all.

Rated: value medium-value: every committing command rewrites the checked-out branch's `branch.<b>.remote` and `.merge`, which loses an upstream someone set by hand, and a command run in a task's worktree publishes the task branch. Urgency medium-urgency: it happens on every commit since b51. Size small: scripts/shop_files.py's push and two scenarios.

Decided: a task branch is never pushed, because nothing committing is run on it: a committing `work` command run on a task's branch (`batch-<n>-t<k>`, the branch checked out) is refused before it writes, naming the task, and changes nothing (U3); `work batch done` already refuses a task commit that touches `.shop/`, so such a commit was never wanted. A branch with an upstream is pushed to that upstream (`git push <remote> HEAD:<its branch.<b>.merge>`) without `-u`, leaving the config as it was; a branch with none is pushed with `-u` as now, so it gets one. The tracking scenario's repository has `main` tracking a branch of another name (e.g. `r1/trunk`): the item's commit reaches `trunk` and `branch.main.merge` is still `refs/heads/trunk` after the command.

## Requirements

### backlog

- **upstream branch** (kind): the branch of a remote that the branch checked out in a repository pushes to.
- **tracking** (condition of repository): a repository whose branch checked out has an upstream branch of another name.
- **tasked** (condition of repository): a repository whose branch checked out is the branch of a task.

#### [g21] `work idea` keeps the upstream branch of the branch checked out
- [r21] While a repository is tracking, when the person runs `work idea`, `work` shall write an item that is `idea`, commit the item and keep the upstream branch.

#### [g20] `work idea` refuses the branch of a task
- [r20] While a repository is tasked, if the person runs `work idea`, then `work` shall exit with an error naming the task and change nothing.
