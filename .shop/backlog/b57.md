# work's push leaves a branch's upstream and task branches alone

## Notes

From .shop/batches/7/review-1.md (observation 2): shop_files' push runs git push -u on the branch checked out, so every committing work command rewrites branch.<b>.remote/merge, and one run inside a task worktree publishes the task branch batch-<n>-t<k> to origin. Push without -u when the branch already has an upstream, and decide whether a task branch is pushed at all.

## Requirements

### backlog

- **upstream branch** (kind): the branch of a remote that the branch checked out in a repository pushes to.
- **tracking** (condition of repository): a repository whose branch checked out has an upstream branch of another name.
- **tasked** (condition of repository): a repository whose branch checked out is the branch of a task.

#### [g19] `work idea` keeps the upstream branch of the branch checked out
- [r19] While a repository is tracking, when the person runs `work idea`, `work` shall write an item that is `idea`, commit the item and keep the upstream branch.

#### [g20] `work idea` refuses the branch of a task
- [r20] While a repository is tasked, if the person runs `work idea`, then `work` shall exit with an error naming the task and change nothing.
