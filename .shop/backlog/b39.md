# Requests' output: reasons shown, unreadable comments once, one-line confirmations

## Notes

From the black-box test of b26 (.shop/records/2026-11-05-b26-github-blackbox.md): `work show <request>` prints a refused line's outcome but not its reason, which the record holds; `work sync` prints every unreadable comment again on every run, on delivered requests too; `work offer`, `propose`, `turn` and `reply` print nothing on success; `work request` requires `--from`, which can only be this context.
Shaped 2026-11-16 (triage .shop/records/2026-11-16-backlog-triage.md: requests on top of b26; no person's decision quoted for b39). Reproduced on main: `work show q14` prints line 19 as withdrawn but not its reason, which q14.md holds under ## Reasons (r104); `work request x --thread t` exits 2 with 'the following arguments are required: --from' (r111); request_sync.unreadable prints an unreadable comment and records nothing, so every sync prints it again (r105, r106); cmd_offer, cmd_propose and the reply and turn handlers return 0 with no print (r107-r110). Changes: request_view.parts prints each line's reason after its line (the term line reason, a row line reason of request line); request_sync records a comment that does not conform under the record's ## Comments (its URL, marked unreadable), applying none of it and setting no status or turn, and passes over a comment the record holds, so it prints once (r105 retires r77, the Implementation's 'never recorded' and watched.json's note reworded by the batch; request_watch may then drop watched.json, left to the implementer); request_cli and the reply/turn commands print '<request> <status> <turn>' as `work show`'s first line; `work request --from` optional, defaulting to this context (r62 kept). Scenarios: a request with a withdrawn line and its reason shown; an unconforming comment synced twice, printed and recorded the first time, not printed the second; each of offer, propose, reply and turn printing the request and its status; `work request` with no --from writing a request from this context. Left out: a delivered request's comments otherwise (r96 already sets nothing). Decisions: record the unreadable comment in the committed record, not in the git dir like the watch, so every clone passes over it; keep --from optional rather than remove it. No dependencies.

## Requirements

### requests

retired: [r77]

- **line reason** (noun): the upstream's reason for the line outcome of a request line, under a request's `## Reasons`. Kind of: text.

| line reason | of | request line | one |

#### [g104] `work show` on a request prints each line's reason
- [r104] While a request line proposed in a request has a line reason, when the person runs `work show` on the request, `work` shall print the line reason.

#### [g105] `work sync` records a comment that does not conform to the comment form, and applies nothing of it
- [r105] While a comment on a request does not conform to the comment form and the request does not hold the comment, when a session runs `work sync`, `work` shall print the comment, write the comment and keep the status of the request.

#### [g106] `work sync` prints a comment that does not conform to the comment form once
- [r106] While a comment on a request does not conform to the comment form and the request holds the comment, when a session runs `work sync`, `work` shall not print the comment.

#### [g107] `work offer` says what it did
- [r107] When the person runs `work offer` on a request, `work` shall print the request and the status of the request.

#### [g108] `work propose` says what it did
- [r108] When the person runs `work propose` on a request, `work` shall print the request and the status of the request.

#### [g109] `work reply` says what it did
- [r109] When the person runs `work reply` on a request, `work` shall print the request and the status of the request.

#### [g110] `work turn` says what it did
- [r110] When the person runs `work turn` on a request, `work` shall print the request and the status of the request.

#### [g111] `work request` raises a request as this bounded context by default
- [r111] When the person runs `work request` without the `--from` option, `work` shall write a request that originates from this bounded context.
