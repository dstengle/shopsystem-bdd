# An adapter spec's id names its own folder, and a provider's version is matched as a version, never a pattern

## Notes

From batch-93 review 1's observations on scripts/model_adapter.py: the <name> of <parent>/adapter/<name> is not checked against the folder holding the spec, and a providers: version is used as a glob pattern (1.* passes when only 1.1.0 is kept).
From batch-93 review 1 on b540's adapter spec check: an id whose /adapter/<name> is not the folder adapters/<name>/ that keeps the spec passes, and a providers: version used as a pattern (1.* passes when 1.1.0 is kept). Two checking lines whose scenarios fail before the fix. Rated medium value (the adapter spec check is trusted by the contracts work), low urgency, small.

## Requirements

### checking

#### [g88] An adapter spec whose id does not match its own name is refused
- [r88] While the id of an adapter spec does not match the adapter spec, if the person validates the adapter spec, then the specification service shall fail the check and name the id.

#### [g89] A provider's version that is not a version is refused
- [r89] While a provider of an adapter spec has a version that does not conform to the version form, if the person validates the adapter spec, then the specification service shall fail the check and name the version.

### specification model

```model
object id
  relations: matches → adapter spec (one)

object provider
  relations: has → version (one)
```

- **match** (verb, state) → relation id.matches. The id of an adapter spec ends with `/adapter/<name>`, the name of the folder `adapters/<name>/` that keeps the adapter spec. Forms: matches, matched. Frame: <id> matches <adapter spec>.
