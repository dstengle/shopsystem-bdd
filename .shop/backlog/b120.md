# model logic reports an error when one pair makes the whole check unsatisfiable, instead of printing no findings

## Notes

Found by b119's encoding study (2026-11-09, scratchpad b112/scale/encoding/report.md, 'Side finding'): grammar/check.lp's hard named-code constraints (l.69, l.71) make the whole program unsatisfiable when one pair's shared code cannot be unified; the brave solve then returns nothing and reports finished, so model logic prints no findings and no L0. 14 of 40 fuzz seeds; on seed 25 dropping the two constraints gives 22 atoms instead of 0. The file's own rule is that one pair never makes the program unsatisfiable: a soft version (the pair marked out) keeps the others' findings; at least an unsatisfiable solve must be reported as an error.
