# work's push never hangs on a slow or prompting remote

## Notes

From .shop/batches/7/review-1.md (observation 1): shop_files' push (scripts/shop_files.py, push_failure) passes no timeout and no GIT_SSH_COMMAND with -o BatchMode=yes, so an SSH remote asking for a passphrase or host key, or a remote that does not answer, hangs every committing work command, and a batch command while it holds the batch lock. Add BatchMode=yes and a timeout; a push that times out is reported like a refused one.

## Requirements

### backlog

- **silent** (condition of remote): a remote that does not answer a push.
