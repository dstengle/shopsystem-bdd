# An artifact registry: each artifact's schema type, file, conforming kinds and fields declared once, checked, its fields read in as attributes and relations, conforming and non-conforming instances generated for scenarios, model forms as its view of the plugin's own files

## Notes

b112 brainstorming, 2026-11-10: the person agreed to delay the registry to 4.1 (after b240) if b240 does the cheap part now: an (artifact) part of speech with an optional Schema: field, stored, and a Field of: marker on hand-made attributes and relations that belong to an artifact. The registry then reads those entries: model check verifies each schema exists and parses and each conforming kind is declared; the grammar reads an artifact's fields in as attributes and relations (replacing the marked hand-made ones); scenarios get conforming and non-conforming instances generated from the schema (e.g. hypothesis-jsonschema); model forms becomes the registry's view of the plugin's own file forms; packs may ship artifacts (an OpenAPI document in the HTTP pack). Ship it as warnings first (an artifact with no schema declared), so it is a minor release, not 5.0. No requirement line changes: lines name artifacts and conform to them as b240 writes them.
