# model logic translates a no K whose restriction says another referent is not a value

## Notes

Met readying b158 (2026-11-10): batches#r20 (b158) says "While an item is `ready` and the item passes the readiness bar and the item has no dependency on an item whose status is not `delivered`, ...". `model parse --form` reads it right: a `not` box over [dependency, item] holding `on`, `of` and a `not` box over the inner item's `status = delivered`. `model logic` stops on it with "no translation of no there": spec_lf_facts' `none` takes only attribute and relation atoms of the box's own referents, not a nested `not` box (a negated attribute of one of its referents). Wanted: such a box read as "no K related so to a K whose T is not v", e.g. `rnone` over the pair with the inner referent's negated value, so a line on an item with no undelivered dependency reads in the check. b158's r33 had the same shape ("the batch has no task whose status is not `done`") and was reworded to "every task of the batch is `done`"; r20 has no such rewording, since the row `dependency | on | item` runs from the dependency, not from the item an `every` would range over.
