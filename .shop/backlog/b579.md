# A counted or only response act of an operation verb is keyed as a request

## Notes

batch-85 review 1 (observation): since b571 Walk.act keys a response act of an operation verb with no parameters req(O,()), but Walk.count and Walk.only in scripts/spec_lf_facts.py still write the plain event, so 'shall publish at least two design-decisions' or 'shall publish only design-decisions whose ...' beside 'shall not publish the design-decision' on one trigger gives no L1 (it did before b571). Key count and only acts of an operation verb as req(e,()) with the rqo fact, as act does.
From batch-85 review 1's observation (in the item's notes): b571 keys a plain response act of an operation verb as req(O,()), but count and only acts still emit the plain event, so their clash with a request of that operation is lost.

## Requirements

### consistency

#### [g41] spec logic finds the clash of a counted request of an operation and a forbidden request of it
- [r41] While a requirement has a trigger and the requirement obliges an act and the requirement uses `count` and an operation and another requirement that has the trigger forbids the act, when the person examines this specification, the specification service shall return `L1`.

#### [g42] spec logic finds the clash of only over requests of an operation and an obliged request of it outside the restriction
- [r42] While a requirement has a trigger and the requirement obliges an act and another requirement that has the trigger does not allow the act and the requirement uses `only` and an operation, when the person examines this specification, the specification service shall return `L1`.
