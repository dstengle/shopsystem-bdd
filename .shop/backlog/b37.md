# A refused request line names its reason again

## Notes

From batch-1 review 1 (Minor observation): retiring intake r3 with b26 dropped the rule that work outcome refused needs --reason, so an asker can get a refusal with no why. A line restores it.
Shaping (2026-11-06): two lines in place of the retired intake r3 (which it does not reuse: a retired id is never used again): r8, a refusal writes the reason under `## Reasons` and commits the request; r9, `work outcome refused` with no `--reason` is refused naming `--reason`. A rewritten line keeps its generated reason (`rewritten as line <m>`) and needs none.

## Requirements

### intake

#### [g8] `work outcome refused` writes the reason
- [r8] When a session runs `work outcome refused` on a request line proposed in a request, `work` shall set the line outcome of the request line to `refused`, write a reason and commit the request.

#### [g9] `work outcome refused` refuses a refusal with no reason
- [r9] While the argument `--reason` is absent, if a session runs `work outcome refused` on a request line, then `work` shall exit with an error naming the argument `--reason`.
