# work batch review merges task branches that conflict in task order, each into the next, and refuses only a real conflict

## Notes

work batch review (batch_merge.merge) merges each in-batch item's branch into batch-<n> in plan order and refuses any conflict but the unbuilt: line with git's first CONFLICT line and the branch only, so batch-51's conflicts were settled by hand on a later branch (b387 merged b354; b391 merged b387). The submit request is to merge the task branches in task order, each after the ones before (git's rerere reusing a settled resolution, else a three-way merge), and refuse only a conflict that remains, naming the file and both items. A conflict is stated as a state relation of kept changes; submit declares the refusal reason. From the missing-command research, the person's words in quote-68.

## Requirements

### execution model

```model
object kept change
  relations: conflicts with → kept change (many)

service batches
  operation submit(batch)  outcomes: done → the proposed change | refused: task not done, kept change citing no item, file conflicting
```

- **conflict** (verb, state) → relation kept change.conflicts with. A task's kept change alters a part of a file that a kept change of an earlier task in the batch alters otherwise, so that merging the task branches in task order, each after the ones before, with git's recorded resolutions, leaves the part unsettled; the `unbuilt:` line of a capability never conflicts. Forms: conflicts, conflicted. Frame: <kept change> conflicts with <kept change>.
