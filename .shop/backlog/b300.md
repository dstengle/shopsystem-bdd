# An order after 'every K' of any act, not only print

## Notes

From the feed product's session on 0.35.0 (feedback relayed by the person, 2026-11-16), item 5: 'return every video from the channel, ordered by ...' is refused; order-by-every exists only after print.
Found shaping b298 (2026-11-16): the cause is likely a frame whose object names a kind other than `thing`, not the act. With `Frame: agent returns file to agent`, "`work` shall return every file, ordered by version, in ascending order to the person" gives `does not parse at ordered (token 13 of 23)`; grammar 4 seems to make `<T>_<K>_Every` only for a `thing` slot. b298 fixes the same cause for `order-by`'s scenario (spec_lf_ordered.said).
Merged in from b312 in the 2026-11-16 triage: order-by-every after a verb whose frame names the collection's kind gets no scenario ('no step of an order of worktree there'): the steps half of the same fault.
Shaped 2026-11-16 (triage: shape; b312 merged in). Reproduced on a copy of grammar/corpus/constructs/spec (its give: 'Frame: agent gives file to agent'): model --root <copy> parse --form 'When the person runs `work start`, `work` shall give every file, ordered by version, in ascending order to the person.' prints 'does not parse at ordered (token 13 of 23)', may follow: file; the same line without the order parses (every [x4: file] scope give(...)). Cause: spec_rgl_np.orders makes <T>_<K>_Every only as k_thing_Arg, so no frame naming the collection's kind takes it; and spec_lf_ordered.every passes that fixed k_thing_Arg tree to said, which looks for the collection only in a thing slot (b312's TraceError 'no step of an order of worktree there'). Fix: orders makes <T>_<K>_Every an argument of K's own slot (coerced up the kind tree by the _Up_ funs as order-by's then does since b298), and every builds its argument per slot as then does (a callable arg to said); the implementer checks that 'every worktree, ordered by version' does not now read two ways beside r<n>_in_By_<T> (worktree's own version vs its files'), the reason orders gave for thing only, and that the construct catalogue's order-by-every example still reads to one tree. Modules: scripts/spec_rgl_np.py (orders), scripts/spec_lf_ordered.py (every), grammar/constructs.md regenerated if the functions' signature shows. Scenarios: design-model-check r316 runs model parse on the catalogue's order-by-every example with a verb whose only frame names the collection's kind (as give does) and checks the exit; feature-file-tools r129 runs features generate on such a group and checks its order counter-example as r124 and r127 do. Left out: the comma before what follows the order (b301): it is a separate change to the order's linearisation and already shows on order-by, so it stays its own item, made dependent on b300 so that its scenario of order-by-every can parse. Depends on nothing.
Rated: high value and high urgency as the triage gave (feed's latest-videos line, 'return every video from the channel, ordered by ...', has no parse nor scenario without it); medium size kept: a grammar signature change with its ambiguity check plus the steps' per-slot argument, two scenarios.
