# The grammar's definition is the source of truth: construct-by-construct and rule-by-rule lines replaced by the catalogues as specification artifacts

## Notes

The person (2026-11-19): many lines in reading.md are derivable from the grammar definition; they record how the grammar came to behave a certain way, which is not definition, as an object's attributes are not each stated as a requirement. Today the same fact is stated four times: the GF sources and generated Context, grammar/constructs.md (generated, examples parsed), grammar/language.md (R1-R12 with tested lines) with the corpus, and reading.md's 61 lines (e.g. r14 'parses a requirement that uses no-noun ... shall complete the request'). checking.md has 47 lines, 22 naming a rule code that grammar/rules.md already catalogues with fail/pass examples. Direction to settle with the person: keep only the language and checking services' general behaviour as requirements (one meaning or a refusal naming why, the terms that may follow, the logical form returned, a construct or rule the catalogue does not define refused); make the construct and rule catalogues part of the specification, each entry's example its test.
