# migrate init leaves an existing .gitignore alone when it holds every line, and matches lines as git does

## Notes

migrate init (scripts/migrate_init.py, ignore_text and run) always puts .gitignore among the files it commits and prints 'wrote .gitignore', even when the repository's own .gitignore already names every ignored name; and it matches a name only by the exact line, so a .gitignore holding '.venv' gets a second '.venv/' added. The fix: compare names as git matches them (a trailing '/' and a leading '/' do not make another entry), and leave .gitignore out of the commit and the output when nothing is missing. r38 retired: its keep of the ignore file holds only when the ignore file does not already conform. The person's words in quote-68.
