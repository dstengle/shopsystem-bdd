# A model element or a term moves to another area on an item

## Notes

requirement id, universal condition id, given block, upstream entry, requirement grammar (tracking), index file, Behaviour line (upgrades) belong to specification; review limit to execution; moved with no line changed. Part of the disentangling of this repository into hosted contexts (decisions 0129-0133).
Tooling first (decisions 0129-0133): work cannot move a model element between areas (an item's model block only adds or merges into its own area's file, --remove-model takes out only the item's own lines, and an element declared in two files is v_m8), nor a vocabulary entry between layers. This item adds work line <b> --into <capability> --move-model '<element header>' (the element with its members out of the model file that declares it, into the area of the capability; its vocabulary entries with it) and --move-term '<word> → <element>' (the entry out of its layer, shared.md among them, into the layer of the area that declares its element); the lay of each move adds to the model file of each area whose lines use a moved word the import of its new area, so that v_m1 stays clean, and the unlay puts it back as git held it. The moves themselves are the item that depends on this one.

## Requirements

### drafting

#### [g66] A model line moved in an item is kept
- [r66] When the person moves a model line in an item, the drafting service shall keep the model line in the item.

#### [g67] Moving a model line that the domain model does not hold is refused
- [r67] If the person moves a model line that the domain model does not hold in an item, then the drafting service shall refuse the request and name the model line.

#### [g68] A term moved in an item is kept
- [r68] When the person moves a term in an item, the drafting service shall keep the term in the item.

#### [g69] Moving a term that no area holds is refused
- [r69] If the person moves a term that no area holds in an item, then the drafting service shall refuse the request and name the term.

### batches

#### [g113] A batch opened declares a moved model line in the area it moves to
- [r113] While an item is `ready` and the item meets the readiness bar and the item holds a model line that moves to an area, when the person opens a batch, the batches service shall keep the area that holds the model line.

#### [g114] A batch opened takes a moved model line out of the area it moves from
- [r114] While an item is `ready` and the item meets the readiness bar and the item holds a model line that moves from an area, when the person opens a batch, the batches service shall keep the area that does not hold the model line.

### tracking model

```model
service drafting
  operation move(model line, item)  outcomes: done | refused: model line not in the domain model
  operation move term(term, item)  outcomes: done | refused: term not in the vocabulary

object model line
  relations: moves to → area (one); moves from → area (one)

object item
  relations: moves → term (many)
```

- **move** (verb, action) → operation drafting.move. Forms: moves, moved. Frame: <actor> moves <model line> in <item>.
- **move** (verb, action) → operation drafting.move term. Forms: moves, moved. Frame: <actor> moves <term> in <item>.
- **move** (verb, state) → relation model line.moves to. A model line names an element the domain model declares in another area, which the item's batch takes out of that area's model file and declares, with the entries that mean it, in this area's. Forms: moves, moved. Frame: <model line> moves to <area>.
- **move** (verb, state) → relation item.moves. An item names a term whose entry its batch takes out of its layer and writes into the layer of the area that holds the element the term means. Forms: moves, moved. Frame: <item> moves <term>.
- **move** (verb, state) → relation model line.moves from. A model line names an element that another area's model file declares, which the item's batch takes out of that file. Forms: moves, moved. Frame: <model line> moves from <area>.
