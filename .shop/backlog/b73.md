# measure batch counts the time of the test runs of work batch done and review

## Notes

From the batch-9 analysis (.shop/records/2026-11-06-shopsystem-bdd-batch-9-analysis.md), asked by the person 2026-11-06: is the test suite a measurable share of a batch's time? measure batch sums the agents' session time and tokens but not how long the test runs of work batch done and review took, so it can't say. Estimated outside the measurement at about 189 s (7 runs of about 27 s) of 4127 s session time. Wanted: measure batch counts each done and review test run's duration, so a test-speed item rests on a measured figure.

## Requirements

### measurement

retired: [r1]
retires: [r12 r1]

#### [g12] A merged batch measured keeps its time, tokens, cost, test runs and opening time
- [r12] While a batch is `merged`, when the person measures the batch, the measurement service shall keep a measurement of the batch and return the wall time of the batch, the session time of the batch, the tokens of the batch, the cost of every role of the batch, the duration of every test run of the measurement and the opening time of the measurement.

### measurement model

```model
object test run
  relations: has → duration (many)

object opening time

object duration

object measurement
  relations: has → test run | opening time (many)
```

- **test run** (noun) → object test run. One run of the tests of a batch when `work` finishes a task of the batch or submits the batch.
- **duration** (noun) → object duration. The time a thing took from its start to its end.
- **opening time** (noun) → object opening time. The time `work` takes to open a batch: its readiness check of the items again, its lay of their lines and its run of their scenarios.
