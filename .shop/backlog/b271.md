# Retire a live requirement with no line replacing it

## Notes

Today work line --retires <cap>#r<n> "<line>" (b128) retires a live requirement only by giving it a replacement line. An item should also be able to retire a requirement outright: its id written under the capability block's retired:, the line (and its group when it was the last) taken out of Behaviour when laid, put back when unlaid, its scenario removed by features generate, no new id. Distinct from b14, which changes an item's own lines before they are built.
Shaped 2026-11-16 after the triage (.shop/records/2026-11-16-backlog-triage.md, Shape: b14 and b271, rewording or dropping lines); no quote of the person is given for b271. Reproduced on a throwaway clone: work line b271 --retires readiness#r4 with no line prints 'work: work line: give one of a requirement line, --term, --relation, --given, --universal, --upstream or --recodify' and exits 1. The new option --no-line goes with --retires: a positional line is no option, so grammar 4 cannot tell a run with a line from one without it, and r34 (--retires alone) says a requirement is written; --no-line gives the trigger its own option set. Modules: backlog_cli (the --no-line flag, refused with a line or without --retires), backlog_lines.retire (no add_line_to when there is no line), backlog_retires unchanged (check, with_retired, lay and unlay already take the line out of Behaviour and its group when last, and put it back), readiness_bar (an item whose only piece is a retired id is not 'no requirement line'; its Implementation bullet changes), readiness_handlers_line (the When with --no-line), readiness.md's Implementation. Scenario r42: work line with --no-line --retires <a live id> on an item: the id under the item block's retired:, no - [r<n>] bullet, one commit; r43: an id no requirement has refused and named. Left out: removing an item's own line (b14); a batches line that the laid spec drops the retired scenario (features generate regenerates the feature from spec/, as for b128's retirements). Rating kept from the triage: medium value, medium urgency, small.

#### [g42] `work line --retires --no-line` retires a requirement in an item with no line replacing it
- [r42] When the person runs `work line` with the `--no-line` option and the `--retires` option set to a requirement id on an item, `work` shall write the requirement id in the item, not write a requirement in the item and commit the item.

#### [g43] `work line --retires --no-line` refuses a requirement id that no requirement has
- [r43] If the person runs `work line` with the `--no-line` option and the `--retires` option set to a requirement id that no requirement has, then `work` shall refuse the command and name the requirement id.
