# migrate upgrade records the plugin's version when no step is pending

## Notes

From the feed product's session on 0.35.0 (feedback relayed by the person, 2026-11-16), item 8: it prints 'no upgrade step is pending' and leaves .shop/plugin-version at 0.34.1; model forms says only migrate upgrade writes the file, so 0.35.0 cannot be recorded and the SessionStart hook keeps offering the upgrade.
Shaped 2026-11-16 (triage wave). Reproduced: a scratch repository whose .shop/plugin-version holds 0.34.1, run with this plugin (0.35.1): migrate upgrade printed 'no upgrade step is pending', exited 0 and left the file at 0.34.1; migrate status printed both versions and no step. Fix in scripts/migrate_upgrade.py: upgrade() with no pending step and a repository version below the plugin's writes the plugin's version to .shop/plugin-version, commits it (message 'migrate upgrade: <from> to <to>') and pushes like an upgrade with steps; with the versions equal it still changes nothing. The scenario of r84: a repository on 0.34.0 and migrate on 0.34.1 (migration_tools_handlers' release of migrate, as r81's scenario sets it), so no step is pending; Then the print, the plugin version file rewritten (to 0.34.1) and committed. r84 names the releases, as r80 does, because the general wording does not go through today: 'the release of every upgrade step is not after the release of this repository' crashes the check (AttributeError in spec_lf_values.members, b310's fault), 'is before' is refused ('no translation of every there': every over one thing's value compared with another's), 'no upgrade step whose release is after ...' does not parse, and an adjective defined by a sentence ('pending (adjective of upgrade step)') is not in grammar 4 at all ('an initiative is open' does not parse either). Worth rewording to the general line once b310 and every over a two-thing comparison are translated. r81 is kept, not retired as the triage expected: its precondition (the same release) is disjoint from r84's (before), and it stays true. Left out: migrate status --hook already prints nothing when no step is pending, so no hook line. No dependencies.

## Requirements

### migration-tools

#### [g84] `migrate upgrade` on a repository behind the plugin's release with no upgrade step pending records the plugin's release
- [r84] While the release of this repository is `0.34.0` and the release of `migrate` is `0.34.1`, when the person runs `migrate upgrade`, `migrate` shall print `no upgrade step is pending`, rewrite the plugin version file of this repository and commit the plugin version file.
