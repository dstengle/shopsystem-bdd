# spec publish refuses a version that is not a version, by a line and a declared reason

## Notes

batch-90 review 1 observation: contract_publish refuses a malformed --version (it guards the path .shop/contracts/<version>/) with no line of checking and no reason declared on specification.publish; give it a line and add the reason to the operation's refused: list.
batch-90 review 1 observation: contract_publish refuses a --version that is not a token it can name a folder by (VERSION, guarding .shop/contracts/<version>/) with no line of checking and no reason declared on specification.publish. The artifact 'the version form' is that token; the declared reason is 'version not in the version form', the reason contract_publish gives to be renamed to it (it says 'version not a version' today).

## Requirements

### checking

#### [g81] A contract at a version that is not a version is refused
- [r81] If the person publishes a contract with a version that does not conform to the version form, then the specification service shall refuse the request and name the version.

### specification model

```model
object version form kind of artifact

service specification
  operation publish(contract, version) by the person
    outcomes: done → the contract | refused: version already published, version not in the version form, requirement not in the language
```

- **the version form** (proper noun) → object version form. The version of a contract as `spec publish` takes it: a letter or a digit, then letters, digits, dots, pluses and hyphens, as `1.2.0`, so that it names one folder under `.shop/contracts/`.
