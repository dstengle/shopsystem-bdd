# A contract is not obtained from a bounded context that fails to answer, and the reason says so

## Notes

batch-94 review 1 observation: contract_obtain._api turns any non-404 gh failure (403 rate limit, 5xx) into 'bounded context unreachable' although _reach already reached the repository; r89 asks for that reason only when the availability is unreachable.
batch-94 review 1 observation: spec obtain gives a bounded context it reached, whose answer to a read of its contracts then fails (a refusal or a failure of its host other than no such contract), the reason bounded context unreachable, which checking#r89 keeps for a bounded context it cannot reach. A third availability, failing, and its own reason tell them apart.

## Requirements

### specification model

```model
object bounded context
  attributes: availability: available | unreachable | failing

service specification
  operation obtain(contract, bounded context, version) by the person
    outcomes: done → the contract | refused: bounded context with no contract, id not in the context id form, bounded context unreachable, bounded context failing
```

- **failing** (adjective) → value bounded context.availability failing. A bounded context the specification service reaches whose answer to a read of its contracts is a refusal or a failure other than no such contract.
