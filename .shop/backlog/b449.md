# The tests command runs the context's .venv interpreter

## Notes

From the missing-commands and new-user-flow research of 2026-11-21: `TESTS = "python3 -m pytest …"` (`batch_tasks.py:39`), and the line `migrate init` writes, ignore the `.venv` the docs install pytest into. `python3 -s -m pytest` prints "No module named pytest", so `work batch done` and `review` fail on a clean machine. Use `.venv/bin/python` when `.venv` exists, and have `migrate init` write it. The person's words in quote-68.

## Requirements

### batches

#### [g77] A task finishes with its tests run by the workspace's virtual environment
- [r77] While a task of an item is `running` and the workspace of the task holds a virtual environment and a scenario of the item succeeds in the workspace of the task, when a session finishes the task, the batches service shall set the status of the task to `done`.

### reviews

#### [g6] A batch is submitted with its tests run by the batch's virtual environment
- [r6] While a batch is `building` and every task of the batch is `done` and the workspace of the batch holds a virtual environment, when the person submits the batch, the batches service shall keep a proposed change of the batch and set the status of the batch to `in-review`.

### execution model

```model
object virtual environment kind of file
```

- **virtual environment** (noun) → object virtual environment. The directory `.venv` at the top of a workspace, whose `bin/python` runs the tests of a task and of a batch in place of the `python3` on `PATH`.
