# Posting a step does not depend on reading the issue first, nor take the other side's comment as its own

## Notes

From batch-9 review 4 (observation on b36's f6 fix): scripts/request_post.py committed now calls unrecorded (gh issue view) before every comment, so a failed view refuses a step that could have been posted; and any comment the record does not hold whose stripped body matches is taken as this step's earlier post, including an unsynced comment from the other side (today the sides' bodies differ, so no client hits it). Consider tolerating a failed view and matching only this side's own posts.
Shaped 2026-11-21: the line says a turn passed is posted though the channel does not provide the thread (the store's read fails); matching only this side's own posts in unrecorded is code under that line, mechanism kept out per directive-7.

## Requirements

### context-requests

#### [g51] A turn passed is posted though the channel does not provide its thread
- [r51] While a context request is `awaiting-asker` and a channel does not provide the thread of the context request, when the person passes the turn of the context request, the context requests service shall set the status of the context request to `awaiting-upstream`, set the side of the context request to `upstream` and keep an entry on the context request.

### tracking model

```model
object channel
  relations: provides → thread (many)
```

- **provide** (verb, state) → relation channel.provides. A channel gives a thread with its entries to the one that reads the thread. Forms: provides, provided. Frame: <channel> provides <thread>.
