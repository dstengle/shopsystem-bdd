#### [g23] `features count --by-tag` counts no scenario line of a docstring
- [r23] While a feature file has a docstring that contains a tag and a scenario line, when the person runs `features count --by-tag`, `features` shall print the scenario count of the feature file and not count the scenario line.

```given
the feature file `features/notes.feature` holds:
  Feature: Notes
    Scenario: Nested
      Given a note
        """
        @slice-9
        Scenario: Phantom
        """
```

#### [g24] `features count --by-tag` counts each examples row of a scenario outline as a scenario
- [r24] While a feature file has a scenario outline, when the person runs `features count --by-tag`, `features` shall count every examples row of the scenario outline as a scenario and print the scenario count of the feature file.

#### [g25] a tag in a docstring is no tag of its feature file
- [r25] While a feature file has a docstring that contains a tag, when the person runs `features list --tag` on the tag, `features` shall exit successfully and not print the feature file.

```given
the feature file `features/notes.feature` holds:
  Feature: Notes
    Scenario: Nested
      Given a note
        """
        @slice-9
        Scenario: Phantom
        """
```

#### [g26] every feature file in a subdirectory is read, however deep
- [r26] While a feature file in a subdirectory has a scenario, when the person runs `features list --title` on the scenario title of the scenario, `features` shall print the feature file.

```given
the feature file `features/sub/deep.feature` holds:
  Feature: Deep
    Scenario: Deep down
      Given a step
```

#### [g27] `features list --tag` prints every scenario of a feature file that has the tag
- [r27] While a feature file has a tag, when the person runs `features list --tag` on the tag, `features` shall print every scenario of the feature file and the feature file.

```given
the feature file `features/cart.feature` holds:
  @cart
  Feature: Cart
    Scenario: Adding
      Given a step
```

#### [g28] `features list --title` prints each scenario whose title contains the search text
- [r28] When the person runs `features list --title` on a search text, `features` shall print every scenario whose scenario title contains the search text.

```given
the feature file `features/cart.feature` holds:
  Feature: Cart
    Scenario: Adding
      Given a step
    Scenario: Paying
      Given a step
```

#### [g29] a feature file with a rule block is refused
- [r29] While a feature file has a rule block, if the person runs `features count --by-tag`, then `features` shall refuse the command and name the feature file.

```given
the feature file `features/rule.feature` holds:
  Feature: Rules
    Rule: one rule
      Scenario: Under a rule
        Given a step
```

#### [g30] `features deprecated` prints each deprecated scenario with the tags of its replacement
- [r30] While a replacement of a scenario has a tag and the scenario has the `@deprecated` tag, when the person runs `features deprecated`, `features` shall print the scenario and every tag of the replacement.

```given
the feature file `features/shelf.feature` holds:
  Feature: Shelf
    @deprecated
    Scenario: Lending (deprecated)
      Deprecated for: Lending a book
      Given a step
    @r4
    Scenario: Lending a book
      Given a step
```

#### [g31] `features deprecated` says when nothing is deprecated
- [r31] While no scenario has the `@deprecated` tag, when the person runs `features deprecated`, `features` shall print the none-deprecated note.

```given
the feature file `features/shelf.feature` holds:
  Feature: Shelf
    Scenario: Lending
      Given a step
```

#### [g32] `features deprecated --json` prints the deprecated scenarios as one JSON object
- [r32] While a scenario has the `@deprecated` tag, when the person runs `features deprecated --json`, `features` shall print the scenario title of the scenario.
