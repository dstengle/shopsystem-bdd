### feature-file-tools

language: codified-2

- **docstring** (noun): the text of a step between two lines of `"""` or of three backticks, in a feature file. Kind of: text.
- **tag** (noun): a Gherkin tag of a scenario or of a feature file, as `@deprecated`. Kind of: text.
- **scenario line** (noun): a line that starts `Scenario:`. Kind of: text.
- **scenario outline** (noun): a Scenario Outline of a feature file, with its Examples tables. Kind of: text.
- **examples row** (noun): one row of values of an Examples table of a scenario outline. Kind of: text.
- **rule block** (noun): a `Rule:` block of a feature file. Kind of: text.
- **scenario count** (noun): the number of scenarios `features count` prints for a feature file. Kind of: text.
- **scenario title** (noun): the text after `Scenario:` that names a scenario, or the title a binding names. Kind of: text.
- **search text** (noun): the text `features list --title` is given, which a scenario title it prints contains. Kind of: text.
- **count** (verb, action): a tool takes a thing as one of the scenarios it counts. Forms: counts, counted. Frame: tool counts thing. Frame: tool counts thing as scenario.
- **subdirectory** (noun): a directory under the directory `--dir` names, at any depth. Kind of: file.
- **contain** (verb, state): a text holds another text within it. Forms: contains, contained. Frame: text contains text.
- **replacement** (noun): the scenario that a deprecated scenario names after `Deprecated for:`. Kind of: scenario.
- **the none-deprecated note** (proper noun): "none deprecated", what `features deprecated` prints when no scenario is deprecated. Kind of: text.
- **the all-bound note** (proper noun): "every binding names a scenario", what `features bindings` prints when every binding names a scenario. Kind of: text.
- **binding** (noun): a `scenario(...)` or `scenarios(...)` call of a test module. Kind of: text.
- **scenarios call** (noun): a `scenarios(<path>, ...)` call of a test module, which binds every scenario of the feature files its path names. Kind of: binding.
- **bind** (verb, state): a binding names the title of a scenario, or a scenarios call names the feature file of the scenario, so that a test runs the scenario. Forms: binds, bound. Frame: binding binds scenario.
- **name** (verb, state): a text holds the path, the title or the id of a thing. Forms: names, named. Frame: text names thing.
- **differ** (verb, state): a feature is not the file `features generate` writes from its capability. Forms: differs, differed. Frame: feature differs from capability.
- **handler** (noun): a function of `tests/scenarios/` that a step runs. Kind of: thing.
- **negated response** (noun): the response of a requirement that says with `shall not` what does not happen. Kind of: text.
- **recipient** (noun): the noun phrase after `to` that a verb's frame gives a recipient. Kind of: text.
- **refusal** (noun): the response of a requirement that says that a tool shall refuse a command. Kind of: text.
- **then step** (noun): a Then line of a scenario. Kind of: step.
- **premise** (noun): a universal condition or a definition of a pack. Kind of: text.
- **entail** (verb, state): a premise gives a step from the other steps of its scenario. Forms: entails, entailed. Frame: premise entails step.
- **codified-2 marker** (noun): the line `language: codified-2` in the frontmatter of a capability. Kind of: text.
