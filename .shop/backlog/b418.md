# A line can say that a request names a title another checklist has (a value in use), not only an example value

## Notes

UX trial 2 (2026-11-20, 0.40.0): to refuse a duplicate title the session tried 'If the person creates a checklist with a title and a checklist whose title is the title exists, ...' and 'While a checklist has the title `t1`, ...', both refused; it settled on example data, 'While the title of a checklist is `groceries`, if the person creates a checklist with the title `groceries`, ...' (w_example). Uniqueness of a value is common in a first app; the language reference could give its form, or grammar 4 read the parameter's value compared with another thing's ('the title of another checklist is the same as the title').
Design 2026-11-20 settled with the person (session d0999860): a request parameter that names an attribute takes 'the T of <noun phrase>' as its value, the construct param-of, read as param(e, T, v) with T(x) = v, per design-decision 0110 (a request parameter's value is a referent of the logical form). spec logic reads two triggers as one request when their parameter values unify, so a code and another thing's value of that code meet. Its scenario gives the other thing a made-up value in a Given and the same value in the When's request, reading no collection (quote-61: no test that reads the store as a collection). Folded in: an operation whose object is only its done outcome introduces that object in the When, never by a Given; scenarios r14, r26, r27, r33, r34, r35 restated with 'no given step and no when step'. The person's words: quote-60 ('Build around the abstract general case'), quote-61, quote-62 (b426, a core driver, is separate). Left out: the second wording, a condition on the parameter (b427), and comparisons other than the same value.

## Requirements

### parsing

#### [g13] A request parameter's value that is another thing's value is parsed
- [r13] When the person parses a requirement that uses `param-of`, the language service shall complete the request.

### specification model

```model
object when step kind of step

object operation
  relations: makes → referent (many)

object referent
  relations: has → instance (one)

object value in use kind of text

object logical form
  relations: holds → value in use (many)
```

- **when step** (noun) → object when step. A step of a scenario that opens with `When`, or with `And` or `But` under one.
- **make** (verb, state) → relation operation.makes. An operation brings a thing into being: the thing is the object of its `done →` outcome and no parameter of the operation names it, as an operation that creates a checklist makes the checklist. Forms: makes, made. Frame: <operation> makes <referent>.
- **value in use** (noun) → object value in use. The value of a request's parameter that is another referent's value of the attribute the parameter names, as "with the title of another checklist", which a requirement that uses `param-of` says and its logical form keeps as `param(e, T, v)` beside `T(x) = v`.
