# A command corrects an item's recorded status, with the reason

## Notes

The person's answer of 2026-11-19 (b370's question): b240, b257 and b160, delivered by plans, were recorded withdrawn; no work command could correct them to delivered, so their files were edited by hand. A command that sets an item's status to the one it should have recorded, with a reason under ## Notes, would keep that a command's change.

2026-11-20: a second case: b413, b414 and b415 were fixed directly on main (169d8bbe2, 699212783, 2d5a26c8a) during UX trial 2, outside any batch, and stay idea with a note naming the commit, since no command records an item delivered by a commit on main. The command should take that case too: an item set delivered with the commit that delivered it.
