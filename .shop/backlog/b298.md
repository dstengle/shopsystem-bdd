# An order on a returned collection gets its scenario

## Notes

From the feed product's session on 0.35.0 (feedback relayed by the person, 2026-11-16), item 3: the fix of .shop/batches/35/defect-3.md. spec_steps4's order Then and world_order's handler for a collection a response returns (any act, not only print). Blocks feed's b2.
Shaped 2026-11-16 for the 0.35.1 fix batch (the person: "Go ahead.", approving b297, b298, b299 and b307 to unblock feed). Reproduced on a copy of the construct catalogue's context with a verb return: with 'Frame: agent returns thing to agent' features generate writes the order's scenario; with 'Frame: agent returns worktree to agent', '... shall return a worktree that holds every file, ordered by version, in descending order to the person' passes model logic and features generate says 'no scenario: no step of an order of worktree there'. So the fault is not the act but its frame: spec_lf_ordered.said looks for the collection said as a thing slot (r.arg(x, "thing")) in the act's Then, which only print's frame (tool prints thing) and other frames on thing give. Fix: said finds the collection's noun phrase in the act's Then by the slot its frame takes (the kind the frame names, found up the kind tree) and swaps the order's noun phrase into it there, the order's tree (r<n>_in_By_<T>) coerced to that slot's kind, not k_thing; features_vocab4 already reads the order of any Then (Call.order), and world_order's then is registered as a local of ThenDoes as well as ThenPrints, checking the command's output, so a feature whose act is not on stdout calls world_order.check with its own output. Modules: scripts/spec_lf_ordered.py (said, then), tests/scenarios/world_order.py and world_fallbacks.py. The scenario (feature_file_tools_uses or _capability, picked by its Givens) writes the catalogue's order-by example with a verb whose only frame names the collection's kind, runs features generate and checks the order counter-example as r123 does. Left out: order-by-every on such a verb, which does not even parse ('`work` shall return every file, ordered by version, in ascending order to the person' with 'Frame: agent returns file to agent': 'does not parse at ordered'), since the grammar generates <T>_<K>_Every only for a thing slot; that is a parse fault for its own item. Depends on nothing; b297 and b299 are the model logic halves of the same feed report.
Rated 2026-11-16: high value, because feed's b2 (latest videos, ordered) has no scenario without it; high urgency, because it is one of the 0.35.1 fixes that unblock feed now; small, because one function of spec_lf_ordered and the handler's registration change, with one scenario.
