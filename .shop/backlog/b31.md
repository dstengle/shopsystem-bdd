# A session watches its request issues and wakes on a new comment

## Notes

Fast follow of b26 (design, Non-goals): a session watching its request issues with Claude Code's Monitor tool and waking on a new comment, so a request moves without the person nudging both sides.
Brought to the top of the backlog 2026-11-06, the person's words in quote-4. Rated high-value (requests move only when the person nudges each side today), high-urgency (the person asked for it next), medium size (a Monitor-driven watch of each open request issue, waking the session with the new comment for work sync, and the skills that start it).

Shaped 2026-11-06. `work watch` polls GitHub (every `--every <seconds>`, default 60) for the issue of each request that is not closed and for the open issues of this context's own repository, and exits successfully after the first poll that finds a comment the request does not hold or an untaken ask, printing one line for each (the request, the issue's URL, the comment's number). It writes nothing: `work sync` records, and its lines say what the session does next. A comment it has printed, kept by its id in the git dir (as `conversation_prompt` keeps its state, never committed), is not printed again, so an unreadable comment, which sync never records, does not wake the session in a loop. A transient gh failure is printed on stderr and the poll tried again; it does not end the watch. Exiting on a find (not streaming forever) keeps it testable and lets the session start it with Bash `run_in_background` (or Monitor) and start it again after each `work sync`. The skills that run `work request`, `work sync` or wait on the other side (raising-a-request, taking-in-a-request) start the watch while any request waits on the other side, and say so. Not lined: the watch with nothing to find (it does not exit, so no scenario can run it).

## Requirements

### requests

- **untaken** (condition of issue): an open issue on the GitHub repository of this bounded context whose body is an ask that no request holds.

#### [g42] `work watch` wakes on a comment the request does not hold
- [r42] While a comment is unrecorded, when a session runs `work watch`, `work` shall print the comment and exit successfully, and `work` shall not write the comment.

#### [g43] `work watch` wakes on a new ask
- [r43] While an issue is untaken, when a session runs `work watch`, `work` shall print the issue and exit successfully.
