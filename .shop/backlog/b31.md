# A session watches its request issues and wakes on a new comment

## Notes

Fast follow of b26 (design, Non-goals): a session watching its request issues with Claude Code's Monitor tool and waking on a new comment, so a request moves without the person nudging both sides.
Brought to the top of the backlog 2026-11-06, the person's words in quote-4. Rated high-value (requests move only when the person nudges each side today), high-urgency (the person asked for it next), medium size (a Monitor-driven watch of each open request issue, waking the session with the new comment for work sync, and the skills that start it).

## Requirements

### requests

- **untaken** (condition of issue): an open issue on the GitHub repository of this bounded context whose body is an ask that no request holds.

#### [g42] `work watch` wakes on a comment the request does not hold
- [r42] While a comment is unrecorded, when a session runs `work watch`, `work` shall print the comment and exit successfully.

#### [g43] `work watch` wakes on a new ask
- [r43] While an issue is untaken, when a session runs `work watch`, `work` shall print the issue and exit successfully.

#### [g44] `work watch` writes no comment
- [r44] When a session runs `work watch`, `work` shall not write a comment.
