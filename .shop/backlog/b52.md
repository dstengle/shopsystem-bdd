# work quote finds a message the person sent mid-turn

## Notes

On 2026-11-06 the person sent "Add a backlog item for managing CLAUDE.md with tools" while the session was working; `work quote` with those exact words refused, even after the turn ended, so b50 "Manage CLAUDE.md with tools" has no quote. conversation_read likely drops the row a message sent mid-turn is kept in (a queued or notification row).

Shaped 2026-11-16. Reproduced: `conversation_read.messages` on the 2026-11-06 transcript (352ba8c2-....jsonl) gives 55 messages and `cited(..., "Add a backlog item for managing CLAUDE.md with tools")` gives None. The words are in that transcript only as a `queue-operation` row (enqueue, then remove with reason `absorbed_mid_turn`) and an `attachment` row of type `queued_command` (`commandMode: prompt`, `origin: {kind: human}`, its own uuid and timestamp); `messages` reads only `user` and `assistant` rows, so it never sees them. The same attachment type carries task notifications (`commandMode: task-notification`) and subagent hand-backs (`origin.kind: peer`), which are not the person's. The fix is in `scripts/conversation_read.py` (its docstring, `messages`): an `attachment` row whose attachment is a `queued_command` with `commandMode` `prompt` and origin kind `human`, not sidechain, read as a message of the person (its `prompt` text, the row's uuid and time), closing the session's turn as a prompt does; a peer's hand-back or a task notification left out. The scenario's world (tests/scenarios/conversation_handlers*.py) writes a transcript with a queued_command row holding the words, runs `work quote` with them and checks the quote cites that message; tests/scripts covers a peer hand-back and a task notification of the same shape left out. conversation.md's Implementation section names the queued message beside the prompts. Left out: the `queue-operation` rows (the attachment row is the one with an origin and a uuid). No dependencies. Rating kept: medium value (a quote the person's words rest on is otherwise lost), medium urgency, small size (one reader function and its scenario).
