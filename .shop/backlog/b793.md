# The product commands take one bounded-context id form

## Notes

New-user trial of 2026-11-26 (quote-103): migrate init and work context use bounded-context/example.org/...; spec context, assign and plays examples use unprefixed ids; both were accepted as two contexts in product.toml ([contexts."example.org/chores/chores-app"] and [contexts."bounded-context/example.org/chores/chores-app"]) with one job each, and spec check read both as this context.
The product commands take the bounded-context id in the one form migrate init and work context use, bounded-context/<domain>/<path> (the context id form); declaring a bounded context, assigning a job to one and mapping a product actor in one with an id of another form are refused naming the id, so one id never makes two contexts.
