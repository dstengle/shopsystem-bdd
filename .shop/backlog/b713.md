# The batch poll moves past look at failure once a fix lands

## Notes

batch-123: after the corpus fix was committed on the task's branch, work batch next still said 'look at failure' until work batch review ran again; it should read a commit since the failure as a fix to submit.
batch-123: after the corpus fix was committed on the task's branch, work batch next still said 'look at failure' until work batch review ran again. A term fix (a kept change on a task's branch of a building batch made after the batch's last submit that a scenario broke; model: object fix kind of kept change); batches r160: with a fix the poll says submit batch; r161 and r162 retire r149 (fix task) and r154 (look at failure), each now only while no fix exists. Technical call: a fix is told by the task branches' commits newer than the failed submit's recorded head (batch_rerun keeps the failed run per task in the git dir; the submit's head is kept beside it), not by a commit message. Worlds that fail first: r160's is batches_world's batch building with every task done, a submit that broke a scenario recorded, then a commit on a task's branch; work batch next says fix task or look at failure today. r161 and r162 keep r149's and r154's worlds (no commit after the failed submit), which pass today, so their scenarios start from the retired lines' and pass only with the new condition read; the new behaviour fails first in r160.
Rated: medium value (a driver loops on a stale step until it reviews by hand), medium urgency, small size (one check in the poll, three scenarios of which two restate).

## Requirements

### batches

retired: [r149, r154]
retires: [r161 r149, r162 r154]

#### [g160] A batch whose failure has a fix is polled for its submit
- [r160] While a batch is `building` and every task of the batch is `done` and a scenario breaks in the workspace of the batch and a fix exists, when the driver polls the batch, the batches service shall return a batch step whose instruction is `submit batch`.

#### [g161] A batch whose item's scenario breaks with no fix is polled for the item's task
- [r161] While a batch is `building` and a task of an item in the batch is `done` and every task of the batch is `done` and a scenario of the item breaks in the workspace of the batch and no fix exists, if the driver polls the batch, then the batches service shall return a batch step whose instruction is `fix task` and the task.

#### [g162] A batch whose other scenario breaks with no fix is polled to look at the failure
- [r162] While a batch is `building` and every task of the batch is `done` and a scenario breaks in the workspace of the batch and no scenario of an item in the batch breaks in the workspace of the batch and no fix exists, if the driver polls the batch, then the batches service shall return a batch step whose instruction is `look at failure` and the scenario.

### execution model

object fix kind of kept change

- **fix** (noun) → object fix. A kept change on the branch of a task of a building batch, made after the batch's last submit that a scenario broke, which the next submit tests. Plural: fixes.
