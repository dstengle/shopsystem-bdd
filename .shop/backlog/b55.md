# A batch runs in one fresh agent, not in the main session

## Notes

Batches 3 to 6 were each orchestrated by one long main session (task, fix and review subagents were fresh, the orchestration was not), against CLAUDE.md's "not inside a long main session". Each batch is run by one fresh agent that follows building-a-batch from `work batch start` to awaiting-merge, dispatching the task, fix and review subagents itself, and replies with the pull request; the main session only starts it, relays the link and, after the merge, runs `work batch merged` and `measure batch`. The person asked for it on 2026-11-06 and for b51 to be run that way first, as its trial. If a subagent cannot dispatch subagents, a fresh session per batch instead. building-a-batch and measure batch's roles (a dispatching subagent is the driver, counted as planning) to follow.

Shaped 2026-11-06 by the regular process, at the person's word ("do the regular process"), in place of a direct edit of the skill. `work batch start`, after it lays the batch, writes the batch brief `.shop/worktrees/batch-<n>-driver/brief.md` (beside the review briefs, not committed) and prints its path: the batch and its tasks with their worktrees, branches and ids; the skill building-a-batch to follow; the push command's environment from `.shop/delivery.toml` if any; the rules every subagent is given (red first, no `.feature` edits, the `Item:` trailer, nothing under `.shop/`, old worktrees never reference, no cp with rm); where it stops (awaiting-merge, no merge, no `work batch merged`); and what it replies. building-a-batch splits in two: the session that starts a batch runs `work batch start` and dispatches one fresh `general-purpose` agent (description `batch-<n> driver`) with the brief's path as its whole prompt, and relays the pull request; the driver follows the rest of the skill. CLAUDE.md's rule on plans names the batch brief. A `batch-driver` agent type is b34's to decide. Rated high-value (batches 3 to 6 grew one session's context; batch-7 and 8 run this way cost less planning), high-urgency (every batch from now on), small (one brief written from what start already knows, and the skill).
