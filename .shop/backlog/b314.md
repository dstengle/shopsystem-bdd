# model logic: no L1 between two acts on objects whose restrictions exclude each other (holds nothing, holds a file)

## Notes

From the review of release 0.35.1 (finding 7): 'shall return a worktree that holds nothing' beside 'shall not return a worktree that holds a file' gives an L1 though no worktree meets both restrictions; the same with print and 0.35.0's 'holds no file' against 'holds a file'.
Shaped 2026-11-16 after the backlog triage (.shop/records/2026-11-16-backlog-triage.md, the cluster model logic's precision; no decision of the person rests on it). Reproduced on scratch contexts built by tests/scenarios/codified2_world.py with design_model_check_worlds_member's terms keep and return: 'shall print a worktree that holds no file' beside 'shall not print a worktree that holds a file', and 'shall return a worktree that holds nothing to the person' beside 'shall not return a worktree that holds a file to the person', each give an L1 on main. Two faults in grammar/check.lp, neither about exclusion. (1) gap/pag read a restriction orel(R,Q,Y,Z) of an object only when the object is the row's first place; in 'a worktree that holds a file' the worktree is the second (orel(R,r_file_in_worktree,x5,x4)), so B's restriction is never seen unentailed and the pair clashes: add gap/pag with relby/relof over orel(R,Q,Z,Y). (2) An act with a recipient has the object pair(X,R), a term with no role, so at/4 unifies it by its literal name and gap/pag, over map of roles, never read its parts: keep ispair(S,pair(X1,X2)) out of the literal at/4 rules, derive at(A,B,S,pair(X1,X2),pair(Z1,Z2)) from its parts, and gap/pag of a pair from either part's. With both on a scratch check.lp the two pairs give no finding, 'return a worktree that holds a file' beside 'shall not return a worktree that holds a file' still gives its L1, r315's world still gives its L1, and this repository's model logic prints the same six L8s. Modules: grammar/check.lp and its comments; the scenarios are design-model-check worlds, a row each in tests/scenarios/design_model_check_worlds_member.py. Beside b232 and b233: no shared fix. b232 (an oattr of value V entailing the onattr of W != V) is a new entailment rule in the same gap/pag block; b233 is spec_lf_quant's translation of an at-most count in a condition, check.lp's ccount untouched. b232 and b314 touch the same lines and fit one batch.
