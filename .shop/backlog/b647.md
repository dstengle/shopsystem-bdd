# The domain model says a model line restates an element, and a restated object is not silently cut down

## Notes

batch-98 review 1 observations (b598): spec/model/tracking.md declares restates → operation only, while the vocabulary's restate frame takes an element; a chunk that repeats one member replaces the whole object with no note from work line --model; the unlay of a restated object fails when another item of the batch adds to it; services, events and actors are not restated. Also contract_obtain's module-map row does not name bounded context failing (b596, r102).
From batch-98's review of b598: a model line that restates an object replaced the whole object when it repeated one member line, silently cutting the members it left out (drafting#r66 names each one on declare); only objects and operations were restated, so a changed event or actor line was appended as a second declaration (batches#r117, r118); the park of an item that restated an object failed to put it back once another item of the batch had added a member line to it (batches#r119); and spec/model/tracking.md said a model line restates only an operation (the tracking model block restates model line to restate an element). Also to fix as you go: contract_obtain's module-map row does not name a bounded context failing (b596).
Rated high value and urgency: a silent loss of model members corrupts the domain model a batch lays; medium: four lines over backlog_model, backlog_model_elements and the drafting declare output.
returned by work batch start: batches: batches#r117: refused: the verb move is an action, and a While clause takes a state

## Requirements

### batches

#### [g119] A park of an item that restates an element keeps a member line another item of the batch adds
- [r119] While an item in a batch holds a model line that holds a member line and another item in the batch holds a model line that restates an element and the element does not hold the member line and the item is `in-batch`, when a session parks the item, the batches service shall keep the member line in the domain model and keep a domain model that does not hold the model line.

#### [g120] A model line that restates an event is laid in place of the event
- [r120] While an item is `ready` and the item meets the readiness bar and the item holds a model line that restates an event, when the person opens a batch, the batches service shall keep the model line in the domain model and keep a domain model that does not hold the event.

#### [g121] A model line that restates an actor is laid in place of the actor
- [r121] While an item is `ready` and the item meets the readiness bar and the item holds a model line that restates an actor, when the person opens a batch, the batches service shall keep the model line in the domain model and keep a domain model that does not hold the actor.

### drafting

#### [g70] A restatement that leaves out a member line of its element names the member line
- [r70] While a model line restates an element and the element holds a member line that the model line does not hold, when the person declares the model line in an item, the drafting service shall keep the model line in the item and name the member line.

### specification model

```model
object element
  relations: holds → member line (many)

object member line kind of text

object event kind of element

object actor kind of element
```

- **member line** (noun) → object member line. A line indented under an element's line in the domain model, an attribute, a relation, a lifecycle or an operation that the element holds.
- **event** (noun) → object event. An element of the domain model that an operation raises, declared by a line that opens with `event`.
- **actor** (noun) → object actor. An element of the domain model that requests operations, declared by a line that opens with `actor`.

### tracking model

```model
object model line kind of text
  relations: restates → element (one)
  relations: specifies → operation (one)
  relations: holds → member line (many)
  relations: moves to → area (one); leaves → area (one)

object domain model kind of file
  relations: holds → model line | operation (many)
  relations: holds → element (many)
  relations: holds → member line (many)
```
