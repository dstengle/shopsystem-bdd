# The batch poll prepares a pending task, waits on an unbuilt one, and names where a review's findings go

## Notes

batch-116, driven by looping on work batch next: (1) for a pending task it said 'build task' while the task's worktree exists only after work batch resume, so the step should be 'prepare task' (resume) first; (2) right after resume it said 'finish task' for a running task with nothing built, reading every running task as ready for done; it should say 'build task' until the task's subagent reports (e.g. a commit citing the item since the lines commit); (3) 'review change' does not say where the reviewer's reply is saved (the review folder's findings.md, which work batch reviewed reads); the step should name the findings file. Also: the subagent harness has no foreground dispatch, so the brief's foreground rule cannot be followed by a driver.

## Requirements

### execution model

```model
object batch step
  attributes: instruction: prepare task | build task | finish task | submit batch | review change | fix finding | park item | stop
  relations: holds → task | batch brief | review folder | findings file | review finding (many)

object findings file kind of file

object review folder kind of file
  relations: holds → findings file (one)
```

### retirements

- model line `object batch step` in execution
