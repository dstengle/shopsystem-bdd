# The batch poll prepares a pending task, waits on an unbuilt one, and names where a review's findings go

## Notes

batch-116, driven by looping on work batch next: (1) for a pending task it said 'build task' while the task's worktree exists only after work batch resume, so the step should be 'prepare task' (resume) first; (2) right after resume it said 'finish task' for a running task with nothing built, reading every running task as ready for done; it should say 'build task' until the task's subagent reports (e.g. a commit citing the item since the lines commit); (3) 'review change' does not say where the reviewer's reply is saved (the review folder's findings.md, which work batch reviewed reads); the step should name the findings file. Also: the subagent harness has no foreground dispatch, so the brief's foreground rule cannot be followed by a driver.
Shaped from batch-116's run on work batch next (the idea's note) with b691 merged in. Lines retire r136-r140 of batches and add the running-unbuilt build step (r145) and the empty batch's stop (r149); r141 kept. Model: object batch step retired and declared again with the value prepare task and the findings file (a second attributes line of one attribute is not merged by domain_model_parse, so a value cannot be added in place: technical call), its entries written again. Built: a pending task -> prepare task, report shop work batch resume; a running task whose task branch holds a commit citing its item since the batch's lines commit -> finish task, else build task with the batch brief; review change names <review folder>/findings.md; fix finding only for a finding no commit cites (Finding:); tasks counted only of in-batch items. Precedence the lines carry: failed over running over pending; fix finding over the task steps stays in pick's order, unstated (a technical call: the lines would need a no-box over findings with kept changes). Worlds that fail first: r146 a batch with one pending task (today build task); r145 a running task whose branch has no commit since the lines commit (today finish task); r144 the same task with one commit citing the item (passes today, so the world also holds a second, pending task to show finish wins); r147 an in-review batch whose step must name findings.md (today only the folder); r149 a building batch whose only task's item is parked (needs-input) (today stop by accident: the world gives the batch an in-batch item with no task, which gets submit batch today); r148 a fix now finding with a commit citing it (today fix finding, must be the task step); r143 a failed task of an in-batch item beside a running one (passes today; the counter-example is a failed task of a parked item, which today parks it).
Rated: high value (every batch driver loops on the poll; wrong steps stall batches), high urgency (batches run on it now), medium size (pick and report in batch_next.py, the model's value, seven scenarios).

### batches

#### [g143] A batch with a failed task of an in-batch item asks the driver to park the task's item
- [r143] While a batch is `building` and a task of an item in the batch is `failed` and the item is `in-batch`, when the driver polls the batch, the batches service shall return a batch step whose instruction is `park item` and the task.

#### [g144] A batch with a built running task and no failed task asks the driver to finish the task
- [r144] While a batch is `building` and a task of an item in the batch is `running` and the item is `in-batch` and the workspace of the task holds a kept change that cites the item and no task of the batch is `failed`, when the driver polls the batch, the batches service shall return a batch step whose instruction is `finish task` and the task.

#### [g145] A batch with an unbuilt running task and no failed task asks the driver to build the task with its brief
- [r145] While a batch is `building` and a task of an item in the batch is `running` and the item is `in-batch` and the workspace of the task holds no kept change that cites the item and no task of the batch is `failed`, when the driver polls the batch, the batches service shall return a batch step whose instruction is `build task`, the task and the batch brief of the batch.

#### [g146] A batch with a pending task and no failed or running task asks the driver to prepare the task
- [r146] While a batch is `building` and a task of an item in the batch is `pending` and the item is `in-batch` and no task of the batch is `failed` and no task of the batch is `running`, when the driver polls the batch, the batches service shall return a batch step whose instruction is `prepare task` and the task.

#### [g147] A batch in review asks the driver to review its change with the review folder and its findings file
- [r147] While a batch is `in-review`, when the driver polls the batch, the batches service shall return a batch step whose instruction is `review change`, a review folder of the batch and a findings file in the review folder.

#### [g148] A batch with a finding to fix now that no kept change is for asks the driver to fix the finding
- [r148] While a batch is `building` and a review of the batch holds a review finding whose triage is `fix now` and no kept change for the review finding exists, when the driver polls the batch, the batches service shall return a batch step whose instruction is `fix finding` and the review finding.

### execution model

```model
object batch step
  attributes: instruction: prepare task | build task | finish task | submit batch | review change | fix finding | park item | stop

  relations: holds → findings file (one)
```

- **batch step** (noun) → object batch step. What a batch needs done next, as the batches service says it to the driver: its instruction and the task, brief, review folder, findings file or finding it is about.
- **instruction** (attribute) → attribute batch step.instruction. What a batch step asks the driver to do.
- **prepare task** (noun) → value batch step.instruction prepare task.
- **build task** (noun) → value batch step.instruction build task.
- **finish task** (noun) → value batch step.instruction finish task.
- **submit batch** (noun) → value batch step.instruction submit batch.
- **review change** (noun) → value batch step.instruction review change.
- **fix finding** (noun) → value batch step.instruction fix finding.
- **park item** (noun) → value batch step.instruction park item.
- **stop** (noun) → value batch step.instruction stop.
- **findings file** (noun) → object findings file. The file `findings.md` in a review folder where the reviewer's reply is saved, which `work batch reviewed` reads. Plural: findings files.
