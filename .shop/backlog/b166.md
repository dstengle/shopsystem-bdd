# work batch done blocked by other in-batch items' unbuilt scenarios that pass on the lines commit

## Notes

batch-22: the lines commit carried strict XPASSes of other items' ids (design-model-check#r74 restating delivered r73; r77/r78/r83 and decision-tiers#r12 through loose fallback handlers) and a v_t12 on b132's term unmarked. done runs the whole suite in a task's tree and may cite only earlier items, so every task but one sees another item's XPASS it cannot fix: at most one task of the batch can be done. Candidates: done treating other in-batch ids' xfail as non-strict (review runs the merged suite strictly), the readiness bar refusing a line whose scenario passes unbuilt, and lexicon problems (v_t12) in the bar.
batch-22 showed at most one task can be done: work batch done runs the whole suite in a task's tree, where another in-batch item's unbuilt scenario that passes is a strict XPASS the task cannot fix. Smallest sound behaviour: in the run of work batch done every unbuilt id's xfail is non-strict (the task's own ids must already be out of unbuilt: done refuses them first, so its own passing scenario is still refused), e.g. by an environment variable done sets and spec_unbuilt.mark reads; work batch review runs the merged suite strictly as now. Also the readiness bar takes in spec_lexicon.problems that the item's lines bring (problems on the copy not on spec/ itself), since b132's v_t12 slipped through.
Rated high value and high urgency: it blocks every multi-item batch of b112's 4.0 work (batch-22 was abandoned on it); small: a switch in spec_unbuilt.mark set by batch_tasks' done run, and the lexicon's new problems in readiness_bar.well_formed.

## Requirements

### batches

#### [g19] Another item's passing scenario does not hold up a task
- [r19] While an item in a batch is `in-batch` and a scenario of the item is passing, when a session runs `work batch done` on a task of the batch that is `running`, `work` shall set the status of the task to `done`.

### readiness

- **ill-termed** (adjective of item): an item whose lines bring a problem of the lexicon (v_t4 to v_t13, a v_t12 among them) that the lexicon without them does not have.

#### [g15] `work ready` refuses an item whose lines bring a lexicon problem
- [r15] While an item is `shaped` and the item is ill-termed, if the person runs `work ready` on the item, then `work` shall exit with an error naming the term.
