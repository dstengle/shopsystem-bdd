# work batch review takes an awaiting-merge batch whose branch merged its base, reviewing only that merge

## Notes

batch-61: PR #85 conflicted with main after the clean review; the driver merged origin/main into batch-61 by hand (3ff2cb60f) and pushed, but work batch review and brief both refuse a batch that is awaiting-merge, so no command checks or reviews a merge of the base after a clean review.

## Requirements

### reviews

#### [g7] A batch awaiting its merge whose branch merged its base is submitted for review again
- [r7] While a batch is `awaiting-merge` and the workspace of the batch holds a base merge, when the person submits the batch, the batches service shall keep a proposed change of the batch and set the status of the batch to `in-review`.

#### [g8] A batch awaiting its merge with no base merge is not submitted
- [r8] While a batch is `awaiting-merge` and the workspace of the batch holds no base merge, if the person submits the batch, then the batches service shall refuse the request and name the batch.

### review-guarantees

#### [g10] A review after a base merge reads only the base merge
- [r10] While the workspace of a batch holds a base merge and the proposed change of the batch has a review and no review finding on the proposed change whose triage is `fix now` exists, when `pr-reviewer` reviews the proposed change, `pr-reviewer` shall review only the base merge.

### execution model

```model
object base merge kind of kept change

object batch
  lifecycle status: awaiting-merge → in-review

service batches
  operation submit(batch)  outcomes: done → the proposed change | refused: task not done, kept change citing no item, batch with no base merge
```

- **base merge** (noun) → object base merge. A kept change on a batch's branch that merges the branch the batch started from into it, made after the batch's last review. Plural: base merges.
