## Requirements

### reviews

#### [g9] A batch awaiting its merge whose branch merged its base is submitted for review again
- [r9] While a batch is `awaiting-merge` and the workspace of the batch holds a base merge, when the person submits the batch, the batches service shall keep a proposed change of the batch and set the status of the batch to `in-review`.

#### [g10] A batch awaiting its merge with no base merge is not submitted
- [r10] While a batch is `awaiting-merge` and the workspace of the batch holds no base merge, if the person submits the batch, then the batches service shall refuse the request and name the batch.

### review-guarantees

#### [g10] A review after a base merge reads only the base merge
- [r10] While the workspace of a batch holds a base merge and the proposed change of the batch has a review and no review finding on the proposed change whose triage is `fix now` exists, when `pr-reviewer` reviews the proposed change, `pr-reviewer` shall review only the base merge.

### execution model

```model
object base merge kind of kept change

object batch
  lifecycle status: awaiting-merge → in-review

service batches
  operation submit(batch)  outcomes: done → the proposed change | refused: task not done, kept change citing no item, batch with no base merge
```

- **base merge** (noun) → object base merge. A kept change on a batch's branch that merges the branch the batch started from into it, made after the batch's last review. Plural: base merges.
