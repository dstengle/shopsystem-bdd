# A parked item's lines leave the other tasks' worktrees

## Notes

Found in batch-3: b45 was parked because its generated scenario could not run (a step with no words, see b46), but its lines and feature stayed on batch-3 and so on t2's branch, so `work batch done batch-3 t2` failed the suite on b45's scenario. `review` takes a parked item's lines out only once every task is done, so the batch could not go on; it was abandoned and b43 restarted as batch-4. `park` should take the parked item's lines out of batch-<n> (unlay_lines) at once, and `done` run a task's tests with them out (merging batch-<n> into the task branch, or testing against it).
