```text
By "hosting" I mean just this: the shop's own list of which bounded contexts it contains. It has nothing to do with servers or deployment.

b576 does three things:
- `.shop` gets a list of the bounded contexts kept in this repository, each by its id under the product. For example, `missingmass.io/shopsystem/shopsystem-bdd` today, with `…/language` added later if the toolchain is split out (b577).
- `work host <context id>` adds a context to that list, refusing a malformed id, a duplicate, or an id that isn't under the product. `work hosts` prints the list.
- A shop that lists nothing is taken to contain only its own context, which is what every shop has today.

Other tools then read that list. `spec check`, `spec publish`, the product check and the coupling report all need to know which contexts live here.

You're right that "host" is a poor word. It reads as runtime hosting. I'd rename it before it's built: **the shop holds a bounded context**. The commands become `work hold <context id>` and `work holdings`, or `shop contexts` once the `shop` command takes over. The language already reads "holds" as containment, so lines stay natural, for example "the shop holds the bounded context".

On where it lives: the list describes what the shop contains, not how work is executed. So I'd still move it out of `batches` into a small shop capability of its own, alongside the delivery settings, which also describe the shop rather than a batch.

If both sound right, I'll reword b576 accordingly before it goes into a batch.
```
