### the session, 2026-11-07T06:16:28.070000+00:00, 42b189a4-766b-4e9c-be2b-837d2b275a51

```text
**Is a verb alone ever valid?** Yes, but only for a verb that really takes no object, and the glossary has to say so.

- **Valid:** "a session *ends*", "the lock *expires*", "a check *fails*". Each says something changed about its subject, which gives a fact to reason from: *the session was open, now it's ended*.
- **Never valid:** a verb that takes an object, used without one. "A caller *asks*" and "feed *gives*" leave out an argument the verb needs, so there's nothing to reason from about it.

You're right that being unambiguous isn't enough. A line can have exactly one parse and still produce no logic. So each verb's declared form also needs to say which facts it produces, so the checker can infer from it.

Here's where we've got to:

**Glossary.** Every term is labelled with its part of speech:
- noun
- adjective
- preposition
- verb, with its form: alone, *with an object*, or *with an object and a recipient*, and the kinds of noun in each slot

**Base grammar.** It starts from basic English sentence structure and restricts it:
- A clause is subject, verb, then an object if the verb has one, plus typed prepositional phrases.
- A noun introduces a variable with "a" and refers back to it with "the".
- "Not" goes on the verb or the relation.
- Anything else is refused.
- Glossaries supply words, not new sentence shapes.

**Credentials once, not in every line.** A requirement that applies everywhere says every request to feed carries a user's YouTube access, so individual lines can say just "a caller requests a video". Binding each caller to its user would also be good, if it doesn't take too much effort. One way, as my guess, is a relation like *caller | acts for | user*.

What's wrong or missing?

Next question: this will refuse lines in every context, this repository's own spec included. Is it acceptable for b82 to cover rewording all of them, or should the new grammar run alongside the old one for a while?
```
