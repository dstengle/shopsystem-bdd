```text
I tested about 25 lines through `model parse --form`, using this repository's own nouns (items held in a batch). To answer your direct question first: **yes. A collection's size and membership can both be stated today, and they read correctly.** Ordering, comparing two things' values, and several closures are what's missing.

## What already works

| Use case | A line that parses | Its reading |
|---|---|---|
| Membership in a response | `work` shall print a batch that holds every item whose status is `ready` | an `every` box, with each item in the batch |
| Membership in a condition | While a batch holds an item, … | `in(x2, x1)` |
| Empty | While a batch holds no item, … | `not [item] in(...)` |
| Only these, nothing else | … a batch that holds only items whose status is `ready` | an `only` box |
| Size, bounded | … a batch that holds at most three items / While a batch holds at least two items | a `count` box |
| Size, exact output | `work` shall print exactly three items | count exactly 3 |
| Size as a value | `work` shall print the number of items in the batch | a `number` box |
| Size compared | While a batch holds an item and the number of items in the batch is more than three, … | count more than 3 |
| Every member meets something | … and every item in the batch is `ready` | `every` box with a scope |
| Every member printed | `work` shall print every item in the batch | `every` with print |
| Two distinct things | `work` shall print two items | `distinct(x6, x5)` |
| A member against a fixed value | the release of x is after `0.34.1` | ordered comparison (`Order: by number`) |

`features generate` already writes scenarios for `every`, `only` and `count` boxes. The "is in" (`in`) relation, which "holds" reads as, is in place.
```
