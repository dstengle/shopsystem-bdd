I agree on the first two and have recorded both as decisions, with items to build them.

**1. Several provider operations per port operation, not one to one: decision 0138, item b637.** An adapter spec records, for each port operation, the *set* of provider operations used to realise it. The set can draw on one provider or several, and one provider operation can serve several port operations. The adapter's realisation lines say how those operations are combined. A job's trace follows every provider operation in the set into that provider's contract.

- The folder layouts we've built so far (b348, b587, b591, b593) become the first adapter.
- I merged b622, obtaining from a context in the same shop, into b636 as another adapter of that port.
