# requests: requests

## Questions
- requests#r22 says work request refuses when 'the delegation given is empty'. Does a delegation of only whitespace (e.g. --delegation "   ") count as empty? Reading A (empty string only): `work request ... --delegation "   "` exits successfully, prints q<n>, and the request is kept and committed with delegation "   " (today's behaviour, under r19); work run then treats "   " as a delegation and sends questions to answer sessions. Reading B (empty after stripping whitespace): the same command is refused because the delegation is empty, exits with an error, and the upstream keeps no request, exactly as for --delegation "". The r22 scenario's Pins line ('a delegation that names no question') leans to B, but the word 'empty' reads as A.

## Answers
- 2026-10-25: Reading B: a delegation that is empty after stripping whitespace is refused, exactly as an empty one (the coordinator under the person's delegation 2026-10-25: "Do not involve me in fixing all of the bugs. Please get the system into a correctly working state before doing a release")
