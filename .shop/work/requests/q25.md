# Every command gives JSON and exits 0 but on a crash; every agent returns structured JSON

## Lines
1. The plugin's commands, `work`, `measure`, `features`, `model`, `tools` and `migrate`, shall give their output as one JSON object on stdout by default.
2. **When** a command of the plugin refuses, finds a fault, finds a check failing or has a question for the person, the command shall exit 0 and give what it found and why in its JSON output.
3. **If** a command of the plugin crashes on an error it does not handle, then the command shall exit 1.
4. The plugin's agents shall return their output as structured JSON.

## Questions
1. line 1: Some commands print text for a reader or a hook (`migrate status --hook` at SessionStart, `features` showing Gherkin or a scenario, `model rules`). Is every one to give one JSON object by default, or do those keep a text form (a flag, or the hook's text inside the JSON)? And is the JSON a stable shape the contract names, or whatever each command finds?
2. line 2: Exit 0 on a refusal, a fault or a failing check contradicts lines already approved: a `check` is a command whose exit code 0 shows its work complete (glossary), `features bindings --unbound` fails the suite by its exit code, and `model check`, `tools size` and `tools check` exit 1 on findings. Which commands does this change: all of them, with `work run` and the suite then reading a field of the JSON (name it, e.g. `ok`) in place of the exit code, or only the commands that refuse or ask the person, with check-like commands keeping a non-zero exit when they find a check failing?
3. line 4: Which agents, and what is the structured JSON: the reply an agent gives its caller (today text such as a commit and counts), or its `result.json`, which is JSON already? Is the shape named per agent, or one shape for all (outcome, summary, files, questions)?
