# Dependencies between initiatives are kept in the queue, and a stale draft is renumbered rather than redrafted

## Lines
1. **Where** an initiative names a request or an initiative it waits on, `work run` shall start no round and no work-item stage for it while what it waits on is not delivered or `done`.
2. `work list` and `work status` shall give, for each initiative that waits on a request or an initiative, what it waits on.
3. **When** a round of the kind `apply` finds that a requirement id its drafts add is already in `spec/`, `work run` shall give that line the next free id of its capability, and the references to it in the drafts the same id, without a new round of the kind `integrate`.
4. **When** every work-item of an initiative is `withdrawn` because the requirements it accepts are already met, and every capability-proposal of it is `formulated` or `withdrawn`, `work run` shall set the initiative `done`.
