# Review findings back to implementation

## Lines
1. **When** a question a reviewer asked on a work-item is answered with a change to make, `work` shall return the work-item to `ready`.
2. **When** `work run` starts an implementer for a work-item that an answer to a reviewer's question returned to `ready`, `work run` shall give the implementer the reviewer's findings and the answer.
3. **When** a question a reviewer asked on a work-item is answered accepting the work-item as it is, `work` shall return the work-item to `done`.

## Outcomes
1. question
2. accepted

## Questions
1. Line 1: work-queue r14 already returns a reviewer's question to `done` on any answer, and `work answer` takes a free-text answer. How does `work` tell an answer 'with a change to make' from one 'accepting the work-item as it is' (line 3)? Readings: (a) a flag or keyword on `work answer` (e.g. `--change` / `--accept`), the recommended one since the answer stays one line of free text; (b) `work` infers it from the answer's wording, which is unreliable; (c) the answer's author is the person or delegation session and picks the transition by running `work answer` for acceptance or another command for a change. Also: should r14's `done` for a reviewer's question then apply only to acceptance?

## Answers
1. 2026-10-25: (a), a flag on `work answer` saying whether the answer asks for a change or accepts the work-item as it is; work-queue r14's return to `done` for a reviewer's question then holds only for acceptance. The gate chooses the flag's form.
by: the coordinator as asker, on the person's approval 2026-10-25 ("Yes, set that up") of a flag on `work answer`; written by hand once, by the person's choice 2026-10-25 ("One hand edit + q3"), because `work` has no command for it (observation/2026-10-25-request-question-unwritten)
