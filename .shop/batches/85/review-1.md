# batch-85 review 1

## Verdict

The batch builds consistency#r40 for b571. A response's act of an operation verb with no parameters is now keyed `req(O,())`. Through `kcov` and `covd`, check.lp makes a "shall not" whose key covers an obliged request's key clash with it. The g40 scenario was generated by `features generate`, and every run in the brief exits 0, as it did at the base. Nothing needs fixing before the merge. There are two observations: the new key is not given to the `count` and `only` paths, and an unrelated speed-up to `features generate` rides in this batch.

## Findings

### f1 Important observation: a counted or `only` act of an operation verb keeps the plain event, so it no longer meets the new `req(O,())` key
- item: b571
- where: scripts/spec_lf_facts.py:189
Since b571, `Walk.act` keys a response's act of an operation verb with no parameters as `req(&lt;op&gt;,())`, by `operated` and `asked`. The other two places that write a response act of that same verb were not changed:

- `Walk.count` (scripts/spec_lf_facts.py:218-224) still writes `resp(..., e, d, x)` and `count(..., e, ...)` with the plain event `e`.
- `Walk.only` (scripts/spec_lf_facts.py:205-207) still writes `only(..., e, d, x)`.

spec_one_thing lets a response's act of an operation verb with no parameters take a plural object, so "shall publish at least two design-decisions" or "shall publish only design-decisions whose …" still reads. Before this change, both of those lines and "shall not publish the design-decision" carried the event `publish`. They met in check.lp's `dem`/`do` rules for `pos`/`neg` and `only`/`pos`. Now the "shall not" or the plain obliged act carries `req(publish,())`, and the count or the `only` carries `publish`. These are different terms, so the clash goes silent. This is the same kind of regression b571 fixes for b545.

What I read: `Walk.act`, `Walk.only` and `Walk.count` in the tree, and spec_one_thing's row in CLAUDE.md, which says that such a verb with no parameters keeps its plurals. I did not run it. To reproduce: put "shall publish at least two design-decisions" and "shall not publish the design-decision" on one trigger; `spec logic` gives no L1 at head. No line of the batch names counts or `only`, so this is recorded as an observation.

Fix: in `count` and `only`, write the event as `req(&lt;e&gt;,())` when `operated(walk, e)` holds, and add the `rqo` fact, as `act` now does.

### f2 Minor observation: `features generate` holding the spec's state is a speed-up no line of b571 asks for
- item: b571
- where: scripts/features:108
Commit e95601910 wraps the capabilities' generation in `spec_held.held(root)`. It changes nothing a caller can see: `features generate` writes no file among spec_held's inputs, so the held state cannot go stale during the run, and `features generate --check` exits 0. Still, it is a performance change unrelated to consistency#r40, carried under b571, with only a CLAUDE.md row and no test or decision of its own. Recorded so the change is traceable; no fix is needed.
