## Critical

**C1. migrate writes through a tracked symlink to a file outside the repository.** At scripts/migrate_layout.py:137-140,
`(root/rel).write_text(text)` follows symlinks, and so does the reader. Repro: a tracked `linked.md` points to
/tmp/…/outside/notes.md and names a docs/superpowers/plans path. `migrate run` exits 0 and rewrites the outside file.
Why: it changes a person's file outside the repository, which git cannot restore. Fix: skip or refuse symlinked paths
(`is_symlink()`, or git mode 120000), and never write a path that resolves outside `root.resolve()`. Add a scenario.

**C2. migrate is not all-or-nothing, and it destroys an ignored file.** write_decisions_index
(scripts/migrate_layout.py:143-148) overwrites `spec/decisions/index.md` without the destination check that the
moves get. The path is not in `plan.created`. All the moves, removals and writes (`write()`, :125-140) run with
`check=True` and nothing rolls them back.
- Repro 1: an ignored, untracked spec/decisions/index.md holding the person's text is overwritten. Then `git add` of
  the ignored path fails with a Traceback and exit 1, with every move already made.
- Repro 2: an ignored *file* `.shop` makes `mkdir .shop/records/…` raise after the first `git mv` has run, leaving a
  half-migrated tree.

Why: this breaks r7 ("change no file") on a refusal, and loses data git does not hold. Fix: put index.md in
`plan.created` so check_moves covers it. Check before writing that no ancestor of a destination is a non-directory.
On any exception during writing, restore the pre-state (stash or reset the index and worktree to the starting
commit), and give a refusal, not a Traceback.

### Safety (item 2)

No `bypassPermissions` or `--dangerously-skip-permissions` appears anywhere. Workers run with
`--permission-mode acceptEdits`, `--plugin-dir` set to the plugin root, and `--allowedTools` set per stage
(scripts/supervise_worker.py:26-34, 121-125). No list has a bare Write or Edit (r13). `git worktree remove --force` is
used only on worktrees the run created, and the put-back checkout and rm happen only inside the implementer's
worktree. Status is written in `work` and `work run`'s commits, except for the following.

**S1. A worker can start a nested supervisor on the main checkout.**
`Bash(python3 <SCRIPTS>/*)` (supervise_worker.py:26) admits `python3 <scripts>/work --root <main checkout> run …`,
which moves statuses as "work run". Every stage also has `Bash(python3 -m pytest*)` together with acceptEdits writes,
so any Python runs through a conftest or a probe file: r14's "no other Python" holds only on paper. The docstring at
:111-113 says the main checkout is never put back. Fix: refuse a `--root` other than the cwd when started under work
run (an environment marker), and check the main checkout's .shop/work against HEAD after each worker. Add a line
saying what pytest permits, for the gate.

**S2. A detached HEAD switches off r6 (put-back) and r4 (rebase).** supervise.py:60 takes
`rev-parse --abbrev-ref HEAD`, which is "HEAD" when detached. In the worktree, supervise_merge.py:44
`diff HEAD...HEAD` is then empty and the rebase does nothing. Reproduced: an implementer's commit setting a work-item
green is fast-forwarded into the main checkout. Fix: refuse a detached HEAD under r10, or use the commit hash.

**S3. r4's tests count untracked files the merge does not take.** The tests run in the worktree (supervise_merge.py:88)
with any untracked conftest.py or step file the worker left there, but the merge takes only the commits. Fix:
`git clean -fdx -e .shop/scratch` before the tests.

**S4. r20 (two disjoint implementers at once) never fires in a real run.** Nothing writes `fileset:` into a work-item.
Supervise reads it only at supervise.py:119 and supervise_brief.py:65. The r19 and r20 scenarios pass only because
supervision_given.py:206 writes it into the Given. Fix: write the planner's file set into the work-item when it
moves to planned (needs a line), or take it from the result file.

**S5. A failure mid-implementation leaves the item `claimed`, against r10.** ready→claimed is committed before the
worktree add, the worker and the ff-merge (supervise_merge.py:57). A git refusal at :59 or :93, or an exception in a
`together` thread (supervise.py:43-46), exits with the item `claimed`. Nothing moves it back, and a hand edit then
trips r6. Fix: on any exception, move it to awaiting-ruling with the error as its question.

**S6. delivery.toml's [allowed_tools] can widen a list.** Only the bare strings "Write" and "Edit" are removed
(supervise_worker.py:64), so "Bash", "Bash(*)" or "Write(**)" pass, against r13 and r14. Neither this override nor
[tests] (supervise_merge.py:27) has a Behaviour line; they appear only in the @r2 and @r12 scenarios. Fix: lines for
both, and refuse entries outside r14's set.

**S7. Agents are told that commands no list gives are allowed.** code-scout.md:74, bdd-implementer.md:16 and
bdd-task-reviewer.md:29 say `ls`, `cat`, `wc` and `grep` are allowed, but no --allowedTools entry gives them. The
stub refuses them and no scenario tries them. Either the real CLI allows read-only commands, in which case r14
overstates the restriction, or the agents' text is wrong. Probe it once with the real CLI.

## Release readiness (item 6)

The release is not ready. The README has no 0.21.0 account (R3), plugin.json says 0.20.0 (R2), and the migration
skill, the path the release exists for, does not use `scripts/migrate` (I1).

What a consuming repository must do to upgrade today:
1. Install the plugin. Its version still reads 0.20.0, and superpowers stays required while plugin.json declares it.
2. `pip install clingo pytest pytest-bdd`, and pytest-xdist as an option.
3. Start from a clean tree with nothing claimed, and nothing symlinked or ignored at a destination (C1, C2).
4. Run `python3 <plugin>/scripts/migrate run --context <owner/product/context>` from the top level (I6), then
   commit. Then map the scenarios and hold the one gate by hand, because the skill does not teach it.
5. Before `work run`:
   - add a pytest `--work-item` option, or set [tests] in `.shop/delivery.toml` (R1);
   - git-ignore `.shop/scratch/` and `.shop/worktrees/` (M22);
   - have the `claude` CLI on the PATH.

None of this is written down for consumers.
