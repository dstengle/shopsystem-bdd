# Builder check of design-r2 and plan-r2 (read against revision-brief.md and the code at 5d6cd4c8)

## Contradictions
1. **R1 vs the scenario suite.** R1 deletes `CommitPush`/`RefuseErr` and design §4.4 replaces `SCommits` with two `SDoes`, but `features/supervision.feature` (257, 395, 440) has "… and pushes the commit" steps, and `features_vocab.py` (27, 30, 238, 276) maps `SCommits`. The scenario suite must stay green in every layer, and `features_vocab.py` is not on the allowance list. Say that `SCommits` stays until L4, and name who deletes it. `grammar/*.gf` has no owner in L4.
2. **`Def` is a start category of Req (§4.3), but `parse(grammar="Def")`** loads `DefEng.gf` (`spec_grammar.load`/`_compile` compile `<grammar>Eng.gf`). Either a new `Def`/`DefEng` module or a startcat argument: choose one. `scripts/model`'s `--grammar` choices (R2) follow that choice.
3. **The `Prep` closed class (§4.2) is unused.** The typed funs `rel_<k1>_<word>_<k2>` already contain the word. **`SRelAtom` duplicates `SAtom`**, because `rel_…_Atom` is already an `Atom`. Drop both, or say what they are for.
4. **R6 refuses non-example given lines**, yet R6's accept and the L3 gate need `--preview`/`--check` to exit 0 on the live supervision, which still has 65 non-example blocks until L4. State whether L3 refuses or tolerates them.
5. **§3 rule 5 / §7.3:** the Givens, When and Thens are worded from the requirement's own trees, with Python choosing the template (`_Given` or `SAtom`), mapping VP→S* and choosing contrast instances. The brief (B) says the generator "keeps only reading traces and linearising".

## Python re-derivations the brief says must come from the one translation
6. **Contrast instances (§7.3)** are a Python rule ("Every/Pl with a restriction → one more solve") that decides what a scenario contains. That is today's `choose`, moved, not gone.
7. **"Extra Givens the group's own clauses do not describe"** needs Python to match trace atoms back to tree clauses, which is an inverse translation. Have `spec_logic` emit a shown label for each clause or conjunct (e.g. `clause(id,i,…)`), so that the reader maps atoms by the translation's own output.
8. **The trigger graph/cone and the horizon edges** ("a response pattern unifies with a trigger pattern, compatible kinds") and **L4's "values a pre-state needs"** are pattern walks over trees. R3's engine is "trees-free", so who derives the edges? Derive them from the translated rules (the head and body predicates of `does`/`set_to`), not from a separate tree walk.

## Gaps and questions
9. **Cone scope.** Is it the capability or the whole spec? Every trigger-less statement (While/Ubiq/Where) of the whole spec enters every cone. So adding an unrelated While anywhere changes every program, and the pool sizes too ("n = NPs of kind K in the program"). Byte-stability is then not "by construction" as §7.4 claims. Which kind of requirement does `test_byte_stable` add?
10. **Pool cap of 3.** A cone needing a 4th instance gives a spurious L1. Report a cap hit as such, not as a conflict.
11. **`it` in a `Def`.** `<cond>_Def : Cond -> Def`, but `Cond` is not kind-indexed, so `it` can parse as any `k_*_It` whose atom typechecks. That gives several trees. "it gives no question and no output" also needs either NP coordination across kinds or a repeated subject. Give one corpus line for each with its expected tree.
12. **`Kind of:` expansion.** Does the supertype row (stage, for, node) also generate its own fun, next to the expanded (stage, for, work-item)? If it does and a subkind NP can fill a node slot, that is two trees. supervision.md 26–30 duplicates index.md 232 once expanded (v_t10). R5 must delete the local ones.
13. **v_t7 "one sentence"** has no counting rule. Code spans (`spec/index.md`), "e.g." and ":" glosses need one, fixed in R2 with tests.
14. **v15m by parsing in the Steps grammar** makes `spec_read`/`model check` compile the Steps grammar (generated by `features_vocab`, owned by R6 in L3). Would a shape test do instead: a line ending in `:` followed by a docstring or table, or `holds "…"`?
15. **Point 2 is measured only inside a group (v15l).** Two groups with the same normalised trigger and condition pass. Add a cross-group rule, or say that this is accepted.
16. **The person's point 3** ("make these term definitions unnecessary"): `## Relations` still lists each meaning of "on"/"for" for each kind pair, now as rows. v_t8 checks the form, not the substance. Say why rows answer the point (they are the domain model's §4, not glossary prose), or report it to the person.
17. **q47 line 4** "an `integrate` stage for an initiative with a result": with typed PP attachment it is ambiguous if (initiative, with, result) ever gets a row. Add it to the corpus as a guarded case.
18. **Size.** `spec_lexicon.py` (192 lines) gains tables, `Kind of:`, `definition` and v_t7–v_t10. `features_vocab.py` is 299. `spec_read.py` is 234. No split module is named for any of them.
19. **Cross-package ids in L4.** `tests/scenarios/supervision_build.py:59` (R8) names `work-queue#r1` (renumbered by R12). `spec/decisions/0072-*.md` names `work-queue#r34–r39` and has no owner. §9.1 greps only `.shop/work/`.
