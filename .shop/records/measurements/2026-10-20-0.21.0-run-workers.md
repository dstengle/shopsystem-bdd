## Contract honoured: the brief and result file of supervise.py (97fd24a)
Every worker definition reads its prompt as the path of a brief file. It takes `Work-item:`, `Read:`, `Run directory:` and `Result file:` from that file, writes its notes, plan, report or findings in the run directory, and writes, last, one JSON object with `status`, `summary` and `questions`. `work run` reads only that JSON.

The stage's own fields are named as decision 0038 names them:
- `fileset`: the researcher and the planner;
- `plan`: the planner;
- `commits` and `report`: the implementer;
- `findings`: the reviewer.

`work run` does not read these extra fields yet.

Each question is one string, because `outcome()` joins strings with "; " and JSON-dumps anything else. No definition depends on a reply. No definition needs a brief line that supervise.py does not write. Each such line is optional and has a fallback:
- `Scripts:`: the plugin's scripts directory;
- `Base:`: the initiative's base;
- the worktree and branch.

See Rulings 1-3.
