**Issues**

Critical: none.

Important:
1. scripts/workqueue.py:36-37, `spec question`. `context_path` does `data["id"].split("/", 1)[1]`. When spec/index.md exists but has no frontmatter or no `id`, `work add i1 w1 ...` ends in `KeyError: 'id'` with a Traceback. When the id has no '/', it ends in `IndexError`. I reproduced both. Why it matters: the ledger rules that Tracebacks fall under r7 ("exit non-zero, say why, and change nothing"). A Traceback does not say why, and the dispatch asks that no Traceback be reachable from the CLI. No scenario covers this. Fix: raise `Refused("spec/index.md gives no bounded-context id (<owner>/<product>/<context>)")` when `id` is missing or has no '/' after the kind. Scenario for the controller: add an Examples row to the r7 outline (features/work-queue.feature:71-74), `| an initiative i1 under .shop/work/ and a spec/index.md with no id | spec/index.md gives no bounded-context id |`, with a Given that writes an index with no id.

Minor:
1. `backlog`, scripts/workqueue.py:56. When `work show` meets a .md under an initiative that is not UTF-8, it ends in a UnicodeDecodeError Traceback. Reproduce: `printf '\xff\xfe---\n' > .shop/work/i1/bin.md; work show`. Fix: catch UnicodeDecodeError and raise Refused naming the file, or skip the file with a warning.
2. `backlog`, scripts/workqueue.py:42 (and :78). Neither `initiative` nor `name` is checked for path separators. Reproduce: `work add i1 ../../../escaped --part-of x --under y --accepts z` writes `<root>/escaped.md` outside `.shop/work/`, which goes against r1's path. Fix: refuse a name or initiative that contains '/' or is '..'.
3. `backlog`, scripts/workqueue.py:47. Field values are written raw. Reproduce: `--part-of $'x\nstatus: ready'` writes a second `status:` line into the frontmatter, which lets a caller of `add` inject a status. Fix: refuse a value that contains a newline.
4. `backlog`, scripts/workqueue.py:78-93 (library only, not reachable from the CLI today):
   - A work-item with no `status:` line, or with no frontmatter, still gets a log line, while the file is left without the status (`re.sub` with count=1 matches nothing). When there is no closing `---`, `text.find` returns -1, and `text[:end]` drops the last character.
   - A log.jsonl line that is blank or not JSON makes json.loads at :66 raise.
   - If the log append fails after :89, the file is already changed, which goes against r7's "change nothing".
   - Fix: refuse a file whose frontmatter has no status, and skip or refuse bad log lines naming the line. Supervision's item should carry these, since that is when moves become reachable.
