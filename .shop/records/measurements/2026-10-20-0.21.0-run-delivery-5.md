## Does the design hold?

Yes, for one work-item. The design is a script that owns status, plus fresh `claude -p --agent` workers that
each get one brief, work in their own worktree, and are read only through a result file. With the four fixes,
it went drafted → green unattended in every scored run.
- The session read nothing the workers wrote. It woke once, on the background command's exit, and printed what
  work run printed.
- No worker touched `.shop/work/`.
- Every move is its own commit, and every stage has a start and an end line with its session id.
- Every failure in the attempts ended where r5 says it should: awaiting-ruling with a question, nothing merged,
  the tree clean. This covered a missing result file, NEEDS_CONTEXT and a planner QUESTION. The failure path
  works as designed.

What the skeleton's lines got wrong was all at the seam between work run and the real CLI. None of it touched
the shape:
1. `--agent` resolves an installed copy of the plugin unless `--plugin-dir` is given. The user-scope 0.18.0 has
   no bdd-planner.
2. `--agent` does not preload an agent's `skills:`. Subagents get their skills that way; a main-session agent
   does not. supervision-1's open unknown is now answered: `skills:` no, `model:` yes.
3. `--allowedTools "Write"` (bare) lets a worker write anywhere. acceptEdits alone keeps writes under the
   worker's working directory. haiku dropped the `.shop/worktrees/<label>/` segment from its run directory path
   in about half its runs, and with the bare Write those writes landed in the main checkout.
4. Bash rules are matched per subcommand, and anything needing approval is refused. Read-only commands
   (`cat`, `ls`, `wc`, `grep`) pass with no rule. Refused: a command behind `cd`, `git -C`, an environment
   assignment or a variable, `mkdir`, `cp`, `git ls-files`.

## What the runs showed that the lines did not foresee (candidate lines, from evidence)

- supervision: work run starts each worker with its own plugin (`--plugin-dir`), not whatever is installed. This
  is now Implementation; the spec's Implementation note still shows the old command line and should gain
  `--plugin-dir`. I did not edit spec/.
- supervision: an agent's skills reach a `claude -p --agent` worker only by the worker loading them. Either it is
  allowed `Skill(<that skill>)`, or work run appends the skill to the prompt.
- supervision: a worker writes only inside its worktree. Writes are left to acceptEdits, and no stage's list
  holds a bare Write or Edit. Evidence: 5 of 8 misplaced with the bare Write, 0 of 8 without.
- supervision: the result's paths (`report`, `findings`) point into the worktree work run has removed. Either
  work run rewrites them to the run directory's copy, or the brief tells workers to give them relative to the run
  directory. A reviewer flagged this.
- supervision: questions a researcher gives with DONE are dropped, and the planner asks them again. Either they
  go into the plan's brief, or DONE means no questions.
- the agents: "you are started in your worktree, never cd". Every implementer and reviewer lost 1-3 turns to a
  refused `cd <worktree> && …`. The session lost one turn in every run to `work run …; echo "exit=$?"`. A line in
  delivering-an-initiative would avoid it: start the command exactly as given, nothing appended.
- supervision: the `work/<item>` branch after a merge. It is still kept. Delete it on merge, unless the person
  rules otherwise; nothing in the runs needed it.
- delivery: with every requirement already accepted, the skill drafts nothing and goes straight to work run
  (v1-v3). That behaviour is reasonable but unstated.

## Cost and time per delivery

One work-item of two files, four stages:
- **Cost**: $0.65-$0.75 (mean $0.70). Workers took $0.53-$0.64 of that and the session $0.11-$0.12.
- **Cost by stage**: research (haiku) $0.015, plan (opus) $0.18, implement (sonnet) $0.14, review (opus) $0.24.

This is the floor for i12's baseline: a trivial item. The budgets have nothing to bind against yet.

## For the person to decide

1. **The reader stages' default tools.** The pinned default is `Read,Glob,Grep,Write,Bash(python3 *),…` in
   supervision.feature's r2 Examples. Its bare `Write` lets a worker write anywhere on the machine, the main
   checkout included. The proposal is to drop `Write` and `Edit` from every stage's default and leave writes to
   acceptEdits, which keeps them in the worktree. Changing the default changes that Examples row, and its
   features/ change is yours to approve. The fixture's delivery.toml does this today.
2. **`Bash(python3 *)`.** It lets any worker run any Python, which can write anywhere and reach the network. In
   these runs it was used for pytest, for the plugin's `tools`, and for probes. Options:
   - narrow it to `Bash(python3 -m pytest *)`, plus `Bash(python3 <scripts>/tools *)` and probe files under
     `.shop/scratch/`;
   - or accept it, with the worktree as the only fence. That fence does not stop Python.
3. **Review uses `git worktree add`.** The reviewer's definition says to check out another revision there; the
   review list does not allow it. Unused in these runs. Either drop it from the definition or add it to the list.
4. **The models by stage.** haiku is the one stage that misplaced its writes. It is also the cheapest
   ($0.015/run), so keep it if decision 1 is taken.
5. **The kept `work/<item>` branch** (above).
