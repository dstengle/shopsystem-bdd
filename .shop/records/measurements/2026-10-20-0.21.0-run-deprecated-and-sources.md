### Important
1. scripts/model:590-593. A scenario tagged both `@deprecated` and `@holding` raises no file problem. The `@deprecated` `continue` runs before the `@holding` check. r26 (spec/capabilities/design-model-check.md:57) says a file problem is raised when "a scenario is tagged `@holding`", with no exception for deprecated scenarios. A half-migrated scenario (the new tag added, the old one not removed) is the likely case, and it passes silently. Fix: move the `@holding` check above the `@deprecated` skip, so the problem is appended first and then the scenario is skipped. Add a row to the r26 outline (features/design-model-check.feature:273-280), e.g. `| features/thing.feature | a scenario is tagged @deprecated and @holding | reports |`, with its branch in feature_file_with (tests/scenarios/test_design_model_check.py:237-250). `spec question`: no scenario covers this case; the controller should confirm the row with the fix.
