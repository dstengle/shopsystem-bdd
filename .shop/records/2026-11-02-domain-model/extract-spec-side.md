Sources: `spec/index.md` Glossary (G), `spec/capabilities/{spec-integration (SI), formulation (F), spec-migration (SM),
spec-consistency (SC), design-model-check (DMC)}.md`, `docs/design-model/grammar.md` (GR, v4) and `design-model.md`
(DM, v4). Ids are cited `si#r12`, `dmc#r24`, etc.; GR/DM by section. A few facts were read from live files under
`.shop/work/` (marked LIVE) to settle what the spec leaves implicit. Extraction only; nothing designed.

Note up front: `spec/index.md` Constraints says the plugin keeps design model **v3**; `docs/design-model/` is **v4**;

different rules (section 2).

## 1. Entities

Identity scheme (dmc#r43, dmc#r46, dmc#r48): every node id is `<kind>/<context path>/<name>`, context path =
`<owner>/<product>/<context name>`; bounded context `bounded-context/<context path>`; requirement
`<capability>#r<n>`; term `term/<context path>/<term>` (lowercased, spaces→hyphens). Bare `<name>` or `<kind>/<name>`
only in kind-fixing fields (`rests_on`, `supersedes`, `argues`, `under`, `depends_on`) (dmc#r43). Ids are IRIs in
waiting (GR §7: "kb's IRIs are already the node ids"). Old forms refused: `<context name>/<name>`, `decision/<name>`,
`obs/<name>` (dmc#r24, sm#r14). Requirement without an id: `<capability>#line<k>`; scenario: `<feature path>:<title>`
(DMC Impl).

### Records (.shop/records/)

Record kinds (GR §1): observation, measurement, review-finding, decision-argument, initiative-archive. Origins: the
first three. A record must be `about` a standing artifact (GR v10b/c). Frontmatter id with a record kind (dmc#r29,
G "record"). Observation headings `## observation/<context path>/<x>` in `.shop/records/observations.md` (sm#r14,
dmc#r19). Archive of plans under `.shop/records/archive/plans/` (sm#r17). LIVE: an initiative's `source` is
`person/2026-10-29-…`, a kind that is no record and no origin.

## 4. Exclusivity, ownership and limits

- **spec/**: nothing under `spec/` changes until the person said yes and answered everything (si#r3); commit to
  `spec/` alone (si#r6); on failure nothing under `spec/` (si#r33). Glossary terms applied only after approval
  (si#r55). "No session writes spec itself" (SI Purpose), yet the apply round "copies the file and runs `model
  decisions`" (SI Impl) — who writes is the round, which is a session. `capability-writer` writes only under
  `<drafts>/round-<n>/` (SI Impl), blind to code (`spec-writers-blind-to-code`).
- **features/**: `formulating-features` commits only feature files and test files `features rebind` changed (f#r6);
  "no session writes feature files itself" (F Purpose) but the round splices and commits (F Impl). Untouched
  scenarios byte for byte (f#r7). No approval for scenarios (f#r2).
- **consistency**: `spec-checker` reads only `spec/` and `features/` (sc#r3); findings mode changes one findings
  file only (sc#r4); never during integration or formulation (sc#r11).
- **migration**: nothing beyond the mechanical commit until the gate is answered (sm#r26); no step-definition body
  changes (sm#r7); mechanical commit changes no line text or scenario except r18 renaming (sm#r22); scenarios
  changed only by tags, deprecations, r18 (sm#r11).
- **model**: edits nothing but `spec/decisions/index.md` (DMC Purpose, dmc#r14, r15, r105); reads only the listed
  paths (dmc#r19); one bounded context.
- **requests** (DM §3): the asker writes lines and answers; the upstream writes outcomes, questions, resolution; each
  only through the tool. `turn` (G).
- **work**: claims disjoint (G claim, GR v_w3); part_of never crosses a seam (GR v18a); only a request's id crosses
  (dmc#r121).
- **the person**: sole approver at the gate (si#r3, r6); a delegation lets a session answer named questions (G);
  glossary questions are left to the person under a delegation (supervision, per CLAUDE.md row).
- Workflow capabilities are guarantees: checked by `measure`, not by scenarios (index Testing); this exempts them from
  v_s3, v15f, r124's scenario check.
