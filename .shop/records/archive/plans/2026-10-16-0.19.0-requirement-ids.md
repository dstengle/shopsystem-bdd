**Goal:** Release 0.19.0, ready to test: consuming repositories' capabilities carry stable requirement ids
(`[r<n>]`, design model v3), scenarios name them by `@r<n>`, the gate approves ids, a repository already on
capability files can be migrated to ids, and `scripts/model check` verifies all of it. Along the way, this

coverage check they already do by hand. Spec changes go through capability-proposals under `work/i3-requirement-ids/`,
built ahead of the gate on this branch, as i2 was: the person approves the ids before the release is merged.

**Tech Stack:** Python 3 stdlib scripts (`scripts/features`, `scripts/model`), clingo (only for `model check`),
`unittest`, Gherkin feature files, Claude Code plugin skills and agents (Markdown), headless `claude -p --plugin-dir`

## Review Focus

1. **A line inserted in the middle of a capability, or lines re-ordered.** Ids must not renumber: the new line takes the next free id even though it sits between r2 and r3. Pinned in Task 4 (brief text) and in the Task 9 `integrate` case (a line added between r2 and r3 must be r6).
2. **A removed line whose id comes back.** A line removed in one round and a line added later must not reuse the removed id, even when the capability's highest id is the removed one. Pinned by `model check` (an added retired id is v15c, already tested) and the Task 9 `integrate` case, whose fixture has `retired: [r5]` with r4 the highest line, so the next id is r6, not r5.
3. **A held scenario whose line was removed.** It still carries `@r5`, but r5 is now retired: `model check` must not report it as dangling or as a second scenario. Pinned in Task 2 (`@holding` scenarios are not acceptance-scenarios).
4. **A consuming repository with no clingo.** The skills must still work: `model check` exits 2 with its install line, and the round does the coverage check by hand and says `model check` did not run. Pinned in Task 5 and Task 9 (one fixture run without clingo).
5. **Migration to ids on a feature file with a Scenario Outline, feature-level tags, an `@holding` scenario and slice tags.** The `@r<n>` tag goes on the scenario's own tag line, never the feature's; held scenarios keep the tag of the line they were held for, or none; slice tags stay. Pinned in Task 2 (`features tag` with `r<n>` on an outline and a tagged feature) and the Task 9 migration fixture.

```markdown
# 0031. A held scenario formulates no requirement

## Decision

When a line is changed or removed and its old scenario is held (decision/held-scenarios), the held scenario keeps its `@r<n>` tag. `@holding` says it formulates no line, so `scripts/model` does not read it as an acceptance-scenario: it neither covers the requirement nor counts as a second scenario of it, and a held scenario whose id was retired is not a dangling reference.

## Context

i3 left open what holding does when a held scenario and its replacement name the same id. A changed line keeps its id, so both carry it; a removed line's id is retired, so the held scenario names an id no line has.

## Alternatives

Strip the tag on hold (the trace of which line it was is lost, and `features holding` cannot show it); a separate tag such as `@was-r<n>` (a second spelling of one id).

## Consequences

`features hold` changes nothing about tags but adding `@holding`, as today.
```

```python
SLICE = re.compile(r"slice-\d+(\.\d+)?$")
```

```python
def cmd_tag(args, files):
    if SLICE.match(args.slice):
        family = re.compile(r"@slice-")
    elif REQ_TAG.match(args.slice):
        family = re.compile(r"@r\d+$")
    else:
        sys.exit(usage_error("tag must look like slice-<n>, slice-<n>.<m> or r<n>"))
    path, f, sc = locate(files, args.title)
    lines = _retag(f, sc, args.slice, family)
    write_checked({path: lines})
    return 0


def _retag(f, sc, new_tag, family):
    lines = list(f.lines)
    new = "@" + new_tag
    placed = False
    for i in sc.tag_lines:
        indent = lines[i][:len(lines[i]) - len(lines[i].lstrip())]
        words = []
        for word in lines[i].split():
            if family.match(word):
                if not placed:
                    words.append(new)
                    placed = True
            else:
                words.append(word)
        lines[i] = indent + " ".join(words) if words else None
    if not placed:
        if sc.tag_lines:
            last = sc.tag_lines[-1]
            lines[last] = lines[last].rstrip() + " " + new
        else:
            text = lines[sc.line]
            lines[sc.line] = text[:len(text) - len(text.lstrip())] + new + "\n" + text
    return [x for x in lines if x is not None]
```

```python
"""A scenario's step definition is the test whose docstring is its title
(decision/plugin-scenarios-run-as-unittest)."""

import re


def titles(feature_path):
    text = feature_path.read_text()
    return re.findall(r"^\s*Scenario(?: Outline)?:\s*(.+?)\s*$", text, re.M)


def missing(feature_path, *classes):
    docs = set()
    for cls in classes:
        for name in dir(cls):
            if name.startswith("test_"):
                docs.add((getattr(cls, name).__doc__ or "").strip())
    return [t for t in titles(feature_path) if t not in docs]
```
